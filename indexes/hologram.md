# D-010 — AI-OS Bridge: L1-каталог драйверов сейчас, один L2 PoC следующим шагом
- Контекст: Q-007 сравнил варианты реализации информационных драйверов/«трайберов» между AI-приложением, Windows, локальным Codex, сервером и репозиториями Sven4. Mavis предложил вариант B с эволюцией к E; Claude добавил MCP-поправку: не изобретать новый протокол для коннекторов, а использовать MCP там, где нужен настоящий инструментальный слой.
- Решение: стартовать не с полной платформы и не с набора хаотичных скриптов, а с поэтапной схемы **B -> E / L1 -> ранний L2**. L1 — каталог `drivers/` с markdown-манифестами, шаблоном, risk/sandbox/secret-policy и первыми черновиками драйверов. L2 — один безопасный read-only PoC-драйвер после согласования.
- Терминология: каноническое имя папки — `drivers/`. Слово «трайбер» (`Treiber`, `Informationstreiber`) допустимо как метафора в обсуждениях, но не вводится как отдельная конкурирующая папка `trailers/`.
- Последствия: `drivers/` становится отдельным реестром возможностей проекта. Запуск непроверенного кода Sven4 не входит в первый этап: сначала только inventory/read-only, запуск позже и только после песочницы. Генерация/индексация драйверов выделяется отдельной задачей; полная серверная платформа L3/L4 не строится заранее.
