# Совместная работа над проектом

Эта папка - рабочее пространство для проектной работы нескольких участников и нескольких AI-ассистентов. Здесь можно вести полилог: вопросы, ответы, идеи, документацию, задачи, решения и код.

Основной формат: Markdown (`.md`). Он удобен для людей, Git и ИИ: легко читать, сравнивать изменения, ссылаться на файлы и хранить историю.

## Быстрый старт

1. Откройте `STATUS.md`, чтобы понять текущее состояние проекта.
2. Посмотрите `TASKS.md`, если нужно выбрать задачу. Это генерируемый индекс (только чтение); сами задачи живут в файлах-шардах `tasks/T-XXX.md`, статус меняется в шарде.
3. Новую задачу или открытый вопрос создайте файлом-шардом через `python tools/next_id.py task|question --agent <имя>`; `TASKS.md`/`QUESTIONS.md` вручную не редактировать.
4. Принятое решение зафиксируйте шардом через `python tools/next_id.py decision --agent <имя>`; индексы `TASKS.md`/`QUESTIONS.md`/`DECISIONS.md` пересобирает `python tools/generate.py`.
5. Для небольшой темы создайте отдельный файл в `topics/` по шаблону `templates/topic.md`.
6. Для большой темы с множеством людей или AI-агентов создайте папку темы по шаблону `templates/topic-folder-README.md`.

## Правила полилога

1. Подписывайте каждое сообщение: `### 2026-06-19 14:30 - Имя`. По умолчанию время указывается в локальном часовом поясе `Europe/Berlin`; если используете другой пояс, подпишите его явно.
2. Новые записи добавляйте ниже существующих, не переписывая чужой текст.
3. Небольшая тема живет в одном файле `topics/*.md`; большая тема живет в папке `topics/<topic>/`.
4. Если нужен ответ ИИ, обращайтесь по имени агента: `@Claude` или `@Codex` (список — в `AGENTS.md`).
5. Если обсуждение привело к задаче, создайте шард `tasks/T-XXX.md` через `python tools/next_id.py task --agent <имя>`; строку в `TASKS.md` добавит `python tools/generate.py`.
6. Если обсуждение привело к решению, создайте шард `decisions/D-XXX.md` через `python tools/next_id.py decision --agent <имя>` (статус `proposed`, ратифицирует человек); индекс `DECISIONS.md` генерируется, вручную его не править.
7. Если появился нерешенный вопрос, создайте шард `questions/Q-XXX.md` через `python tools/next_id.py question --agent <имя>`; индекс `QUESTIONS.md` генерируется, вручную его не править.
8. Если меняете служебные или общие файлы, оставьте короткое обоснование в профильной теме или в `dialog.md`: что изменили, зачем, и какое у вас мнение.

## Имена файлов

Принято (D-005): новые технические и тематические файлы именуются в ASCII (`api-design.md`, `project-rules.md`, `data-model.md`), а русский заголовок пишется внутри файла.

Существующие русские файлы остаются рабочими: `dialog.md`, `board.md`, `participants.md`, `topics/`. По D-007 они мигрируют к ASCII постепенно, при следующей существенной правке конкретного файла.

## Большая группа и много AI-агентов

Если одну тему обсуждает много людей или несколько автоматических агентов, не используйте один общий длинный файл. Создавайте папку темы:

```text
topics/topic-name/
  README.md
  summary.md
  questions.md
  decisions.md
  messages/
```

Внутри `messages/` правило такое: **одно сообщение = один файл**. Это снижает конфликты и позволяет агентам работать параллельно.

Для автоматических агентов используйте `AGENTS.md` и `queues/`. Подробные правила описаны в `PROTOCOL.md`.

Захват задачи агент делает атомарно через `python tools/pipeline.py next <agent>` (или `claim <agent> <T-id>`) — это нужно, чтобы несколько агентов не выполняли одну и ту же задачу вслепую. Каталог `queues/claimed/` — legacy-история: отметки в нём руками не создавать.

## Обоснование правок

Рабочая папка должна быть похожа на асинхронный форум: участники пишут не только результат правки, но и причину. Для служебных файлов (`STATUS.md`, `TASKS.md`, `QUESTIONS.md`, `DECISIONS.md`, `PROTOCOL.md`, `AGENTS.md`, `board.md`, `dialog.md`, `templates/`, `queues/README.md` и правила очередей) правило такое:

```md
### YYYY-MM-DD HH:MM - Имя

Изменил: `file.md`.
Почему: ...
Мое мнение: ...
Что нужно от других: ...
```

Основная тема для таких объяснений сейчас: `topics/organization.md`.

## Как просить ИИ прочитать изменения

В файле (укажите нужного агента, например `@Claude` или `@Codex`):

```md
@Claude
Прочитай эту тему, ответь на открытые вопросы и предложи следующий шаг.
```

В чате:

```text
Прочитай рабочую папку и отреагируй на новые изменения.
```
