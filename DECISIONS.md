# Решения

Журнал принятых решений. Он нужен, чтобы команда не возвращалась к одному и тому же спору.

## Формат записи

```md
## D-001 - Краткое название решения

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan, Codex
- Контекст: почему вообще принимали решение
- Решение: что именно выбрали
- Последствия: что теперь нужно делать иначе
```

## Принятые решения

## D-001 - Markdown как основной формат

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan, Codex
- Контекст: нужна папка для коллективной проектной работы, понятная людям и ИИ.
- Решение: использовать Markdown для обсуждений, статусов, вопросов, документации и решений.
- Последствия: новые обсуждения создаются как `.md`-файлы; служебные данные можно добавлять позже в JSON/YAML только при необходимости.

## D-002 - Для больших тем использовать отдельный файл на сообщение

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan, Claude, Codex
- Контекст: в одной теме могут одновременно писать много людей, AI-агентов, подагентов и скриптов.
- Решение: для больших тем использовать папку темы с `messages/`, где одно сообщение хранится в отдельном Markdown-файле.
- Последствия: снижается риск конфликтов записи; итог темы нужно собирать отдельно в `summary.md`, `decisions.md` и общих файлах проекта.

## D-003 - Правки служебных файлов сопровождаются обоснованием

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan, Claude, Codex
- Контекст: чтобы правки не «гоняли» туда-сюда, людям и агентам нужно видеть причину изменения и иметь возможность ответить асинхронно.
- Решение: при изменении служебных/общих файлов автор оставляет короткое обоснование в профильной теме (`темы/...`) или в `Диалог.md`.
- Последствия: правки становятся обсуждаемыми (форум-стайл); обсуждение конвенции — в `темы/организация-папки.md`.

## D-004 - Метод принятия решений по открытым вопросам

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan, Claude, Codex
- Контекст: открытые вопросы нужно решать обоснованно и сообща, а не волевым выбором.
- Решение: каждый открытый вопрос оформляется как «Варианты → плюсы/минусы → рекомендация → голоса → итог» (шаблон `templates/decision-options.md`) перед переводом в `answered`.
- Последствия: решения становятся прозрачными и воспроизводимыми; итог переносится в `DECISIONS.md`.

## D-005 - Имена новых файлов в ASCII

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan (голос), Claude, Codex
- Контекст: кириллические пути дают трения с git (экранирование), ссылками (percent-encoding), Unicode-нормализацией и инструментами/CI.
- Решение: новые технические и тематические файлы именуются в ASCII (`api-design.md`), кириллица идёт в заголовок внутри файла. На момент D-005 существующие русские имена (`Доска.md`, `Диалог.md`, `Участники.md`, `темы/`) оставались как есть.
- Последствия: новые файлы создаются с латинскими именами; миграция существующих русских имён позднее уточнена отдельным решением D-007.

## D-006 - Сборщик итогов в больших темах: гибрид

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan (голос), Claude, Codex
- Контекст: в больших темах нужно сводить `messages/` и фиксировать решения без узкого места и без бесконтрольной автоматизации.
- Решение: AI-агент или скрипт готовит `summary.md` и черновики решений, а человек (или явно назначенный сборщик) переводит решения в `accepted`. Совпадает с `PROTOCOL.md` §8.
- Последствия: на каждую большую тему назначается сборщик; финальное утверждение решений — за человеком.

## D-007 - Постепенная миграция русских имён к ASCII

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan (голос), Claude, Codex
- Контекст: D-005 задал ASCII для новых файлов; оставался вопрос по существующим русским именам (Q-004).
- Решение: постепенная (ленивая) миграция — файл с русским именем переименовывается в ASCII при следующем существенном изменении, с обновлением всех ссылок на него; массового разового переименования не делаем. Новые файлы сразу в ASCII (D-005).
- Последствия: смешанный стиль временно сохраняется и сходит на нет; при каждом переименовании обязательна правка ссылок (README/STATUS/Доска/QUESTIONS/TASKS/темы).

## D-008 - Границы D-003: что считать значимой правкой

- Дата: 2026-06-19
- Статус: accepted
- Кто участвовал: Stefan (голос), Claude, Codex
- Контекст: D-003 требует обоснование для «значимых» правок служебных файлов; нужно было определить границу (Q-005).
- Решение: обоснование обязательно для значимых изменений — структура, правила, решения, задачи, статусы, протокол, права агентов, очереди, шаблоны, активные темы. Мелочи (опечатки, форматирование, типографика, мелкие уточнения формулировок) обоснования не требуют. Совпадает с `PROTOCOL.md` §7.
- Последствия: журналы не засоряются обоснованиями к мелочам; важные изменения остаются прослеживаемыми.
