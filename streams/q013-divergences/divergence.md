# Синтез разногласий: Onboarding & Manual Roadmap (Q-013)

Этот документ сформирован в результате проведения процедуры "Котла" (D-018) для вопроса Q-013.

## Консенсус (То, с чем все согласны)
- Обучающие материалы и операционные руководства необходимы.
- Onboarding-документ является точкой входа для новых агентов, Manual — для оперативной работы.
- Следует избегать создания гигантских монолитных документов, так как они ухудшают контекст и скорость понимания.

## Разногласие 1: Слияние документов Onboarding и Manual
**Суть:** Должны ли `agent-onboarding.md` и `top-agent-operating-manual.md` быть объединены в один документ?
- **Позиция А (Отклонена):** Слить в один документ для обеспечения единой "точки входа".
- **Позиция Б (Принята, Codex):** Сохранить раздельные роли. Onboarding — для первого знакомства, Manual — для операционной работы.
- **Доказательная база:** Огромные файлы усложняют загрузку контекста. Разные аудитории (новый агент vs работающий агент) требуют разной подачи информации.
- **Решение (Stefan, Human Gate):** Принята Позиция Б. Вводится drift-check guard, чтобы документы не противоречили друг другу.

## Разногласие 2: Отношение к дублям (Duplicate tasks)
**Суть:** Как поступать, если два агента создали дублирующие или параллельные задачи по одной теме?
- **Позиция А (Отклонена):** Жестко закрывать второй таск как duplicate. (Плюс: чистая очередь. Минус: потеря альтернативного мышления).
- **Позиция Б (Принята, Вариант C):** Разделить уровни. Один canonical task остается на исполнение, а альтернативы переносятся в design comparison / topic fork / variant note.
- **Доказательная база:** Позволяет сохранить дизайн-пространство (разные варианты) при чистой очереди выполнения.
- **Решение (Stefan, Human Gate):** Принята Позиция Б.

## Разногласие 3: Worktree Isolation
**Суть:** Делать ли git worktree изоляцию обязательной при наличии 2+ агентов?
- **Позиция А (Отклонена):** Обязательный режим для всего.
- **Позиция Б (Принята):** Режим worktree является *рекомендованным*, а обязательным становится только по явным триггерам (same-file коллизия, STALE-состояние индекса).
- **Доказательная база:** Избыточное ветвление замедляет работу для мелких правок.
- **Решение (Stefan, Human Gate):** Принята Позиция Б. (D-021/D-022 уже отражают эту политику).
