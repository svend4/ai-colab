# Variant-start order policy - independent Codex variant

## 00. Причина независимого варианта

Эта запись создана до чтения `tools/top.py` и до поиска по репозиторию по теме `variant-start`. Причина: пользователь указал на методологическую ошибку, когда агент сначала проверяет существующие механизмы, а потом уже формулирует собственный вариант. Такой порядок полезен для избежания дублей, но вреден для политики независимых вариантов: агент уже получает якорь от чужого решения и может не раскрыть собственный потенциал.

## 01. Условия применимости

Правило применимо к задачам, где явно требуется:

- выработать собственный вариант агента;
- сравнить несколько вариантов людей и агентов;
- не считать совпадение названия дублем содержания;
- сначала раскрыть разные подходы, затем синтезировать consensus и divergence.

Правило не обязательно для простых багфиксов, где пользователь просит исправить конкретную ошибку в конкретном файле.

## 02. Независимый ответ агента

Мой вариант: команда верхнего слоя для старта варианта должна работать в два этапа.

Этап A - независимый старт:

1. Создать отдельный stream агента.
2. Внести в stream минимальный контракт: тема, агент, задача, статус, причина, ожидаемый формат.
3. Явно сказать агенту: сначала заполни независимый ответ в этом stream.
4. Не запускать repo-search автоматически до первичной записи содержательного ответа.

Этап B - сверка:

1. После записи независимого ответа разрешить repo-search.
2. Сравнить stream с существующими документами, задачами, решениями и другими stream.
3. Повторяющиеся смысловые пункты вынести в consensus.
4. Различия вынести в divergence, а не удалять как “дубли”.

Минимальная техническая форма: `variant-start` по умолчанию должен создавать stream и печатать следующую команду для поиска, но не выполнять поиск сразу. Если нужен старый режим, он должен быть явным, например `--search-now`.

## 03. Потенциал, который нужно раскрыть до синтеза

Потенциал независимого варианта состоит в том, что агент может предложить иной порядок работы:

- сначала вопросник и псевдокод процесса;
- затем stream;
- затем поиск;
- затем сравнение;
- затем синтез;
- затем promotion в задачу, тест или изменение кода.

Если поиск запускается раньше, эта цепочка сжимается до “найти похожее и не дублировать”. Для информационной разработки это слишком узко.

## 04. Сравнение с известными вариантами

Сравнение выполнено после первичной независимой записи.

Consensus:

- `D-017`, `D-028`, старый `variant-start-top` и новый sub-agent stream сходятся в одном: нужен короткий верхний вход для независимого варианта.
- Совпадение темы или названия не является шумовым дублем до synthesis.
- Stream должен быть отдельным артефактом агента, а consensus/divergence должны выделяться после сравнения.
- `variant-start` не должен принимать governance-решения и не должен писать mainline-документы.

Divergence / superseded:

- Старый T-254-вариант предлагал порядок `repo-search -> stream create`. Для strict independent-first задач этот порядок теперь считается устаревшим: он создаёт раннее якорение агента.
- Новый T-258-порядок: `stream create -> independent draft -> repo-search/compare -> ready-for-synthesis`.
- Hegel указал два технических риска: конфликт `--no-search`/`--search-now` и неявный non-json статус executed search. Оба риска учтены в `tools/top.py` и `tools/test_top.py`.
- Galileo добавил orchestration-акцент: для пачки sub-agents нужен фазовый барьер, где все сначала сохраняют independent streams, а compare/synthesis запускается после barrier.

Обновлённые adoption targets:

- `tools/top.py`: search deferred by default; `--search-now` explicit; conflicting search flags mutually exclusive.
- `tools/test_top.py`: parser/conflict/deferred smoke покрыты.
- `docs/top-layer-command-groups.md`, `docs/independent-variant-stream-policy.md`, `tools/README.md`, `tools/capabilities.py`: live guidance обновлён, historical T-254 не переписан.

## 07. Synthesis contract

В mainline можно переносить только пункты, которые не уничтожают независимые варианты:

- stream создаётся отдельно для каждого агента;
- совпадение названия не считается дублем;
- repo-search допустим после независимой записи;
- разногласия фиксируются как divergence.

Спорные пункты нужно оставить открытыми:

- дефолтный режим `variant-start`;
- нужен ли новый статус `independent-draft`;
- нужен ли отдельный compare-step.

Моя предыдущая ошибка была процедурной: я применил инженерный рефлекс “сначала проверить, что уже есть”, хотя задача требовала “сначала раскрыть собственный вариант”. Этот stream нужен как техническая защита от повторения этой ошибки.
