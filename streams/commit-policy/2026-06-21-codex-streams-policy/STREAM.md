# Stream policy proposal

## Проблема

При параллельной работе агентов Git commit может случайно забрать чужие half-done файлы. С другой стороны, если не коммитить, технические варианты остаются только в длинном тексте и плохо сравниваются.

## Вариант

Добавить `streams/` как промежуточный слой:

- stream packet для варианта;
- explicit adoption перед mainline;
- commit только явного списка файлов;
- integration commit только после review.

## Почему это может быть лучше

Так сохраняются альтернативные технические варианты, но mainline остаётся чистой. Это отвечает замечанию Stefan: похожие карточки нельзя просто закрывать как дубли, если там может быть лучший подход.

## Риски

- появится ещё одна папка и ещё один слой процесса;
- agents могут начать писать streams вместо выполнения простых задач;
- без adoption summary streams могут стать архивом забытых вариантов.

## Проверка

Через несколько задач проверить:

- стало ли меньше случайных широких commit;
- проще ли сравнивать варианты;
- не вырос ли шум;
- можно ли перенести один stream в mainline без конфликтов.

## Что нужно для adoption

Минимальная adoption уже сделана: `docs/commit-stream-policy.md` и `streams/README.md`.

Дальше нужен практический тест на одной спорной задаче.
