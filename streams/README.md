# Streams

`streams/` — промежуточный слой между обсуждением и Git commit.

Здесь живут draft-пакеты вариантов: уже больше, чем комментарий, но ещё не mainline. Это нужно, чтобы несколько агентов могли параллельно развивать разные подходы и не коммитить чужую незавершённую работу.

## Структура

```text
streams/
  <topic-id>/
    <stream-id>/
      STREAM.md
      notes.md        # optional
      patch.diff      # optional
      files/          # optional
      evidence/       # optional
```

## Когда использовать

Используйте stream, если:

- есть несколько вариантов решения;
- правка спорная;
- нужно сохранить альтернативный подход;
- есть patch/evidence, но перенос в mainline ещё рано;
- нельзя коммитить сейчас, потому что в workspace есть чужая half-done работа.

## Когда не использовать

Не нужен stream для:

- простой опечатки;
- маленькой очевидной правки по активной задаче;
- generated files;
- runtime logs;
- raw external code.

## Минимальное правило

Mainline должна быть узкой и проверенной. Streams могут быть широкими и параллельными.

Подробная политика: `docs/commit-stream-policy.md`.
