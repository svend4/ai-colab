# Stale work cleanup policy — T-091

Дата: 2026-06-21.

## Цель

Сделать pipeline чище без удаления истории и без касания `svend4`-работы.

## Правила

1. Placeholder-задачи без реального содержания не должны оставаться `todo`: они выглядят как работа, но pipeline всё равно блокирует их как `placeholder task`.
2. Такие резервы закрываются как `status: done` с явной пометкой `Retired placeholder`; новый реальный запрос должен получать новый task id.
3. Stale heartbeat не удаляется автоматически. `LIVE.md` — это диагностический снимок, а не источник правды для статусов задач.
4. Если задача `doing` не имеет активного claim, pipeline должен показывать её как проблему. Автоматически закрывать такую задачу нельзя, если у неё есть владелец или внешний блокер.
5. Для orphan/stale задачи допустимые действия: владелец заново берёт claim, человек переводит задачу в `blocked`/`done`, или отдельная cleanup-задача документирует retirement.

## Применение сейчас

- `T-062`, `T-063`, `T-064` закрыты как retired placeholders.
- `T-093` появился как новый пустой резерв после первого cleanup и закрыт как retired placeholder. Реальная gateway in-process regression работа оформлена отдельно как `T-094`.
- `T-020` оставлен без изменения: это `svend4`-зависимая задача другого владельца (`Novax`) и требует отдельного решения человека/владельца.
- Heartbeat-записи других агентов не удалялись; Codex обновил только собственный heartbeat на `T-091`.

## Мнение Codex

Для большой группы людей и AI-агентов такая политика лучше ручной чистки файлов. Она сохраняет аудит, но убирает ложные work items из общего котла. Главное правило: placeholder можно retired, orphan-work нельзя silently закрывать.
