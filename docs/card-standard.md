# Стандарт «карточка-визитка» (card)

> Обобщение `decision-menu` до **универсальной единицы коммуникации**. Внизу пирамиды —
> **«поваренная книга»**: все детали, все рецепты (агентский детейл, спеки, диффы, код). Вверху —
> **меню**: краткое содержание, суть. Середина — **метаданные содержания**: рецептов, блоков,
> стройматериалов, отзывов, предложений, жалоб, процесса. Эта середина встраивается **между
> программным кодом и агентом/нейросетью** и между **людьми**. Её форма — **карточка-визитка**:
> микро-кластер, **микро-фрактал** подачи/обработки/коммуникации информации здесь-и-сейчас.

## 1. Карточка = фрактальная единица

Одна форма на всех уровнях (фрактал):

```
[ТИП] Название — суть            ← верхушка карточки (как строка каталога / визитка)
`риск·усилие·обратимость`        ← теги-метаданные
Что · Плюсы · Минусы ·           ← середина: метаданные (тип-специфичные)
🔹 Что значит · 🔹 К чему ведёт · 🔹 Ответственность   ← СЕМАНТИЧЕСКИЕ метаданные
[ вложенные карточки → ]         ← дети (фрактал: карточка из карточек = меню)
→ основание: detail_ref          ← ссылка в «поваренную книгу» (детали)
```

**Фрактал:** карточка может содержать карточки. **Меню = карточка типа `menu`, дети которой —
карточки вариантов.** Рецепт = карточка, дети — шаги. Так одна форма масштабируется от визитки
до полного меню.

## 2. Типы карточек (один контракт, разные поля)

| Тип | Для чего | Ключевые поля середины |
|---|---|---|
| `menu` | выбор из вариантов | дети (карточки) |
| `decision` | решение/вариант | what · pros · cons · 🔹means · 🔹leads_to · 🔹responsibility |
| `recipe` | рецепт/методичка | what · when · steps · pitfalls |
| `block` | блок (blocks.py) | what · cluster · verdict |
| `review` | отзыв | what · liked · issues |
| `complaint` | жалоба | what · impact · wanted |
| `proposal` | предложение | what · 🔹value · cost · 🔹means · 🔹leads_to |
| `process` | состояние процесса | what · state · next · blockers |

🔹 = **семантические** поля (не «как», а «что это значит / к чему ведёт / ответственность») — ядро
стандарта. «Букет»: карточка несёт **сочетание** (риск × смысл × последствие × ответственность),
а не один лепесток.

## 3. Контракт (схема)

```json
{
  "type": "decision",
  "key": "A",                 // для каталога-выбора
  "title": "...", "gist": "одна фраза",
  "tags": {"risk":"low|med|high","effort":"S|M|L","reversibility":"easy|hard|irreversible","scope":"..."},
  "recommended": false,
  "fields": { "what":"...", "pros":[...], "means":"...", "leads_to":"...", "responsibility":"..." },
  "children": [ {карточка}, ... ],   // фрактал
  "detail_ref": "ссылка в основание"
}
```

## 4. Инструмент

`tools/card.py` — фрактальный рендерер (обобщает `tools/decision_menu.py`):

```
python tools/card.py card.json                       # карточка/дерево
python tools/card.py proposals.json --from-proposals  # workflow-выход → меню-карточка
python tools/card.py - --toc                          # из stdin, только каталог-верхушки
```

`from_proposals` переводит структурный выход workflow'ов (агенты отдают proposals) в меню-карточку
→ замыкается **«агенты предлагают детально (основание) → человек выбирает по карточкам (середина)»**.
Это апекс-слой подачи: между кодом, ИИ-агентами и людьми.

## 5. Где применять

- Агент/оркестратор → человек: любое предложение действия (вместо «2 слов»).
- Агент ↔ агент: компактный обмен (визитка вместо лога).
- Человек ↔ человек: общий язык обсуждения (меню, а не агентский детейл).
- Отзывы/жалобы/предложения по блокам/рецептам/стройматериалам — как карточки `review/complaint/proposal`.

D-006 (человеко-гейт): high-risk решения подаются человеку **только** карточкой.
