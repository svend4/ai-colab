# Стандарт «меню решений» (decision-menu)

> Когда агенты предлагают дальнейшее действие, человеку нельзя давать ни **2 слова** (непонятны
> суть, последствия, ответственность), ни **весь агентский детейл** (основание пирамиды — слишком
> много). Нужен **средний слой**: развёрнутое содержание + метаданные, из которого человек (и люди
> между собой) **выбирают**. Как **меню в ресторане** с описанием и плюсами/минусами; как **оглавление
> книги** или **каталог news-групп + метаданные** — с верхушки понятна суть, вниз — детали.

## 1. Три слоя пирамиды подачи

```
        ВЕРХУШКА (catalog / оглавление)   ← одна строка на вариант: суть + теги. Понять «о чём речь».
       ────────────────────────────────
      СЕРЕДИНА (МЕНЮ РЕШЕНИЙ — этот стандарт)
     карточка варианта: что · плюсы · минусы · ЧТО ЗНАЧИТ · К ЧЕМУ ВЕДЁТ · ОТВЕТСТВЕННОСТЬ
    ──────────────────────────────────────────
   ОСНОВАНИЕ (detail) — полный агентский разбор, спеки, диффы, обсуждение между агентами.
```

- **Верхушка** — каталог: на каждый вариант одна строка `[ключ] Название — суть (риск·усилие·обратимость)`.
- **Середина** — это **меню решений**: разворачивает каждый вариант в карточку с метаданными. Цель —
  чтобы человек понял **смысл и последствия и ответственность**, не ныряя в основание.
- **Основание** — полный детейл (агентский), куда ведёт ссылка `detail_ref`. Туда ныряют, если карточки мало.

## 2. Метаданные: технические И СЕМАНТИЧЕСКИЕ

Меню несёт два рода метаданных. Семантические — главная новизна (не «как», а «что это значит»):

| Поле | Род | Что несёт |
|---|---|---|
| `tags.risk` | техн. | low / med / high — масштаб риска |
| `tags.effort` | техн. | S / M / L — усилие |
| `tags.reversibility` | техн. | easy / hard / irreversible — откатываемость |
| `tags.scope` | техн. | что затрагивает (файлы/подсистемы/governance) |
| **`means`** | **семант.** | **ЧТО ЭТО ЗНАЧИТ** — концептуально, для направления проекта |
| **`leads_to`** | **семант.** | **К ЧЕМУ ВЕДЁТ** — последствия вниз по течению (и хорошие, и плохие) |
| **`responsibility`** | **семант.** | **ОТВЕТСТВЕННОСТЬ** — на что подписываешься, что может пойти не так, кто отвечает |

> «Букет»: вариант — не одна метрика, а **сочетание** (риск × смысл × последствие × ответственность).
> Стандарт требует представить весь букет, а не один «лепесток».

## 3. Схема варианта (контракт)

```json
{
  "key": "A",                       // выбираемый ключ (буква/цифра)
  "title": "Краткое название",
  "gist": "одна фраза — для каталога-верхушки",
  "tags": {"risk":"low|med|high","effort":"S|M|L","reversibility":"easy|hard|irreversible","scope":"..."},
  "what": "1-2 предложения — что это конкретно",
  "pros": ["плюс", "плюс"],
  "cons": ["минус/риск", "..."],
  "means": "семантика: что выбор ОЗНАЧАЕТ",
  "leads_to": "семантика: к чему ВЕДЁТ (вниз по течению)",
  "responsibility": "семантика: ставка/ответственность/что может пойти не так",
  "detail_ref": "ссылка в основание (спека/отчёт/дифф)",
  "recommended": false
}
```

Обёртка меню: `{title, context (1 абзац — ситуация и почему выбор сейчас), options:[...], recommendation, how_to_choose}`.

## 4. Когда применять

- Агент/оркестратор предлагает **дальнейшее действие** человеку (вместо «2 слов»).
- Решение несёт **ответственность/необратимость** (governance, ratify, разрушительное, дорогое).
- Нужно **обсуждение между людьми** — меню = общий язык, а не агентский лог.
- НЕ применять для тривиального/обратимого (там «2 слова» достаточно — не перегружать).

Связь с D-006 (человеко-гейт high-risk): high-risk решения подаются человеку **только** меню-формой.

## 5. Рендер и инструмент

`tools/decision_menu.py` принимает JSON-меню (файл/stdin) и печатает:
- **каталог** (верхушка): таблица `ключ | вариант | суть | риск·усилие·обр.`;
- **карточки** (середина): по варианту все поля, семантические — выделены;
- **рекомендацию** и **как выбрать**.

```
python tools/decision_menu.py menu.json            # полное меню
python tools/decision_menu.py menu.json --toc       # только каталог-верхушка
python tools/decision_menu.py menu.json --md         # markdown (для подачи человеку)
```

Источник `options` — структурный выход workflow'ов (агенты уже отдают proposals); рендерер
переводит агентский детейл в человеко-меню. Так замыкается «агенты предлагают → человек выбирает».

## 6. Пример (сокращённо)

```
Меню: что строить дальше
| ключ | вариант | суть | теги |
| A | Dedup-волна _ioutil | заменить boilerplate в ~40 тулах | med·L·easy |
| B | Закрыть T-192 | doc-cleanup queue→agent_queue | low·S·easy |

## A — Dedup-волна _ioutil
Что: заменить 5-строчный UTF8-boilerplate в ~40 тулах на import+вызов.
Плюсы: −200 строк дубля; единая точка IO-настройки.
Минусы: трогает ~40 файлов разом; часть Codex-hot → риск конфликтов.
Что значит: переход «россыпь → один источник» завершается на IO-слое.
К чему ведёт: проще менять IO-политику; но крупный diff → дольше review.
Ответственность: массовая правка; если _ioutil с багом — падают все 40. Обратимо (git revert).
→ detail: tools/_ioutil.py
```
