# Облегчение pre-commit хука

## 0. Проблема (наблюдённая 2026-07-06/07)

Под многоагентной нагрузкой (3+ агента коммитят одновременно) коммиты стали занимать
**5–10 минут** и в пике **насыщают машину** (git-команды и `Get-Process` таймаутят за 60с).
Замеры причин на коммит:

| Шаг pre-commit | Время | Проблема |
|---|---|---|
| `validate.py` (полный, 290 задач) | **~2 мин** | главный тормоз; гоняется на КАЖДОМ коммите |
| `generate.py --check` (всё дерево) | ~15–30с | блокирует по ЧУЖОМУ entangled-нав → гонка регенерации |
| geometric repack (git) | ~60с | Novax, T-292; митигируется `gc.autoDetach true` |
| нав-churn (регенерация + повтор) | ×N | другой агент коммитит → нав устаревает к концу моего хука (live-lock) |

Итог: коммит-контур — связывающее ограничение этапа. Прямой аргумент — сессия 2026-07-06/07,
где несколько попыток коммита подряд таймаутили.

## 1. Принцип решения (оборона в глубину — уже в commit-safety-standard)

**Локальный хук = быстрая обратная связь (секунды). CI = полный энфорсмент.**
`--no-verify` обходит только локальный хук, но не CI — поэтому тяжёлую полноту безопасно
перенести в CI, а локально оставить быстрые критичные проверки.

## 2. Что меняется

| Проверка | Было (боевой хук) | Станет (pre-commit.fast) |
|---|---|---|
| Валидация канона | `validate.py` полный (~2 мин), БЛОК | `validate_staged.py` — только staged файлы (секунды), БЛОК; полный → CI |
| Свежесть нав всего дерева | `generate.py --check`, БЛОК | **WARN** (не блок): чужой entangled-нав не тормозит твой коммит |
| Согласованность ТВОИХ staged | `staged_check.py` (C1-b), БЛОК | **без изменений**, БЛОК (ловит: твои canon-источники staged, а нав нет) |
| Тихий дрейф деривата | `gap_scan drift`, БЛОК | **без изменений**, БЛОК (быстро) |
| Массовое стирание | `bulk_guard --hook`, БЛОК | **без изменений**, БЛОК (D-026, безопасность) |
| orphans / dcard | WARN | **без изменений**, WARN |

**Ключ:** безопасность (`bulk_guard`) и согласованность твоих изменений (`staged_check`,
`validate_staged`) остаются БЛОКИРУЮЩИМИ и быстрыми. Тяжёлый полный `validate` и
всё-дерево `generate --check` уходят в CI / WARN.

## 3. Готовые артефакты (на диске, ждут применения)

- ✅ `tools/validate_staged.py` — быстрая валидация staged канон-файлов (front-matter, id==имя,
  статус, битые ссылки, дубли id среди staged). Fail-open при недоступном git.
- ✅ `tools/tests/test_validate_staged.py` — 5 кейсов (valid / id-mismatch / bad-status /
  dangling-ref / no-staged). **Прогнать при разгрузке машины.**
- ✅ `tools/githooks/pre-commit.fast` — черновик облегчённого хука (не активен).
- ⏳ CI: `.github/workflows/bulk-guard.yml` уже гоняет полный `validate.py`; ДОБАВИТЬ туда шаг
  `python tools/generate.py --check` (полнота нав в CI). Малая правка, см. §5.

## 4. Риск-анализ

| Риск | Митигация |
|---|---|
| Локально пропущен канон-инвариант, который ловил полный validate | Полный validate — в CI на push/PR; branch protection блокирует merge |
| generate --check стал WARN → устаревший нав в коммите | `staged_check` (БЛОК) ловит несогласованность ТВОИХ изменений; всё-дерево — в CI; аудит-H-2 закрыт staged_check'ом, не generate --check |
| validate_staged что-то не проверяет | Он и не должен — это быстрый фильтр; перекрёстные инварианты/счётчики/синтез = CI |
| bulk_guard ослаблен | НЕТ — остаётся блокирующим локально + дублируется в CI |

## 5. Swap-план (когда машина разгрузится, 3 шага)

1. **CI-полнота:** в `.github/workflows/bulk-guard.yml` добавить шаг
   `python tools/generate.py --check` (после validate).
2. **Прогнать тест:** `py -3 tools/tests/test_validate_staged.py` (ожидается TESTS OK) +
   `py -3 tools/validate_staged.py` на реальном staged.
3. **Активировать:** заменить `tools/githooks/pre-commit` содержимым `pre-commit.fast`
   ЧЕРЕЗ reconcile (старый → `pre-commit.full.bak` как снапшот, не удалять — D-026/reconcile),
   затем закоммитить через `tools/commit.py` (коммит теперь секундный).

## 6. Ожидаемый эффект

Коммит-хук: ~2 мин → **секунды**. Многоагентная работа перестаёт упираться в коммит-контур;
насыщение машины уходит. Полнота канона сохранена (в CI). Безопасность D-026 сохранена
(локально + CI). Это снимает связывающее ограничение этапа Beta-0.

## 7. Вопрос к котлу (D-035)

- **Вопрос:** применить облегчённый pre-commit (полный validate → CI)?
- **Варианты:** (a) применить по swap-плану §5; (b) применить, но полный validate оставить
  локально как WARN (двойная страховка, чуть медленнее); (c) не менять (принять медленные коммиты).
- **Рекомендация:** (a) — прямой фикс наблюдённого блокера; полнота и безопасность сохранены в CI.
- **Impact:** снимает главное ограничение производительности многоагентной работы.
