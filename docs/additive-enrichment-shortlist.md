# Список безопасных additive-задач для обогащения проекта (Additive Enrichment Shortlist)

**Примечание (D-037)**: Согласно правилу D-037, новые скрипты `tools/*.py` создаются **только при явной потребности человека или из friction-боли**. Для каждой задачи ниже указано, требует ли она создания нового файла в `tools/` или предполагает расширение существующих механизмов. В случае пересечения с существующим функционалом предпочтительнее расширять имеющиеся инструменты.

Данный список содержит безопасные задачи для постепенного улучшения проекта (additive-методология). Задачи сфокусированы на добавлении новой ценности (защита, индексы, методы, отчёты, прототипы) без удаления или изменения истории.

## Защита (Protection)

### 1. Валидатор консистентности JSON-структур
- **Что сделать**: Скрипт, проверяющий синтаксическую корректность всех `.json` файлов в проекте.
- **Какие файлы затронет**: `tools/validate.py` или `tools/validate_staged.py`
- **Новый tools/*.py**: Нет. Пересекается с `validate.py` и `validate_staged.py`. Предлагается расширить один из существующих валидаторов.
- **Риск**: Низкий (read-only проверка).
- **Как проверить**: Запустить расширенный скрипт и убедиться, что он корректно находит ошибки в намеренно сломанном тестовом JSON-файле.

### 2. Скрипт проверки битых ссылок (Markdown Linter)
- **Что сделать**: Утилита для обхода всех `.md` файлов и проверки того, что внутренние ссылки ведут на существующие документы.
- **Какие файлы затронет**: `tools/drift_check.py` или `tools/heading_check.py`
- **Новый tools/*.py**: Нет. Пересекается с `drift_check.py` и `heading_check.py`. Предлагается добавить функционал линтера ссылок в один из них.
- **Риск**: Низкий.
- **Как проверить**: Добавить битую ссылку в тестовый файл и убедиться, что скрипт её помечает.

### 3. Детектор конфликтов путей и имён файлов
- **Что сделать**: Проверка соблюдения ASCII-имён (по D-007) и отсутствия конфликтующих имен (например, в разных регистрах).
- **Какие файлы затронет**: `tools/validate.py` (или новый скрипт `tools/detect_naming_conflicts.py` по решению человека).
- **Новый tools/*.py**: Возможен (только по решению человека), но лучше добавить в `tools/validate.py`.
- **Риск**: Низкий.
- **Как проверить**: Добавить файл с русским именем или пробелами в тестовую папку и запустить утилиту.

## Индексы (Indexes)

### 4. Восстановление исходных файлов задач (T-294 – T-296)
- **Что сделать**: Создать физические файлы разметки для задач T-294, T-295 и T-296, чтобы генератор индексов мог их корректно обрабатывать.
- **Какие файлы затронет**: `tasks/T-294.md`, `tasks/T-295.md`, `tasks/T-296.md`
- **Новый tools/*.py**: Нет.
- **Риск**: Низкий (простое добавление недостающих файлов).
- **Как проверить**: Запустить `tools/generate.py` и убедиться, что индекс задач обновляется корректно.

### 5. Генерация агрегированного индекса участников
- **Что сделать**: Автоматический сбор статистики и данных по участникам в единый индекс.
- **Какие файлы затронет**: `tools/generate.py`, `indexes/participants_index.md`
- **Новый tools/*.py**: Нет. Пересекается с `generate.py`. Предлагается расширить логику генерации в `tools/generate.py`.
- **Риск**: Низкий.
- **Как проверить**: Запустить генератор и проверить визуальную корректность созданного `.md` файла.

### 6. Индексатор решений (DECISIONS) по тегам
- **Что сделать**: Парсер файла решений, извлекающий теги/категории и формирующий сводный навигационный файл.
- **Какие файлы затронет**: `tools/canon_index.py` или `tools/decisions_usage_scan.py`, `indexes/decisions_by_tag.md`
- **Новый tools/*.py**: Нет. Пересекается с `canon_index.py` и `decisions_usage_scan.py`. Предлагается доработать один из существующих сканеров.
- **Риск**: Низкий.
- **Как проверить**: Запустить расширенный скрипт и сверить список сгенерированных тегов с исходными файлами решений.

## Методы (Methods)

### 7. Утилита экспорта индексов в CSV
- **Что сделать**: Метод конвертации данных о задачах из `.json` или `.md` в формат CSV для внешнего анализа.
- **Какие файлы затронет**: `tools/export_csv.py` (или существующий экспортёр).
- **Новый tools/*.py**: Да, только при явной потребности человека.
- **Риск**: Низкий.
- **Как проверить**: Выполнить экспорт и открыть результат в любом табличном редакторе.

### 8. Анализатор дубликатов задач (Similarity Checker)
- **Что сделать**: Метод, анализирующий тексты задач и выявляющий потенциальные дубликаты.
- **Какие файлы затронет**: `tools/find_duplicates.py`
- **Новый tools/*.py**: Да, только при явной потребности человека или из friction-боли.
- **Риск**: Низкий.
- **Как проверить**: Запустить в `tasks/` и проверить логику на заранее подготовленных задачах с похожим описанием.

### 9. Форматировщик таблиц Markdown
- **Что сделать**: Утилита для красивого выравнивания столбцов в Markdown-таблицах проекта.
- **Какие файлы затронет**: `tools/format_tables.py`
- **Новый tools/*.py**: Да, только при явной потребности человека.
- **Риск**: Низкий (безопасные изменения пробелов).
- **Как проверить**: Применить к тестовому файлу с неровной таблицей и проверить с помощью `git diff`.

## Отчёты (Reports)

### 10. Генератор ежедневного отчёта (Daily Activity)
- **Что сделать**: Сбор статистики по измененным файлам и закрытым задачам за последние 24 часа.
- **Какие файлы затронет**: `tools/report_diff.py`, `reports/daily_activity.md`
- **Новый tools/*.py**: Нет. Пересекается с `report_diff.py`. Предлагается расширить его функционал.
- **Риск**: Низкий.
- **Как проверить**: Запустить скрипт и сравнить с выводом `git log --since="1 day ago"`.

### 11. Статистика по статусам задач
- **Что сделать**: Сбор распределения задач по колонкам (`todo`, `doing`, `done`) с текстовым прогресс-баром.
- **Какие файлы затронет**: Возможен новый `tools/task_stats.py` или расширение `tools/generate.py`.
- **Новый tools/*.py**: Только при явной потребности человека, иначе лучше встроить в `generate.py`.
- **Риск**: Низкий.
- **Как проверить**: Сравнить вывод скрипта с содержимым `TASKS.md`.

### 12. Отчёт о качестве кодовой базы (Code Quality Snapshot)
- **Что сделать**: Сводка о размере файлов, сложности и наличии TODO-комментариев.
- **Какие файлы затронет**: Возможен новый `tools/code_quality.py` или расширение существующих проверок гигиены (`test_repo_hygiene.py`).
- **Новый tools/*.py**: Только при явной потребности человека.
- **Риск**: Низкий.
- **Как проверить**: Запустить анализатор и проверить соответствие метрик реальности.

## Прототипы (Prototypes)

### 13. Прототип визуализации графа зависимостей (DAG)
- **Что сделать**: Скрипт для создания `.dot` файла на основе поля `depends_on` в задачах.
- **Какие файлы затронет**: Возможен новый `tools/visualize_dag.py`, `docs/dag.dot`
- **Новый tools/*.py**: Да, прототип (создается при потребности визуализации).
- **Риск**: Низкий.
- **Как проверить**: Сгенерировать файл и открыть его в просмотрщике графов (например, Graphviz).

### 14. Прототип CLI-интерфейса для онбординга
- **Что сделать**: Интерактивный терминальный скрипт для помощи новому агенту/участнику в навигации по документам.
- **Какие файлы затронет**: `prototypes/onboarding_cli.py` (папка `prototypes/`, не `tools/`)
- **Новый tools/*.py**: Нет. (Прототипы размещаются отдельно или оформляются как CLI скрипт при потребности).
- **Риск**: Низкий.
- **Как проверить**: Запустить скрипт и пройти интерактивный диалог.
