# Стандарт безопасного коммита

Ответ на near-miss массового удаления ~11 000 строк (2026-07-06): агент собирался
закоммитить массовое удаление через `git commit --no-verify`, что обошло бы
`bulk_guard`; пойман до коммита, откатан. Стандарт закрывает саму возможность.

## Правило (обязательное для всех агентов)

1. **Коммит — только через `python tools/commit.py <явные пути> -m "..."`.**
   Сырой `git commit` допустим лишь когда обёртка недоступна.
2. **`git add -A` / `git add .` / `git add *` — ЗАПРЕЩЕНЫ.** Только явные пути.
   Причина: широкий стейдж в общем дереве сметает удаления, возникшие от
   параллельной работы других агентов.
3. **`git commit --no-verify` — ЗАПРЕЩЁН.** Он выключает весь pre-commit, включая
   `bulk_guard` (страховку D-026). Если хук блокирует по безобидной причине
   (устаревший нав от чужой работы) — чинить корень (регенерировать свою зону /
   worktree / commit_queue), а не обходить гейт.
4. **Массовое удаление файлов/истории — только через accepted-решение и человека.**
   Устаревшее помечается `status: closed`/`deprecated` (принцип `reconcile`,
   docs/nondestructive-reconciliation-2026-07-06.md), не удаляется.

## Оборона в глубину (почему это надёжно)

`--no-verify` — встроенный git-механизм, локально его нельзя отключить. Поэтому
защита строится слоями, и критический гейт стоит там, куда `--no-verify` не
дотягивается — в CI:

| Слой | Механизм | Обходится --no-verify? |
|---|---|---|
| 1. Обёртка | `tools/commit.py` — явные пути, порог удаления, bulk_guard | не нужна (не вызывает --no-verify) |
| 2. Локальный хук | `tools/githooks/pre-commit` → `bulk_guard --hook` (блок при accepted D-026) | **да** (дыра) |
| 3. CI (главное) | `.github/workflows/bulk-guard.yml` — проверка диапазона push/PR, >20 файлов/>500 строк → ожидание одобрения человека в Environment `mass-delete-approval` | **НЕТ** — CI --no-verify не пропускает |
| 4. Детект | CI + `status_drift`/`gap_scan` ловят след обхода (канон-источники + устаревший нав) | — |

Слой 3 — реальный энфорсмент: локальный хук даёт быструю обратную связь, но его
всегда можно обойти; CI не пропускает массовое удаление на push/PR без одобрения
человека, независимо от `--no-verify`. Осознанное массовое удаление одобряет человек
через GitHub Environment `mass-delete-approval` (required reviewers; D-026 П-4,
предложение D-040). Токены в сообщениях коммитов и метки на PR не принимаются.
