# reconcile — неразрушающая сверка коллизий

> **Запрос Stefan (котёл-день 2026-07-06, C2):** формализовать принцип «при дубликате /
> повторении / переполнении / коллизии — НИКОГДА не удалять старое, а записывать в новый
> файл / подвариант / путь / тему / подфайл» — в технический алгоритм с именем.

## 0. Формула

**Коллизия никогда не решается удалением.** Она решается ветвлением в новый адресуемый
артефакт + указателем старшинства. Старое остаётся живым и достижимым; «что важнее»
помечается отдельным указателем, а не фактом существования/несуществования. Удаление
содержания (`drop`) — единственный исход, требующий человека.

## 1. Имя: `reconcile`

Выбрано из трёх предложенных (голоса проектировщиков) за: (а) наследование семантики уже
существующих `tools/git_reconcile.py` и `docs/canon-merge-driver.md` — «union, ни один вклад
не теряется»; (б) нейтральность к исходу (не предрешает merge/drop/supersede); (в) симметрию к
трём носителям коллизий — ID, документы, код. Реализуемо как `tools/reconcile.py`.

**Рассмотренные альтернативы** (сохранены, D-017 — не стирать; переосмыслены как ИСХОДЫ, а не
конкурирующие имена): `dedup` → `action: drop` (только шум, только человек); `merge` →
union-merge; `coalesce` → под-режим для скаляров; `supersede` → значение старшинства; `link` →
cross-link; `sanation` → занято `information-refactoring-sanation-standard`.

## 3. Таксономия случаев (7 классов)

| Класс | Что | Признак распознавания |
|---|---|---|
| **A. ID-reuse** | один ID под разный смысл | один T-/D-/Q-id, разные тела/авторы |
| **B. Точный дубль** | почти одинаковые артефакты | высокое совпадение содержания, разные пути |
| **C. Дивергенция** | варианты одной сущности | одна тема, разные решения/подходы |
| **D. Stale-superseded** | устаревший снимок | нацелен на уже изменённое (напр. на accepted) |
| **E. Переполнение** | файл слишком велик | размер выше порога (dialog.md, documentoutput.md) |
| **E1. Повтор/эхо** *(вариант №1/№3)* | повтор содержания | внутрифайловый повтор ИЛИ эхо-vs-первоисточник |
| **F1. Co-edit** *(вариант №2)* | одновременная правка | два писателя в один файл — **единственный класс, где merge желателен** → `crdt_merge` |

## 4. Случай → исход → условие → механизм-без-удаления

| Случай | Исход | Условие | Механизм (без rm) |
|---|---|---|---|
| A ID-reuse | под-ID / новый ID | смысл держит старый ID → под-ID `T-275.a/.b`; иначе новые ID через `next_id.py` | redirect-заглушка на старом пути; тело каждого смысла сохранено |
| B дубль | primary + cross-link ИЛИ candidate-drop | покрытие бесспорно → superseded+redirect; спорно → cross-link | тело младшего в `variants/`, НЕ удаляется |
| C дивергенция | variant + синтез | пока спор → оба variant; доказано → синтез в решение (D-018) | streams/ + `document-synthesis` skeleton |
| D stale | reframe-as-audit | покрыто новым | пометка «аудит», redirect на актуальное; источник не трогать |
| E переполнение | roll-over *(№2)* / снапшот-заморозка *(№3)* / папочный режим (D-002) | выбор стратегии — человек | старое → архивный снапшот `_full-<sha8>.md`, новый — активный |
| E1 повтор | coalesce / пометка эхо | внутри файла vs эхо | сжать в ссылку на первоисточник, тело сохранить |
| F1 co-edit | union-merge | list-поля / непересекающиеся строки | `crdt_merge` / `git_reconcile` — оба вклада входят |

## 5. Старшинство без удаления

Значения указателя: **`primary`** (актуальный) · **`superseded`** (перекрыт, с `redirect_to`) ·
**`variant`** (равноправный, ждёт синтеза) · **`redirect`** (заглушка-указатель).

**§5.1. Три механизма (из всех трёх вариантов, взяты все):**
- **оси старшинства** *(№2)* — провенанс / полнота / ратификация как отдельные оси, не один флаг;
- **решётка** *(№1)* — частичный порядок артефактов (что кого перекрывает), не линейный;
- **advisory-overlay** *(№3)* — старшинство как накладываемый советующий слой, не запись-в-тело.

**Инвариант «salvage перед понижением»** *(№3):* прежде чем пометить артефакт superseded,
его уникальное содержание извлекается (в `variants/` или блок salvage) — понижение никогда не
теряет то, чего нет в primary. **Спорный флип primary между конкурентами — только человек.**

## 6. Конвенция именования новых артефактов

- **Под-ID:** `T-275.a` / `T-275.b` (смыслы одного ID); новые самостоятельные — через `next_id.py` (обязательно).
- **Варианты:** `topics/<t>/variants/<agent>-<slug>.md` (тело перед redirect).
- **Redirect-заглушка:** старый путь/ID остаётся файлом с шапкой `redirect_to: <новый>` — ссылки не рвутся.
- **Снапшот переполнения:** `<base>_full-<sha8>.md` (content-address, №1) — неизменяемый архив.
- **Superseded:** шапка `status: superseded` + `redirect_to:` + сохранённое тело.
- Единый словарь reconcile-полей front-matter: `reconcile_of`, `redirect_to`, `supersedes`, `variant_of`.

## 7. Алгоритм (реализуемо как `tools/reconcile.py`)

Только advisory + dry-run; ветки `rm` НЕТ (удаление недоступно инструменту):

0. **Safety-pregate** *(№2)* — проверка D-026 (не массовое ли стирание маскируется под reconcile).
1. **detect** — собрать метки коллизий (список, №3): совпадение содержания, дубль ID, пересечение тем.
2. **classify** — отнести к классу A–F1; развести dup ↔ divergence (разные исходы!).
3. **plan (dry-run)** — предложить исход по таблице §4; напечатать план, НЕ применять.
4. **apply-\*** — запись только по явным флагам (`--apply-redirect`, `--apply-supersede`, `--apply-link`); grow-only.
8. **verify-no-loss** *(№2)* — после apply убедиться, что тело каждого вклада достижимо (salvage-инвариант).

## 8. Консенсус и расхождения трёх независимых вариантов

**Консенсус (независимо сошлись — сильный сигнал):**
1. Все три построили **7-классовую таксономию** с одними ядрами (ID-reuse, дубль, дивергенция, stale, переполнение, повтор/эхо) — разными разрезами.
2. Все три назвали базой **CRDT MV-Register / concurrent-siblings + append-only/COW** и явно отвергли авто-merge и LWW «по счёту/дате».
3. Все три: **redirect-заглушка с сохранением тела ПЕРЕД сворачиванием** (`variants/` + salvage), и **старшинство = отдельный указатель**, а не факт существования.
4. Все три спроектировали **один advisory-детектор (dry-run) — обёртку над существующими движками**, без ветки `rm`.

**Расхождения (сохранены все, не сведены к одному — D-029):**
- **Где «сидит» принцип:** структура ячейки/файла (№1) · переход состояния/ЖЦ (№2) · детектор-роутер (№3) — разные слои, не конкуренты; берём все три.
- **Модель старшинства:** решётка (№1) vs три оси (№2) vs advisory-overlay (№3) — взяты все (§5.1).
- **Safety-gate D-026** как явная фаза — только у №2 → взят самый осторожный.
- **Классы E1** (внутри vs между файлами) и **F1** (concurrent-edit) — сохранены оба смысла.
