# Политика безопасности драйверов (T-036)

Единый свод правил безопасности для драйверов (Treiber) и работы с большими/внешними папками. Сводит воедино принципы из `decisions/D-010`, `drivers/SCHEMA.md`, `Q-008` и `tools/permissions.json`. Действует для всех агентов.

## Правила (обязательные)

1. **Read-only по умолчанию.** Новый драйвер начинает в режиме `mode: read-only`. Запись/изменение/удаление — только после явного решения и обновления манифеста.
2. **Dry-run перед записью.** Любая операция записи сначала показывает план («что будет изменено»), применяется только после подтверждения. Для пакетных правок — обязательно.
3. **Никакого запуска непроверенного кода без песочницы.** `run`/`test`/`install`/shell/сеть для внешних репозиториев (Sven4 и пр.) запрещены, пока нет: отдельной песочницы (выделенный пользователь/контейнер), лимитов CPU/памяти/сети и отдельного решения. Сначала только `inspect`/`summary` (read-only).
4. **Секреты — вне репозитория.** Токены, пароли, ключи не хранятся в `drivers/`, `tasks/`, `logs/` и любом коммите. Только переменные окружения / секрет-стор. Манифест: `secrets: forbidden-in-repo`.
5. **Аудит для risk medium/high.** Драйверы с `risk: medium|high` обязаны логировать вызовы (`audit: true`, поле из Q-008/B). Запись — в `logs/` (per-agent/per-task, не в общий горячий файл) и/или `workbench.db audit_log` (T-031).
6. **Минимум прав.** Драйвер видит только то, что нужно для задачи (зона в `tools/permissions.json`). Не расширять зону «на всякий случай».
7. **Лимиты на процесс.** `timeout_seconds` (по умолчанию 30) и `max_output_bytes` (по умолчанию 1MB) — защита от runaway и memory blow-up (поля из Q-008/B).
8. **Детекция дрейфа.** Поле `source_last_verified` в манифесте; если источник менялся, а манифест старый (>30 дней) — валидатор предупреждает, данные пересверяются.

## Степени риска (как назначать)

| risk | Когда | Автономия (risk_gate) |
|---|---|---|
| `low` | чтение в своей зоне, без сети, без секретов | AUTO |
| `medium` | запись, сеть, БД, внешние данные | REVIEW (+ audit) |
| `high` | запуск кода, удаление, доступ к секретам/системе | HUMAN (+ audit + песочница) |

## Чек-лист перед включением драйвера

- [ ] `mode: read-only` (или есть решение на запись)
- [ ] `secrets: forbidden-in-repo`, секретов в файлах нет
- [ ] `risk` назначен честно; для medium/high — `audit: true`
- [ ] `sandbox` указан, если возможен запуск кода
- [ ] зона в `permissions.json` минимальна
- [ ] для внешних репозиториев — только `inspect`/`summary` на L1
