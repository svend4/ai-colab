# План тестового корпуса для драйверов (T-038)

Маленький, безопасный, детерминированный набор fixture-файлов для проверки драйверов (`files`, будущие `text-extract`, `search-index`, `report`). Корпус коммитится в репозиторий (он мал и безопасен), живёт в `drivers/test-corpus/`.

## Состав корпуса (10–20 файлов)

| Файл | Назначение (что проверяет) |
|---|---|
| `plain.txt` | обычный UTF-8 текст |
| `unicode.txt` | кириллица + emoji + спецсимволы (кодировки) |
| `empty.txt` | пустой файл (граничный случай) |
| `big.txt` | ~200 КБ (проверка `max_output_bytes`/усечения) |
| `data.csv` | таблица (для `text-extract`/`data`) |
| `record.json` | вложенный JSON |
| `config.yaml` | YAML с front-matter-подобной структурой |
| `sample.py` | код Python (языки, тесты-детект) |
| `sample.md` | markdown с заголовками/таблицей |
| `nested/a.txt`, `nested/deep/b.txt` | вложенные папки (обход дерева) |
| `dup1.txt`, `dup2.txt` | одинаковое содержимое (дедуп/похожесть) |
| `risky.sh` | shell-скрипт (детект потенциально опасного — НЕ запускать) |
| `secret-like.txt` | строка вида `API_KEY=...` (детект секрет-паттернов, проверка что НЕ логируется) |

Все файлы — безопасные, без реального исполнения, без настоящих секретов.

## Сценарии и критерии PASS/FAIL

**files (read-only): list / read / search / summarize**
- `list(.)` → PASS: видит все файлы включая `nested/**`; FAIL: пропуск вложенных.
- `read(empty.txt)` → PASS: пусто без ошибки; FAIL: исключение.
- `read(big.txt)` → PASS: усечение по `max_output_bytes`, помечено; FAIL: отдаёт всё/падает.
- `search("API_KEY", .)` → PASS: находит в `secret-like.txt`, но значение НЕ попадает в лог/аудит; FAIL: секрет утёк в лог.
- `summarize(.)` → PASS: число файлов, типы, размеры верны.

**text-extract (будущий): извлечение текста**
- `data.csv`, `record.json`, `sample.md` → PASS: чистый текст/структура; FAIL: мусор/битая кодировка на `unicode.txt`.

**search-index (будущий): индекс + поиск по смыслу/словам**
- индекс по корпусу → запрос «конфигурация» → PASS: возвращает `config.yaml`/`sample.md`; FAIL: пусто или нерелевантно.

**report / repo-inventory: карта + риски**
- inventory корпуса → PASS: верно классифицирует языки, помечает `risky.sh` и `secret-like.txt` как риск; FAIL: не помечает опасное.

## Общие критерии

- **Детерминированность:** один и тот же корпус → один и тот же результат (для регресс-тестов).
- **Безопасность:** ни один сценарий не запускает `risky.sh` и не печатает содержимое `secret-like.txt` в логи.
- **Read-only:** прогон не меняет файлы корпуса.
