# Независимый консенсус: конвейер «вариант → сверка по смыслу» (операционная методичка)

Дата: 2026-06-25 · Статус: **proposed** (kotel-консенсус готов, D-029 предложен Codex). Источник: методичка `variants/independent-first-reconcile-2026-06-25/`, карта консенсуса `kotel/independent-first-reconcile-consensus-2026-06-25.md`.

Цель — как ПРАКТИЧЕСКИ прогнать цикл, где N агентов/людей сначала вслепую вырабатывают свой полный вариант, и лишь потом сверяются — **по смыслу, не по числу голосов**, сохраняя минор-уникальное.

## Принцип (одной строкой)
Независимость нельзя оставлять на волю — её ловит ПРОЦЕСС (барьеры между фазами). Совпадение ценно ТОЛЬКО при независимости (иначе эхо). Консенсус = пережил опровержение, а не набрал голоса.

## Конвейер: 5 фаз → тула → CLI

| Фаза | Что делает | Тула | Запуск |
|---|---|---|---|
| 1. Производство (вслепую) | каждый автор пишет свой вариант в `variants/<тема>/<автор>.md`, не читая чужих | — | соглашение: `sealed: blind`, `model:`, `lens:` в front-matter |
| 2. Гейт зрелости+печати (вход) | вариант в котёл, только если выработал потенциал (5 полей) И запечатан | `ripeness_gate.py` | `python tools/ripeness_gate.py --board` |
| 3. Мера независимости | эффективное число свидетелей (клоны схлопываются: N клонов = 1) | `independence_measure.py` | `python tools/independence_measure.py <тема-dir>` |
| 4. Консенсус по смыслу | 3-слот: ядро(≥2 свидетеля)·минор(сохранён)·scope; вес = свидетели, не count | `consensus_by_meaning.py` | `python tools/consensus_by_meaning.py <тема-dir>` |
| 5. Red-team-гейт (выход) | в канон, только если пережил опровержение; refuted → negative-set с причиной | `red_team_gate.py` | `python tools/red_team_gate.py redteam/<тема>.md` |

Линт «3 слоёв» для самих тул: `python tools/code_pyramid.py --board`.

## Два структурных гейта (симметрия)
- **Вход — `ripeness_gate`** (И-1 seal + И-2 зрелость): тонкий/незапечатанный вариант не входит в сверку.
- **Выход — `red_team_gate`** (RT-1..4): «консенсусный» claim не идёт в канон без записи `survived`.

## Две несущие стены
- **№1 — канонизация claim ПО СМЫСЛУ.** Лексика не видит конвергенцию разными словами (доказано: 0 ядра лексикой vs 9 семантикой). Решение: семантический канонизатор (LLM). **Надёжность доказана** — 3 независимых канонизатора (вкл. англоязычный) дали ту же топологию ядра. Подключается как смысловой шаг в фазу 4.
- **№2 — измерение независимости** (а не объявление): `independence_measure` считает свидетелей по генотипу+поверхности. seal доказывает порядок, мера — независимость.

## Как прогнать полный цикл (пошагово)
1. Поставить вопрос в общую ветку (только вопрос, не ответы).
2. Каждый автор: свой вариант в `variants/<тема>/<автор>.md`, вслепую, `sealed: blind`. Раскрыть до 5 полей (условия·ответ·уникальное·риски·вопросы).
3. `ripeness_gate --board` → отсеять незрелые НАЗАД.
4. `independence_measure <тема>` → сколько РЕАЛЬНО независимых свидетелей (флаг, если одна модель).
5. Сверка: семантически канонизировать claim (стена №1) → `consensus_by_meaning` взвешивает по свидетелям → ядро·минор·scope.
6. Расхождения: сперва детализировать («разные условия → оба правы?»), потом — настоящий конфликт.
7. Red-team каждого ядро-claim → `red_team_gate` → survived в канон, refuted в negative-set с причиной.
8. Промоушн консенсуса в общую ветку; варианты остаются как история (не удаляются).

## Триада/фрактал и масштаб
Охват триадичен: автор (малый) → кластер/портал (средний/золотая середина) → глобал (большой). Человек = ещё одна линза-автор в той же `variants/` (симметрия агенты↔люди). Для КОДА: дивергенция на уровне концепта/псевдокода (`variants/code-divergence-sandbox-2026-06-25/`), реализация — один раз в worktree.
