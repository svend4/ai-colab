# AI-агенты и автоматические участники

Реестр AI-агентов, скриптов и автоматических участников, которые могут читать или писать в рабочую папку.

## Правила для всех агентов

- Работать по `PROTOCOL.md`.
- Не удалять чужие сообщения.
- Не переписывать историю обсуждения.
- Не менять финальные решения без новой записи в `DECISIONS.md`.
- Для больших тем писать отдельные сообщения в `topics/<topic>/messages/`.
- Для результатов автоматической работы использовать `queues/outbox/`.
- Если агент не уверен, он должен создать вопрос в `QUESTIONS.md`, а не молча менять итоговые файлы.
- Автоматический агент может добавлять решения со статусом `proposed`; перевод в `accepted` делает человек или явно назначенный человеком сборщик.
- Захват задачи — `python tools/pipeline.py next <agent>` (или `claim <agent> <T-id>`); `queues/claimed/` — legacy-история, отметки в нём руками не создавать (см. `PROTOCOL.md`, раздел «Очереди для агентов»).
- Коммит в общее дерево — через очередь коммитов `tools/commit_queue.py` (`enqueue <agent> --save` → `turn` → `git commit` → `done`, D-031); при триггерах параллельной работы (`python tools/cohort.py guard`) — уход в worktree Уровня-1 (D-022). Подробно: `PROTOCOL.md`, раздел «Commits, streams и полу-коммиты».

## Ростер и зоны записи

Единый источник ростера — `tools/_canon.py`, зоны записи — `tools/permissions.json` (проверка: `python tools/permissions.py <agent>`).

- **Ростер** (`AGENTS_ROSTER`, ратифицирован: Stefan, 2026-07-06): claude, codex, mavis, novax.
- **Кандидат в ростер**: jules (Google Labs Jules, облачный агент) — работает только через ветки и PR; статус по D-041 (`proposed`).
- **Служебные** (`SERVICE_AGENTS`): subagent-worker — служебные исполнители роёв (workflow-подагенты); их следы в рабочих артефактах — норма, `validate.py` не даёт WARN (решение Stefan 2026-07-06).
- **Исключённые** (`EXCLUDED_AGENTS`): antigravity — вне ростера до объяснения по инциденту outbox-mass-strip (решение Stefan 2026-07-06); `validate.py` напоминает WARN'ом с этой причиной.
- **Критические пути** (deny-список `"_deny_agents"` в `tools/permissions.json`, проверяется ПЕРВЫМ для любого агента, включая зону `**`): `tools/permissions.json`, `tools/githooks/**`, `sandbox/approvals/**` — правит только человек (решение Stefan 2026-07-06, закрывает gate-10/C31).
- claude/codex — широкая зона записи (`**`) за вычетом критических путей выше.

## Проверка

- Зависимости для тестов: `python -m pip install -r requirements.txt` (там только pytest).
- Полный прогон, как в CI (`.github/workflows/nightly-tests.yml`): `PYTHONUTF8=1 python tools/test_all.py --with-pytest`.
- Облачные агенты (jules) запускают полный прогон перед тем, как открыть PR, и пишут результат в описании PR.
- PR в `main` дополнительно проверяет `.github/workflows/canon-check.yml`.

## Дополнение к Матрице полномочий (D-027)

Единственным техническим источником правды для определения зон записи агентов является файл `tools/permissions.json`. Любое нарушение границ блокируется на этапе pre-commit. Все новые агенты или скрипты обязаны быть добавлены в матрицу полномочий.
