# Skill: ревью репозитория (repo-review)

Повторяемая процедура перепроверки и независимого ревью (как в `темы/repo-review-2026-06-21.md`).

## 1. Перепроверка (re-check) — факты, не мнения

```bash
python tools/validate.py                 # канон: 0 ERROR? манифесты/tools/ссылки
python tools/generate.py --check         # навигация/index не STALE?
python tools/pipeline.py status          # есть ли ready/doing/застрявшие blocked?
# тесты драйверов:
for t in drivers/*/test_*.py; do python "$t"; done
python drivers/mcp_sync_acceptance.py    # MCP tools/call 19+/N (переносимо)
```

Зафиксируйте РЕАЛЬНЫЙ вывод. Ищите дрейф: `STALE index`, `doing without active claim`,
`status: blocked` за уже снятой причиной, placeholder-задачи, stale heartbeat,
манифесты `ready` без зелёной приёмки (D-015).

## 2. Ревью по измерениям

Архитектура · governance · качество tools/*.py (конкурентность/Windows) · drivers/security
(allowed-root/redaction/audit/sandbox) · здоровье процесса (дрейф) · ценность коллаборации
(продукт vs мета-отчёты). Каждый минус — с доказательством `файл:строка`.

## 3. Вывод

- **Плюсы/минусы** по важности (high/medium/low) с доказательствами;
- **Рекомендации** P0 (сейчас)/P1 (код-безопасность)/P2 (стратегия);
- спорные статусы/чужие файлы — **предлагать** (proposed), не менять молча (D-006);
  технический статус драйвера менять по **D-015** (код работает + сверка ≥2 агентами).

Отчёт — в `темы/<review>.md` + указатель в `queues/outbox/`; не дублировать тяжёлый отчёт
в нескольких местах (одна каноническая копия + ссылки).

## Готово, если

`validate ERROR=0`, перечислены проверенные находки с доказательствами и приоритизированные
рекомендации; ничего чужого не изменено молча.
