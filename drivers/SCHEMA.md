# Driver Manifest Schema v1

Статус: **draft**. Это рабочее предложение по Q-008, а не финально принятое решение.

Цель схемы: сделать `drivers/*.md` не просто описательными текстами, а проверяемыми манифестами способностей проекта. На L1 драйвер остаётся Markdown-файлом, но его front-matter должен быть достаточно строгим, чтобы агент мог понять назначение, риск, режим запуска и ограничения.

## Обязательные поля

| Поле | Пример | Назначение |
|---|---|---|
| `id` | `repo-runner` | Стабильный ASCII id драйвера. |
| `type` | `driver` | Для настоящих драйверов всегда `driver`. |
| `title` | `Repo runner — inventory репозиториев` | Человекочитаемое название. |
| `status` | `draft`, `ready`, `deprecated` | Жизненный цикл манифеста. |
| `level` | `L1`, `L2`, `L3` | Архитектурный уровень: манифест, tool/MCP, сервер. |
| `mode` | `read-only`, `manual`, `safe-write`, `execute` | Максимально разрешённый режим. |
| `owner` | `Codex`, `Novax` | Кто отвечает за актуальность. |
| `risk` | `low`, `medium`, `high` | Риск драйвера. |
| `activation` | `manual`, `pipeline`, `mcp`, `scheduled` | Как драйвер активируется. |
| `interfaces` | `[inspect, summarize]` | Доступные функции/контракты. |
| `inputs` | `[repo-path, repo-url]` | Разрешённые входы. |
| `outputs` | `[summary, risk-report]` | Ожидаемые выходы. |
| `sandbox` | `required-before-run-or-test` | Требование к песочнице. |
| `secrets` | `forbidden-in-repo` | Политика секретов. |
| `source_last_verified` | `2026-06-20` | Когда манифест сверяли с реальным источником. |
| `timeout_seconds` | `30` | Лимит времени для будущего L2/L3 вызова. |
| `max_output_bytes` | `1048576` | Лимит вывода для будущего L2/L3 вызова. |
| `audit` | `true`, `false` | Нужно ли журналировать вызовы. |
| `related` | `темы/ai-os-bridge.md` | Связанные темы, задачи, решения. |

## Опциональные поля

| Поле | Пример | Назначение |
|---|---|---|
| `tools` | `[list_tables, columns, head, summarize]` | Фактические имена `@mcp.tool()`, зарегистрированные MCP-сервером драйвера. В отличие от концептуального `interfaces`, это машинно-проверяемый контракт: `tools/validate.py` сверяет его с реальными декораторами в `drivers/<id>/mcp_server.py` и выдаёт ERROR при расхождении (борьба с дрейфом «interfaces ≠ tools», ревью T-078 находка K). Поле опционально: проверка включается только если `tools` объявлено. |

## Рекомендуемые значения

`status`:

- `draft` — описание ещё обсуждается;
- `ready` — можно использовать как контракт;
- `deprecated` — не использовать для новых задач.

`level`:

- `L1` — Markdown-манифест, без runtime;
- `L2` — локальный tool/MCP, всё ещё ограниченный;
- `L3` — серверный или sandbox runner.

`mode`:

- `read-only` — только чтение и анализ;
- `manual` — действие выполняет человек/агент вручную по инструкции;
- `safe-write` — запись только в разрешённые выходные каталоги, обычно с `--dry-run`;
- `execute` — запуск кода или внешних процессов; требует отдельного решения и sandbox.

`risk`:

- `low` — чтение локальных файлов без секретов и без исполнения;
- `medium` — структурированные данные, репозитории, локальные инструменты, возможные персональные данные;
- `high` — запуск кода, сеть, внешние API, массовые изменения, секреты.

## Правила безопасности

- `risk: medium` и `risk: high` должны иметь `audit: true`.
- `mode: execute` без отдельного решения запрещён.
- `secrets` не должен быть `in-repo`.
- Для `mode: safe-write` нужен dry-run режим или отдельное объяснение, почему он невозможен.
- `source_last_verified` нужен для борьбы с дрейфом: если источник изменился, статичный манифест может ввести агента в заблуждение.
- `timeout_seconds` и `max_output_bytes` обязательны даже для L1, потому что L1 должен заранее проектировать будущий L2/L3 runtime безопасным.

## Минимальная проверка будущим валидатором

В `tools/validate.py` позже стоит добавить:

1. Все `drivers/*.md` с `type: driver` имеют обязательные поля.
2. `risk` входит в `low|medium|high`.
3. `mode` входит в `read-only|manual|safe-write|execute`.
4. `risk: medium|high` требует `audit: true`.
5. `timeout_seconds` — положительное число.
6. `max_output_bytes` — положительное число.
7. `source_last_verified` имеет формат `YYYY-MM-DD`.
8. (реализовано, T-086) `mode: execute` выдаёт ERROR, если `sandbox` не указывает реальную изоляцию (`container`/`docker`/`nsjail`/`firejail`/`gvisor`/`sandboxed-vm`); с реальной изоляцией — WARN (подтвердить accepted-решение). Декларативные значения (`required-before-...`) execute не разрешают.
9. (реализовано, T-084) Опциональное поле `tools` сверяется с реальными `@mcp.tool()` в `drivers/<id>/mcp_server.py`; расхождение — ERROR.

## Мнение Codex

Для текущей стадии лучший вариант — **B из Q-008**: расширенный манифест без MCP-метаданных. Он уже закрывает три практических риска: дрейф источника, runaway-процессы и отсутствие audit trail. Полный MCP-manifest лучше отложить до первого реального L2/MCP PoC.
