# Drivers — L1-каталог информационных драйверов

Эта папка — первый практический слой AI-OS Bridge по D-010. Здесь описываются пассивные способности проекта: файловые, информационные, репозиторные, локальные и серверные драйверы.

В ранних обсуждениях встречались слова «трайбер» и `trailers/`. Каноническое имя каталога в репозитории — **`drivers/`**; «трайбер» остаётся допустимой метафорой в тексте.

Терминология:

- **driver** — внутренний короткий термин проекта.
- **Treiber** — немецкий технический перевод слова «драйвер».
- **Datenadapter** — драйвер данных.
- **Informationsadapter** — драйвер/адаптер знаний и документов.
- **Konnektor** — драйвер внешнего API или сервиса.
- **Schnittstelle** — интерфейс/контракт функций.

На уровне L1 драйвер — это markdown-манифест, а не запущенный процесс. Он описывает назначение, риск, режим активации, права, входы, выходы и будущий путь к L2/MCP.

## Правила

- Драйверы по умолчанию **пассивные**: они не запускаются сами.
- Первый режим для новых драйверов — **read-only**, если нет отдельного решения.
- Секреты, токены и пароли не хранятся в `drivers/`.
- Запуск непроверенного кода требует отдельной песочницы и отдельного решения.
- Если драйвер станет реальным инструментом/MCP, его манифест обновляется, а решение фиксируется в `decisions/`.

## Текущие черновики

| ID | Назначение | Первый режим | Риск |
|---|---|---|---|
| `files` | безопасное чтение и инвентаризация файлов | read-only | low |

## Backlog из `docs/ai_middle_layer_architecture_ru.md`

Импортированный документ предлагает более широкий набор практических драйверов. Не создаём их все сразу, но используем как backlog:

- `file_inventory_driver` — карта файлов, hash, типы, размеры.
- `copy_driver` — безопасное копирование без изменения оригиналов.
- `text_extract_driver` — извлечение текста из PDF/DOCX/HTML.
- `classification_driver` — классификация документов и тем.
- `dedupe_driver` — поиск дублей.
- `report_driver` — генерация Markdown/CSV/HTML-отчётов.
- `ocr_driver` — OCR для сканов.
- `anonymization_driver` — обезличивание копий, не оригиналов.
- `search_driver` — SQLite FTS/BM25, позже embeddings.
- `github_repo_driver` — инвентаризация репозиториев.

Правило D-010 остаётся прежним: сначала L1-манифесты и read-only PoC, потом MCP/сервер только при реальной необходимости.
