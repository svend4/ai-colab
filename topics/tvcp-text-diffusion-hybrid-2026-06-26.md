# textscene — 2D полу-диффузионная многоагентная текстовая модель

> Цель автора TVCP (Stefan Engel): обратить всю мощь терминальной видеосвязи на **параллельную текстовую** обработку — «полу-диффузионная модель для ТЕКСТА». 1D-чат = строка во времени; видео = 3D; нужен **средний путь — 2D-карточки**, где положение несёт смысл, а не время.

---

## 0. Визитка

| | |
|---|---|
| **Что** | 2D-сетка карточек смысла + детерминированное «проявление» (coarse seed → fine body) + многоучастниковая канва людей и ИИ-агентов |
| **Откуда мощь** | TVCP-примитивы, проверенные в коде: `Grid.DiffuseFrames` (детерминизм без GPU), `scene.Op box/text/rect` (2D draw-DSL = карточки), raymeet `Region`/`Pose` («смысл не пиксели»), `tvcp-ai/1` (любой мозг за одним JSON-HTTP) |
| **Куда применяем** | наш файл-нативный канон: `view.py`/`view_html.py`, `crdt_merge.py`/`seq_merge.py`, `canon_index.py` (FTS5), `thread_runner.py` |
| **Новые артефакты** | `tools/text_scene.py`, `tools/text_mux.py` + **правка** `tools/crdt_merge.py` (чинит реальный баг) |
| **Несущее ядро** | **РАСКЛАДКА / РАДИУС / ПОРЯДОК детерминированы** (чистые функции, явный ключ) ↔ **СЕМАНТИКА ТЕЛА = оракул**, который держится ВИДИМЫМ на всех уровнях |
| **Главная честность** | «диффузия» для текста — это **прогрессивное раскрытие**, не denoising; «семантический blur» как усреднение токенов **не определён** и из MVP **вырезан** |

## 1. Оценка живого TVCP (кратко, +/−)

**Доки (+):** drift-guard встроен в документацию, а не декларирован: `TVCP_AI_PROTOCOL` §0/§8 — «authority is the Go code; where prose and code disagree, the code wins», подпёрто `speccoverage_test.go` (каждый advertised kind покрыт `ConformanceBattery`). `CONCEPT_MAP` даёт граф **переиспользования** (хабы SceneVector/Hexagram/Quest/Ecosystem), а не список фич — прямой аналог нашего `view.py`-среза по `[[links]]`.
**Доки (−):** статусный дрейф README↔домен-доки (README Roadmap «Text chat [ ]», а `TEXT_CHAT.md` описывает фичу работающей); числа захардкожены и разъехались («~120» vs «121 команда»); многоучастниковость размазана по трём несшитым докам (`TEXT_CHAT` 1D + `SHARED_WORLD` raymeet + §11 Contract Net).

**Идея (+):** «смысл не пиксели» — это **байтовый бюджет**, а не лозунг: `Region`~100–300Б, `Pose` 44Б/тик. `tvcp-ai/1` swap-brains + `CheckResponse` как «validator = trust boundary» = архитектурный аналог нашего «кворума оракулов» с детерминированной проверкой формы.
**Идея (−):** псевдо-диффузия = **upscale+blur**, НЕ диффузия (нет data-driven denoising). Для пикселей ок; для текста «усреднить смысл двух блоков» **не определено** — оператора нет, его пришлось бы изобретать (и это вся трудность за красивой аналогией). raymeet — **звезда с единственным автором** (анти-CRDT): конфликтов нет по конструкции, поэтому конфликт-резолюции в TVCP нет — а нам она нужна.

**Код (+):** детерминизм образцовый и переносимый: `DiffuseFrames` (`grid.go:117`) сеет шум через `rand.NewSource(1)`, `alpha=i/(steps-1)` (`grid.go:128`), blur затухает `rad=maxRad*(1-alpha)` (`grid.go:136`) — чистая арифметика, GPU-free, golden-тестируемо. Дисциплина `clampi`/`Color()` def-fallback — «misbehaving model can't blow up the frame». Лестница `sketch → ToScene → scene.Op` = «меню→детали».
**Код (−):** `scene.Apply` (`scene.go:75`) НЕ санирует per-op `X/Y/W/H/R` — `case "rect"` (`scene.go:85`) и `case "disc"` (`scene.go:126`) гоняют циклы по сырым JSON-значениям (только канва клампится в `RenderScene`); `Grid.rect:43` молча «extend last color» (придумывает данные); нет golden-теста на `DiffuseFrames(seed=1)`; гонка на общий `g.pal`.

**Безопасность (+):** явный thread-model для `BRAIN_URL` (§14 «brain endpoint is untrusted»), HMAC-подпись записей реестра (§10 `pkg/sign`), ack-based идемпотентный apply + id-dedup (`ChatSync`).
**Безопасность (−):** §11 Contract Net описывает много-мозговую кооперацию, но живой raymeet **строго одно-директорный** (`SHARED_WORLD:99` host=single author) — торг ДО задачи, не арбитраж ВО ВРЕМЯ; conformance проверяет ЛЕГАЛЬНОСТЬ, не КАЧЕСТВО («a brain may advertise a kind it answers badly»); `BRAIN_URL` без аутентификации/рейт-лимита; нет модели угроз для внутреннего недоверенного гостя.

## 2. Гибрид «2D полу-диффузия текста»: суть и почему 2D — средний путь

1D-чат (`TEXT_CHAT.md`) кодирует **одну ось — время**: строка за строкой, прошлое уходит вверх. 3D-видео (`raymeet`) кодирует пространство **с глубиной** — но у текста глубины нет, поэтому полная аналогия `pkg/raytrace` ломается. **Средний путь — 2D-сетка карточек, где положение несёт смысл, а не время.**

- **Ось Y = слой абстракции** (вниз = от общего к частному, progressive disclosure: меню→детали).
- **Ось X = ширина темы** (соседние карточки = смежные подтемы).

Это прямой текстовый аналог `Grid.Rows[y][x]` из `grid.go`: там ячейка несёт цветовой токен («navy»), у нас — `Seed{id, gist, links, type}`. Карточка рисуется **уже существующими** `scene.Op` без новых op-кодов: `box`=`f.DrawBox` (`scene.go:121`, рамка), `text` (`scene.go:114`, заголовок+тело), `vgradient` (`scene.go:90`, шапка/phase-бар).

**Хребет — Проект 5 (textscene): ровно 2 новых файла + 1 правка**, потому что 3 из 4 контуров у нас уже построены:
- раскрытие = `view_html.py` `<details>`-каскад;
- ретрив = `canon_index.py` FTS5;
- агент-цикл = `thread_runner.py`.

> **Честная оговорка о пределе аналогии (красная команда [videopower], принято).** «Видео» в TVCP делает один примитив — `DiffuseFrames` (шум→цель, документированная scene-wipe). И именно он **НЕ переносится**: что выживает — лишь `upscale`+`blur` цветовых каналов (`upscaleBilinear`: `top.Blend(bot, ty)`). У текста **нет непрерывного канала для `Blend`**: нельзя лерпнуть `seed_id A → seed_id B`. Поэтому «доля L2-ячеек растёт `alpha=i/(steps-1)`» — это **НЕ диффузия, а прогресс-бар над дискретным порядком раскрытия**. Мы **не называем staged-reveal «диффузией»**: транспортируемый примитив — это `upscale+blur` как **операция РАСКЛАДКИ** (грубая сетка-сид → детальная плитка), а denoising-анимацию из несущих claim'ов исключаем (оставляем опционально как «анимация раскрытия», без претензии на изоморфизм).

## 3. Механизм псевдо-диффузии текста (сид → проявление)

Переносим стадии `grid.go` на смысл, сохраняя детерминизм, и **демотируя bm25 из детерминированного ядра** (две трещины детерминизма, найденные красной командой — закрыты):

### 3.1 Seed ← `Grid.rect()`
`text_scene.seed(seed_id|query, cols, rows)` собирает темы по **двум осям**: `canon_index.search` (FTS5) ∪ `view.slice_ids` (BFS по `[[links]]`). Рваная сетка нормализуется как `rect()`, но **пустая ячейка добивается дефолтом-плейсхолдером `·`** (НЕ повтором соседа, как `grid.go:43` — это его баг для семантики: «дорисовка» придумала бы контент).

> **Трещина детерминизма #1 (раскладка), закрыта.** `sha256(seed_id+query)` фиксирует ПОРЯДОК раскладки, но `view.slice_ids` (`view.py:58`) возвращает `[seed]+[i for i in seen ...]`, где `seen` — Python **set**, итерация которого НЕ insertion-ordered. Комментарий «BFS-порядок сохранён» в `view.py` сам неверен. **Фикс:** `seed()` помечает каждый id **глубиной BFS** и сортирует по `(depth, sha256(seed_id+id))` — это и есть корректный текстовый аналог `rad=maxRad*(1-alpha)` (раскрытие от центра по графовому расстоянию). Никогда не полагаемся на порядок множества. **Golden-тест** пинит точную последовательность карточек для фиксированного корпуса (тот самый тест, которого мы требуем у TVCP для `DiffuseFrames(seed=1)`).

> **Трещина детерминизма #2 (сид), закрыта.** `canon_index.search` ранжирует `ORDER BY bm25(canon)` (`canon_index.py:54`); bm25 зависит от ГЛОБАЛЬНОЙ статистики корпуса, значит один запрос на двух узлах с расходящимися корпусами даёт **разные ячейки сида** — не только тела. Это ломает «детерминированный сид» в late-join MMORPG-сценарии (`SHARED_WORLD:101` «late joins self-heal»). **Фикс — выбран вариант (b), честный и совпадающий с собственным host=author принципом дизайна:** хаб — **единственный автор сетки-сида** (raymeet host-single-author), broadcast `card_seed` авторитетно; гости **не перезапускают search**, только идемпотентно применяют. Опционально (a) — переранжировать FTS по корпус-независимому ключу (link-distance / лексический sha256). «Каждый узел пересчитывает одинаково» — **выброшено как фантазия**.

### 3.2 Проявление ← три L-уровня (то, что РЕАЛЬНО есть в `assemble()`)
- **L0** = `▦ type+id` (тонкое новое дополнение к `view.assemble`);
- **L1** = `+ gist` ← `view.py:112 _gist` (= «первая строка длиннее 12 символов», **существует, детерминирован**, режим `live`);
- **L2** = `+ тело` ← `view.assemble` frozen (inline body, существует).

`diffuse_steps(grid, steps)`: доля L2-ячеек растёт линейно по `alpha=i/(steps-1)`, порядок раскрытия = глубина BFS из 3.1. **Это рабочее трёхстадийное прогрессивное раскрытие, которое красиво деградирует в сегодняшний `view_html` `<details>`-каскад.** Мы **называем это reveal-staging, а не token-space интерполяцией**.

> **Вырезано из MVP (красная команда [feasible]/[idea], принято).** Опциональный «строгий L-движок» (token-`Blend` интерполяция gist-токенов 4 соседей + separable текст-blur, `tf≥окно/2`) **не сводится ни к одному существующему примитиву и не имеет определённой математики**: единственная `gist`-функция — `_gist` (чистая селекция, не усреднение); `RGB.Blend` — взвешенное среднее ТРЁХ чисел, а gist-токены — множество слов без метрики. На коротких/разнородных корпусах усреднение даёт пустой gist. **Это та самая «красивое слово без механизма», на которую целится линза автора.** Если возвращать — только как конкретный код с тестом, и НЕ называть «Blend»; defensible-замена соседской операции = **top-k общих FTS-термов (пересечение множеств)**, а не интерполяция.

## 4. 2D-раскладка карточек/меню (scene-DSL ↔ view_html)

`card_to_ops(card, L)` → набор `scene.Op` (графт Проекта 2):
- `{op:box}` (рамка) + `{op:vgradient,h:1}` (шапка) +
- `{op:text,s:id}` + `{op:text}`-строки тела (детерминированный жадный `wrap()`) +
- `{op:text,s:"→"+links}` (рёбра-каналы).

**Терминал-рендер.** `RenderScene` клампит **только канву** 400×200 (`scene.go:149-154`), значит ≈ ≤16 карточек/экран, дальше пагинация/фокус-зона+миниатюра.

> **Унаследованный баг санитизации, закрыт на нашей стороне (красная команда, принято).** `scene.Apply` НЕ клампит per-op `X/Y/W/H/R` — карточка с длинным wrapped-заголовком даст огромный `W` и попадёт прямо в незащищённый цикл `case "rect"`/`case "disc"`. `RenderScene` защищает канву, **не** геометрию op. **Фикс:** `card_to_ops` **клампит каждый op по локальному box карточки ПЕРЕД** передачей в рендер (та же `clampi`-дисциплина, что мы советуем TVCP, применённая к своему эмиттеру), ИЛИ весь рендер делаем в Python и Go-путь не трогаем. **Не** полагаемся на то, что `RenderScene` защитит per-op.

> **Капасити — не из пиксельного клампа (красная команда [videopower], принято).** «400×200 ⇒ ≤16 карточек» путает **символьную канву** с **семантической ёмкостью**. Реальный лимит — **когнитивный**, не терминальные ячейки. Кламп используем как технический предохранитель, не как «закон раскладки».

**HTML-рендер.** `view_html.compile_html` `<details>`-каскад в CSS-grid (`grid-template-columns:repeat(cols,1fr)`) — карточки ложатся настоящей 2D-плиткой, клик = локальный `L0→L2`. Coarse-вид = свёрнутые заголовки-меню (раскрытие, которое у `view_html` УЖЕ есть), fine-вид = всё раскрыто.

> **Оси нужно ЗАРАБОТАТЬ или демотировать (красная команда [videopower], принято).** `sha256`-сортировка детерминирована, но **семантически произвольна**: она не кладёт смежные подтемы рядом по X и не «общее-над-частным» по Y. У `grid.go` ячейки несут реальную 2D-локальность цвета (sky над ground, потому что так положила МОДЕЛЬ); у нас положение — хеш, и соседскому blur не на чём работать. **Поэтому:** Y берём из **графовой глубины** (BFS-расстояние от seed по `[[links]]` — это уже градиент абстракции в `view.slice_ids`), X — из FTS-кластера / co-citation смежности; `sha256` оставляем **только как tie-break**. Без этого артефакт честно зовётся **«меню карточек», а не «2D-сцена»**, и claim снижается.

## 5. Многоагентная MMORPG / сетка-камер (raymeet → текст: люди + агенты)

`tools/text_mux.py` — калька raymeet-звезды на файл-нативный канон.
- **Хаб = единственный автор сетки-сида** (как `host` в `SHARED_WORLD:99-101`) — это же закрывает трещину детерминизма #2.
- Участники однородны на проводе: `kind:human|agent` + endpoint (`thread_runner --llama` ИЛИ offline-синтетик).
- Каждый = своя «камера наблюдения» = свой `view`-срез на ОДНУ сетку со своим фокус-курсором.
- `focus_pose` (текст-аналог `Pose` 44Б): `mode∈{idle,denoising,typing,bidding}` → presence-глиф в углу плитки + focus-cone «кто на меня смотрит».
- **Агент↔агент↔человек:** общение = append шага в `threads/<card-id>.md` через `thread_runner.run`; агент B читает шаг A через `assemble_context` (FTS-ретрив), дописывает свой; ребро `[[link]]` = канал диалога.
- **Под-вопрос (пустой слот)** → Contract-Net (`pkg/acl` cfp→propose→accept дешевейшему) → победитель открывает соседнюю ячейку («моб под квест») — строго с лимитом spawn/тик и TTL пустых карточек.

> **Честность про «видеосвязь» (красная команда [videopower], принято).** raymeet-камеры рендерят ОДИН мир из РАЗНЫХ поз **каждый тик** — N реально параллельных живых фидов; видео-мощь = **ЧАСЫ**, толкающие кадры независимо от изменений (`Pose` = 44Б/тик). Наш текст **событийный, не тактовый**: без тика «поток» — это presence-список, обновляемый на событиях, т.е. **chat-роутер, а не видео-фид**. `focus_pose mode{...}` = **typing-indicator** (фича из будущей работы `TEXT_CHAT.md`), не фид. **Фикс:** заменяем FPS-метафору на **event-stream / CRDT-op-log** (это и есть `crdt_merge` + `queues/outbox`); presence = last-event-timestamp, не тик. Свойство «много живых участников» остаётся — без фейкового clock.

> **Безопасность роя (красная команда [multiagent_sec], принято — обязательные фиксы):**
> - **Аутентификация авторства.** §14 «validator=trust boundary» взят, а §10 **подпись — нет**: `uid` в `step_msg`/`focus_pose`/`card_seed` **самозаявлен**. Любой `kind:agent` может подделать сообщение от чужого `uid`. **Фикс:** подписывать `(actor_id, endpoint, allowed_kinds)` HMAC (зеркало `pkg/sign`); неподписанный автор = недоверенный.
> - **Contract-Net без интегритета ставок** награждает поддерево низшему биддеру → злоумышленник бидит 0 и «открывает соседнюю ячейку» = контролирует расширение канвы. **Фикс:** подписанные ставки + per-actor spawn-бюджет + co-sign хаба/кворума на открытие ячейки.
> - **Захваченный хаб = оракул корпуса.** Хаб выбирает, какие карточки существуют, их `[[links]]` и корпус, из которого все реконструируют тело. Кворум голосует только по телам **показанных** карточек, не видит подавленных. **Фикс:** Merkle-root корпуса в `card_seed` (~32Б) — узел ДЕТЕКТИТ расхождение корпуса; на mismatch — отказ от локального `elaborate` + метка `corpus-divergent` на карточке (тихое отравление → видимый отказ).

## 6. Кодек/провод «смысл не пиксели» + CRDT-мёрж карточек

По проводу — **ТРИ мелких сообщения; тело карточки НИКОГДА не идёт** (пересобирается локально через `view.load_canon/assemble`):

| Сообщение | Размер | Аналог raymeet | Семантика |
|---|---|---|---|
| `card_seed` | ~120Б `{id,gist,links,type}` + Merkle-root ~32Б | `Region`~100Б | broadcast 1× хабом, ack-heal |
| `focus_pose` | ~40Б | `Pose` 44Б | loss-tolerant presence |
| `step_msg` | append в тред | `ChatSync` | uid+dedup, hub-rebroadcast |

Это буквальный перенос тезиса «a walker received a trickle of descriptions and reconstructed every pixel locally» (`SHARED_WORLD:84`).

**Условие корректности (честный лимит).** Как raymeet (host = single author + idempotent apply), так и у нас: корпус+индекс должны совпадать на узлах — **теперь это ВЕРИФИЦИРУЕМО** Merkle-root, а не предполагается. На mismatch шлём не полный diff (раздувает wire сверх 100Б-идеала), а отказываемся реконструировать и помечаем карточку.

### Правка `crdt_merge.py` — чинит ПОДТВЕРЖДЁННЫЕ баги (MVP step 0, под тестом):

1. **Воскрешение через удаление.** `_union_lists` (`crdt_merge.py:94-99`) — **pure add-wins без tombstone** (`seen,out=set(),[]` → dedup-union): конкурентное удаление карточки воскрешает её, ломая со-правку общей канвы. **Фикс — OR-Set с конкретными тегами:** каждый add несёт уникальный тег `sha256(actor_id+card_id+lamport)`; remove передаёт множество **наблюдённых тегов**, которые гасит; add с невиданным тегом выживает (add-wins **по тегу**, но полностью наблюдённый remove — durable). Без явного набора тегов «OR-Set» не имплементируется (gate: тест «delete на одной стороне переживает конкурентный edit на другой»).

2. **Эвикция участника невозможна (дыра безопасности).** `participants` ∈ `LIST_FIELDS` (`crdt_merge.py:25`) мёржится тем же add-wins → однажды добавленный враждебный `kind:agent` endpoint **не удаляется никаким мёржем**. **Фикс:** вынести `participants` в **отдельный OR-Set с tombstone + правилом авторитета удаления** (tombstone участника эмитит только хаб/кворум).

3. **`_merge_scalar` не коммутативен.** `return ov, True` (`crdt_merge.py:110`) = «ours-wins» **позиционно** → `A⊕B ≠ B⊕A` на `gist`/`type` (зависит от порядка аргументов git/caller). Ломает order-independent apply, на котором держится «смысл не пиксели». **Фикс:** детерминированный tie-break `max(ov,tv,key=(actor_priority, sha256))` + `conflict:true` (оба значения видны); `level=max` — единственный естественно-монотонный скаляр.

4. **Каузальность:** version-vector `vv` (повтор op = no-op), тело через `seq_merge` diff3 (маркеры только на пересечении строк). `git_reconcile.py` merge-driver — тот же на `cards/**/*.md`.

> **GC tombstone (красная команда, принято).** GC тега — только после стабильного каузального watermark (все живые акторы ack-нули через `vv`); рост `vv` ограничен ретайром акторов за TTL в компактный epoch-счётчик (иначе `vv` раздувается с числом акторов, а tombstone-GC «не сойдётся в долгоживущем рое» — собственный риск дизайна).

## 7. Что взять к нам / что посоветовать TVCP

**Взять у TVCP:**
- (а) **«validator = trust boundary»** (`CheckResponse`, §14): шаг треда применяется только после **детерминированной проверки СХЕМЫ** (YAML front-matter валиден, `[[links]]` резолвятся, размер ограничен) ДО append.
- (б) **clamp-дисциплина** (`clampi`, `Color()` def-fallback): кривой токен агента дефолтится с пометкой, а не роняет мёрж.
- (в) **`sketch→ToScene` лестница** как наш двухуровневый «меню→детали»: слабый агент эмитит грубый sketch, сильный — полный scene.
- (г) **дельта-спек узла** (raymeet `Region`/`SceneDelta`): единица обмена — структурный патч узла, а не весь `.md`-файл (снимает тяжесть мёржа больших топиков).
- (д) **`speccoverage`-паттерн** для канона: тест, сверяющий front-matter `tasks/T-*.md` с реальностью (статусы, не битые `[[links]]`, объявленные инструменты существуют) + строка «authority = код/индекс» в каждом ключевом `.md`.

**Советовать TVCP (фальсифицируемые баги в их коде):**
1. `scene.Apply` (`scene.go:85,126`) НЕ санирует per-op `X/Y/W/H/R` — отрицательный/гигантский `W` = паника или тяжёлый цикл (единственная брешь в образцовой clamp-дисциплине; критично для много-участникового сценария).
2. Гонка на `.pal`: `*Grid`-пейлоады пишут `g.pal=pal` в общий указатель — два параллельных рендера = data race.
3. `Grid.rect:43` «extend last color» молча придумывает данные.
4. Нет golden-тестов на `DiffuseFrames(seed=1)` — детерминизм заявлен в докстринге, ничем не зафиксирован.
5. Поднять §10 verify с SHOULD до MUST; подписывать сам Response мозга, не только запись реестра; rate-limit на `/v1/decide`.

## 8. MVP-порядок постройки (первый артефакт — `text_scene.py`)

**Step 0 — `crdt_merge.py` tombstone-фикс (gated by test).** OR-Set с тегами + tombstone; тест «delete переживает конкурентный edit». **Без этого «много-участниковая» половина дизайна некорректна** — поэтому это шаг 0, а не §6-nicety.

**Step 1 — однопользовательский `text_scene.py`:**
- `seed()` (FTS ∪ slice_ids, **BFS-depth tagging**, сортировка `(depth, sha256)`) →
- `render(grid, L)` (`card_to_ops` с **per-op clamp**) →
- `diffuse_steps()` coarse→fine (L0→L1→L2, `_gist` существует).
- Рендеры: ANSI-таблица (`--steps` = анимация раскрытия), HTML (CSS-grid `<details>`).
- **Golden-тесты:** (i) последовательность карточек для фикс-корпуса; (ii) **раскладка-детерминизм** (тот же корпус+query → та же сетка) — это и есть реально-транспортируемое детерминированное ядро из §6, а не denoising.

**Step 2 — `text_mux.py`:** `queues/outbox/` как файловый офлайн-провод (`card_seed`/`focus_pose`/`step_msg` JSON-строки, без сети) → много-агентная канва с presence (last-event-ts) и подписанным Contract-Net.

**Step 3 (опционально, high-stakes):** строгий L-движок — ТОЛЬКО если определён конкретным кодом с тестом и под именем «top-k общих термов», не «Blend».

**Конфликт-контур.** Данные → CRDT-слой детерминированно; семантический спор (оба переписали тело) → `conflict:true`, оба тела видны, выносится в **видимый кворум** `oracle_quorum/consensus_by_meaning` (≥2 мозга с дивергенцией-пометкой на карточке). Граница **РАСКЛАДКА/РАДИУС/ПОРЯДОК детерминированы** (depth+sha256, чистые L-функции) **↔ СЕМАНТИКА ТЕЛА = оракул** держится ВИДИМОЙ на всех уровнях — это тестируемое ядро.

## 10. Вердикт

**Что держится (front-load, verbatim-истинно против кода TVCP):**
1. **Кодек «смысл не пиксели»** — `card_seed`~120Б == `Region`, тело пересобирается локально (буквально `SHARED_WORLD:84`).
2. **host-single-author + OR-Set-с-tombstone общая канва** — фикс `_union_lists` (`crdt_merge.py:94-99`) это **реальный баг-фикс** (конкурентное удаление сейчас воскрешает — подтверждено в коде).
3. **per-participant view-slice = камера** — структурно реально.
4. **Трёхстадийное раскрытие L0/L1/L2** на существующих `_gist`/`assemble`/`<details>` — рабочее и красиво деградирует.

**Что демотировано в «опциональный флавор, не несущее»:** всё diffusion/FPS/blur. «Полу-диффузия» честно = **детерминированное прогрессивное раскрытие от seed**, не denoising; «семантический blur» = top-k общих термов или ничего.

**Тестируемое ядро:** граница **РАСКЛАДКА/ПОРЯДОК/РАДИУС детерминированы** (depth+sha256, чистые L-функции, golden-тест) **↔ СЕМАНТИКА ТЕЛА = оракул, видимый на всех уровнях**. Оракул-проблема не «решена», а **сужена до формы детерминированным gate'ом** (как `CheckResponse`↔`ConformanceBattery` сужает её у TVCP) и **смягчена видимым кворумом** для семантики — не молчаливым LWW одного захватываемого судьи.
