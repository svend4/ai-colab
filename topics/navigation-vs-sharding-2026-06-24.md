# 0. Визитка

> **Резолюция спора** (lane B → lane A): divergence «нужен ли шардинг tasks/» закрыт мнением Stefan,
> опирающимся на ТЕХНИЧЕСКУЮ реальность, а не виртуальную идею. Решение: **шардинг не делать**;
> человеческую навигацию решить **метаданными** (визитки файлов + папка-индексы), машинную — оставить
> плоской + дать машиночитаемые индексы. Структура от общего к частному.

## 0.1. Card (5 сек)
- **Было (предложение C-04):** разрезать `tasks/` (222 файла) на под-папки по диапазонам ID.
- **Стало (это решение):** НЕ резать. Плоско + два канала навигации по метаданным.
- **Почему:** машине плоско безразлично (grep/glob не различают); шардинг ломает всех читателей ради удобства, которое решается дешевле — метаданными.

# 1. Решение

1. **Шардинг `tasks/` (и других плоских папок) — ОТКЛОНЁН.** Файлы остаются плоскими (`tasks/T-NNN.md`).
2. **Человеческая навигация** решается **метаданными**, не структурой папок:
   - **визитка** (краткое описание) в ЗАГОЛОВКЕ каждого файла — уже есть (`header.py`);
   - **папка-индекс** — отдельный документ В КАЖДОЙ папке: что в этой папке, метаданные файлов, что в подпапках, навигация.
3. **Машинная навигация** — плоская структура + машиночитаемые **индексы** (`index.json`, индекс команд, индекс визиток) в отдельных файлах/формате.
4. Порог `dir_health` >200 для `tasks/` переосмысляется: не «FAIL → шардить», а «нужен папка-индекс» (см. §5).

# 2. Обоснование — техническая реальность, не виртуальная идея

- **Машине плоско всё равно.** `glob`/`grep`/чтение 222 файлов из одной папки — норма; файловая система и инструменты не деградируют на сотнях файлов. Узкое место навигации — **когнитивное (человек)**, а не машинное.
- **Цена шардинга непропорциональна.** Чтобы разрезать, надо переписать ВСЕХ читателей (`generate/validate/pipeline/next_id/reconcile/dispatch/metrics` — все глобят `tasks/*.md`) на рекурсию, переместить 222 файла, рискнуть ссылками и конфликтом с параллельным агентом. Большой риск ради того, что машине безразлично.
- **Проблема, которую шардинг решал бы (человек не видит структуру), решается дешевле** — метаданными поверх плоской структуры, **ничего не перемещая и не ломая**.
- Это и есть консенсус **C-09**: «машинный и человеческий оптимум РАЗНЫЕ → обслуживай оба РАЗНЫМИ механизмами». Шардинг пытался одной палкой (структура папок) решить обе задачи — неверно.

# 3. Два канала навигации (разные для машины и человека)

```
        ПЛОСКАЯ структура (tasks/T-001.md … T-222.md)  ← физически не меняется
        ├─────────────────────────────┬──────────────────────────────┤
   КАНАЛ МАШИНЫ                                       КАНАЛ ЧЕЛОВЕКА
   index.json (канон-навигация)                      tasks/INDEX.md (папка-индекс)
   индекс команд (command_index.py)                  README больших папок
   индекс визиток (header.py board, машиночит.)      board.md / by-status / by-owner
   → grep/glob/load по плоскому                       → читаемое оглавление папки
```

- **Машина**: плоско + индексы. Уже есть `index.json` (канон), `command_index.py` (команды), `header.py board` (визитки). Можно добавить машиночитаемый JSON-индекс папки.
- **Человек**: визитка в шапке файла + **папка-индекс** (что лежит в папке + подпапки + навигация) + существующие виды (`board.md`).

# 4. Дизайн — три уровня метаданных (общее→частное)

1. **Файл** → визитка в шапке (`header.py`): id/type/title/status/**gist** (что это). Уже 213/214 покрытие.
2. **Папка** → `INDEX.md` (или `_index.md`) в каждой папке: автособираемая из визиток таблица
   `id | type | status | gist` всех файлов + ссылки на подпапки + краткое «что здесь». Машина и человек
   читают один файл вместо листинга 222. Генерируется (`folder_index.py`), как `index.json`.
3. **Проект** → центральные индексы (`index.json`, command_index, концепт-карта).

`folder_index.py` собирает уровень 2 из уровня 1 (визиток `header.py`) — ничего не перемещая.

# 5. Что меняется в прежних документах

- **C-04 (шардинг)** в `razbor-consensus`/доске — **снимается с lane A**; заменяется на C-04′
  «навигация-через-метаданные» (это решение). Divergence DIV-04 («потолок файловой модели») —
  **РАЗРЕШЁН** (второй голос дан Stefan).
- **`dir_health.py`** — порог files>200: переосмыслить как «нужен папка-индекс», не «нужен шардинг»
  (FAIL → WARN, если в папке есть актуальный `INDEX.md`). См. §6.
- **`architecture-fundamentals` §3.2.1-2** (шардинг по ID) — пометить «опционально/отклонено для текущего
  масштаба; навигация решается метаданными (это решение)».

# 6. Сборка (что построить)

1. **`tools/folder_index.py`** — генератор/чекер папка-индекса (`INDEX.md`) из визиток `header.py`:
   `--write <dir>` собирает, `--check` верифицирует актуальность (как `generate --check`). [строится сейчас]
2. **`dir_health.py`** — смягчить files-per-dir: при наличии `INDEX.md` → WARN вместо FAIL.
3. Прогнать `folder_index --write tasks/` → плоские 222 становятся навигируемыми одним оглавлением.

**Итог.** Не платим за шардинг (машине он не нужен) — решаем реальную (человеческую) проблему навигации
дешёвыми метаданными поверх неизменной плоской структуры. Решение опирается на техническую реальность.
