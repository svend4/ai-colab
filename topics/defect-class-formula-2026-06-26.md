# Систематическая формула решения дефектов многоагентной работы

> Запрос Stefan: вывести из commit_queue-инстанса ОБЩУЮ «информационную формулу» решения таких проблем;
> по истории найти, какие жалобы были, как решены, перепроверить эффективность и где ещё есть подобное
> (технич./семантич.). Метод: моя независимая формула (sealed ДО роя) + рой-аудит 98 проблем с перепроверкой
> на месте + адверсариальная критика. Все три сошлись на ядре; критика добавила 5 уточнений — они ниже.

# 1. Класс дефектов «конкурентного вклада» — 6 симптомов
Когда ≥2 актора (или актор + гейт/оракул/дериват) трогают общее состояние:
- **(a) немой отказ** — проигравшему не сказано кто/насколько/позиция.
- **(b) потеря работы** — вклад исчезает (коллизия, смерть актора, перезапись).
- **(c) несправедливая контенция** — слепой retry, голодание, давка.
- **(d) молчаливое слияние** — конкурентные правки тихо перезаписываются; minority/конфликт теряется.
- **(e) захватываемая авторитетность** — решает один судья/оракул/host/узкое место.
- **(f) тихий дрейф деривата** *(добавлено red-team)* — производное представление (метрика/индекс/портал/board)
  МОЛЧА расходится с источником при ре-нейминге/смене схемы; **немой ноль выглядит как валидный ответ**.
  Проявляется БЕЗ коллизии (один актор). Живой пример: `metrics.py:77 load("темы")` → `topics total=0` при ~78 файлах.

# 2. Диагностика C.1 + ПОРОГ ОТСЕЧКИ
Чек-лист (6 вопросов-детекторов): при коллизии видно кто/насколько/позиция? (a) · переживает ли работа/minority
смерть участника? (b) · FIFO или слепой retry/голодание? (c) · прячется ли конфликт при merge? (d) · один ли
судья/узкое место решает истину? (e) · **есть ли дериват, который сломается МОЛЧА при ре-нейминге источника? (f)**

**Порог отсечки** *(уточнение red-team — иначе бюрократия):* «≥1 ДА» гипер-инклюзивно (почти любая операция даёт
ДА). Полный 7-шаговый рецепт применять ТОЛЬКО если `severity(потери) × frequency(коллизии)` выше порога; иначе
**деградировать до шага 1** (одно board-сообщение) без durability-очереди-гейта. Не ставить `commit_queue` там,
где хватает `O_EXCL`-флага.

# 3. Рецепт (7 шагов + инварианты + 3 контр-инварианта)
1. **ВИДИМЫМ/ИЗМЕРИМЫМ** — board: кто держит/как давно/позиция N из M/возраст блокировки. *Инв: немой отказ запрещён.*
2. **DURABILITY-ПЕРВЫМ** — снять состояние ДО борьбы за ресурс. *Инв: потеря работы запрещена; архивация ≠ удаление.*
3. **СЕРИАЛИЗАЦИЯ/СПРАВЕДЛИВОСТЬ** — ресурс берёт только голова очереди. *Инв: нет thundering-herd/голодания.*
4. **ГЕЙТ** — терминальный переход через проверку. *Инв: галочку ставит гейт/кворум, не автор соло.*
5. **СЛИЯНИЕ С ВИДИМЫМИ ФЛАГАМИ** — `☐queued ⟳active ✓green ★accepted ~variant !conflict ✗failed 🌫fog`. *Инв: конфликт/крестик не прячутся.*
6. **RESOLVE: конфликт → человеку** — `contested`, эскалация. *Инв: спорное не утверждается соло.*
7. **RESOLVE: minority НЕ терять** — вынести в divergence, не стереть. *Инв: запрет удаления вынесенных мнений.*

**Контр-инварианты (добавлены red-team — без них формула САМА порождает дефекты):**
- **C-I РЕКУРСИЯ ГЕЙТА.** Шаги 4 и 6 сами суть симптом (e): гейт/кворум/человек — захватываемая авторитетность.
  Формула лечит (e) на уровне *единицы*, перенося его на *механизм проверки*. → **К каждому гейту/кворуму/человеку
  ПОВТОРНО применить C.1 по всем симптомам** (иначе (e) поднят этажом выше, где его перестают искать).
- **C-II FOLD-NOT-DELETE.** Шаги 2 и 7 вместе = монотонный grow-only стор без сборки → деградация (тот же класс,
  что `metrics.py` давится на 78 файлах). → Удаление по-прежнему запрещено, но **развёрнутое хранение — нет**:
  каждый grow-only стор обязан схлопывать «N вариантов → 1 summary + N указателей» по порогу размера.
- **C-III МЕТА-ТЕСТ ДЕТЕКТОРА.** Флаг (`!conflict`, `grounded:True`) доказывает, что *детектор сработал*, а не что
  проблема реально видна. Детектор бывает со-дефектен (зелёный тест поверх сломанного кода). → Критичный детектор
  проверять **мутацией**: намеренно сломать источник, убедиться, что тест/флаг КРАСНЕЕТ; не краснеет → `!co-defective`.

# 4. Переносимость (3 инстанса — структура решения инвариантна)
| Шаг | commit_queue (D-031, технич.) | oracle_quorum/text_mux (D-030, семантич.) | workflow_recover (оркестрация) |
|---|---|---|---|
| 1 видимо | board (.git-lock возраст, держатель) | lanes-view (видимый консенсус/конфликт) | started/completed/pending |
| 2 durable | `enqueue --save` (предсохранение patch) | grow-only cell-store / seal | journal.jsonl (каждый агент durable) |
| 3 fair | лок берёт только голова | independence-weight (не громкость) | — |
| 4 gate | done/fail lifecycle | quorum verdict | — |
| 5 флаги | ☐⟳★✗ | !conflict / ~variant | ✓/в-полёте |
| 6 человек | merge-gate owner | contested → человек | — |
| 7 minority | recover-патч переживает проигрыш | no-silent-delete / divergence.md | recover даже из мёртвого workflow |

Различается лишь *единица* (commit / cell / agent-result) и *ресурс контенции* (index.lock / право на истину /
оркестрация). Структура — одна. Это и есть систематическая формула.

# 5. Где формула САМА ломается (честно, из red-team)
- **Самореференция (e):** см. C-I — без рекурсии гейта симптом не устранён, а спрятан выше.
- **Рост (b)+(7) → новый дефект:** см. C-II — спасая от потери, гарантирует смерть от накопления.
- **Вера во флаг (5):** см. C-III — «флаг проставлен» ≠ «проблема видна», если детектор сам не проверен.
- **Бюрократия:** без порога (§2) рецепт навешивается на тривиальное.

# 6. Аудит истории: каталог + открытые проблемы (полный — `SYNTHESIS.md`; здесь сводка + правки red-team)
Перепроверено 12 значимых решений на месте: **10 full, 2 partial, 0 none** — большинство жалоб (Q-001..Q-022,
D-001..D-031) закрыто и не рецидивирует. Правки вердиктов от red-team (оптимизм понижен):
- **Q-010 → не «partial», а СКРЫТО-СЛЕПОЙ:** `metrics topics=0` И `test_metrics.py` со-дефектен (фикстура тоже
  пишет в `темы/`) → тест НЕ покраснеет от бага даже после «починки» только metrics. Симптом (f)+(d)+co-defective.
- **D-031 → «full на атомарность, UNTESTED на fairness+recovery»:** `race_test` доказывает только single-winner
  атомарность index.lock, не справедливость (голодание хвоста) и не recover после смерти держателя.
- **Q-007 → partial:** `exit=124` = timeout-kill teardown; «pass=19» куплено ценой зависания.
- **Q-005 → фактически RED:** `test_instruction_trace.py` падает; `assurance.py` рапортует `grounded:True` поверх
  красного теста (флаг врёт — инстанс C-III).

**Открытые проблемы класса (ранжировано, технич. И семантич.):**
1. **Silent derivation drift (f) — ВЕСЬ класс, не одна `темы`.** `metrics.py:77`(=0 подтв.), `promote.py:57`,
   `instructions.py:435`, возможно `generate.py`/`portal.py`/`edges.py`. → **единый реестр `CANON_DIRS`**,
   деривативы импортируют его (не литералы) + гейт «пустой результат от несуществующего пути → ERROR, не 0».
2. **Co-defective test (e на уровне тестов).** `test_metrics` зелёный поверх сломанного; `assurance grounded:True`
   поверх красного. → мутационная проверка критичных детекторов (C-III).
3. **Unbounded grow-only (C-II).** cell-store / архив предсохранений / divergence растут без свёртки. → fold-not-delete.
4. **worktree/merge_gate не вкл. по умолчанию (c)+(b)+(e).** STALE-индекс связывает флот; merge_gate сам захватываем.
   → merge-owner tiers + ротация интегратора (C-I).
5. **Оракул семантики (e)+(d) — открытый фронтир (D-030).** Судьи одной модели; «неопровергнут»=«никто не пробовал».
6. **Анти-auto-accept только для synthesis-report (e).** Прямое `D-*.md status:accepted` мимо синтеза не ловится.
   → гейт на любой `decisions/D-*.md accepted` без следа человека → ERROR.
7. **T-148 enforcement (a).** cohort guard печатает, не блокирует → WARN→блок по триггерам.
8. **Нет авто-теста heartbeat (a).** Слой видимости без регрессии.

# 7. Вердикт
Один 6-симптомный класс, один диагностический чек-лист с порогом, один 7-шаговый рецепт с 3 контр-инвариантами
(рекурсия гейта · fold-not-delete · мета-тест детектора) — закрывает все симптомы на техническом, семантическом
и оркестрационном плече. Метод обращён на себя: независимая версия + рой + red-team сошлись на ядре, а
адверсарий нашёл, что формула без контр-инвариантов САМА порождает (e)-вверх, рост и веру-во-флаг — и это
названо явно. Самый недо-применённый шаг — durability-первым; самый коварный новый симптом — (f) тихий дрейф
деривата (живой баг подтверждён). Главный урок прежний: галочку ставит гейт, крестик не прячется, minority не
теряется — но и гейт, и стор, и детектор сами подлежат той же проверке.
