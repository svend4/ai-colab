# Предложение (proposal): Механизм safe-auto-apply

> **Статус: proposed** (требует ратификации через Котёл D-018).

В рамках задачи **T-206 (P28 FINDER-фронтира)** мы внедряем механизм авто-исправления (`safe-auto-apply`), чтобы система могла чинить тривиальные дрейфы и выполнять рутинные операции без вовлечения человека. 

Авто-мутация несёт риски, поэтому вводится строгий гейт и реестр разрешённых правил, применяемых только для **доказанно-обратимых (derived/idempotent)** операций. PRIMARY данные (код, тексты обсуждений, governance) не могут быть изменены автоматически без ревью.

## Реестр `SAFE_AUTO` (Кандидаты)

1. **Индексные обновления (derived data)**:
   - `python tools/generate.py` — регенерация `TASKS.md`, `STATUS.md`, `board.md`, `index.json`. Восстанавливает индексы по front-matter.
2. **Синхронизация состояний (reconcile)**:
   - `python tools/reconcile_state.py fix --apply` — синхронизация derived-данных/snapshot.
3. **Очистка протухших записей (archive)**:
   - `python tools/stream.py archive --apply` — архивирует stale streams (P16). Это полностью обратимая и идемпотентная административная операция.

## Механизм и Гейт в `tools/blocks.py`

В `tools/blocks.py` добавляется поддержка ключа `--auto-safe` для команды `improve`.
Его логика работы:

1. Запускается аудит/сбор проблем (`adoption.py`, `friction.py`, `drift_check.py` и т.д.).
2. При наличии "advisory_flags" (замечаний) или падений в "gate", скрипт проверяет наличие ключа `--auto-safe`.
3. Если флаг есть, то запускается применение **ТОЛЬКО** тех команд, которые явно прописаны в реестре `SAFE_AUTO_RULES` внутри `blocks.py`.
4. Скрипт выводит лог авто-исправлений.
5. Любые другие проблемы, требующие смысловых решений, оставляются человеку (или роутеру) в виде уведомлений/proposal.

## Критерий принятия (Acceptance)
Котёл (D-018) должен ратифицировать этот подход. Если реестр утверждён, `blocks.py` может штатно применять эти команды при вызове с `--auto-safe`.
