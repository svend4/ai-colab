# Очередь коммитов → единый синтез (технический + семантический)

> Повод: вживую поймана коллизия `.git/index.lock` («File exists») при параллельных коммитах двух агентов.
> Голый лок — НЕМОЙ отказ: не видно кто держит, насколько, и работа коммитера может потеряться. Задача (по
> запросу): сделать коллизию ИНФОРМАТИВНОЙ, добавить ПРЕДСОХРАНЕНИЕ и обобщить метод на СЛИЯНИЕ — не только
> техническое (файлы/git), но и СЕМАНТИЧЕСКОЕ (утверждения/ячейки): какие флаги (галочки/крестики) и как синтез.

# 1. Что было не так (немой отказ)
`git commit` параллельных агентов дерётся за `.git/index.lock`. При коллизии видно лишь:
```
fatal: Unable to create '.../.git/index.lock': File exists.
```
Чего НЕ видно и что нужно: **кто** держит, **как давно**, **сколько осталось**, **моя позиция в очереди**, и
куда делась **моя несохранённая работа**. `commit_lock.py` (advisory-лок) сериализует, но на busy говорит лишь
«занят агентом X» — без «насколько» и без очереди. Корень моей коллизии: фоновые `git commit` шли **в обход**
advisory-лока. Вывод: нужен слой, который (а) делает занятость измеримой, (б) не теряет работу, (в) упорядочивает.

# 2. Решение (технический слой): `tools/commit_queue.py` НАД `commit_lock`
Четыре свойства (реализованы, под тестом `test_commit_queue.py`):

1. **Богатая обратная связь** — `board`:
   ```
   .git/index.lock: свободен | ЗАНЯТ 14s (raw git / зависший)     ← та самая немая коллизия, теперь с возрастом
   commit-lock: держит 'codex' — взят 14s назад, осталось 106s по TTL (свежий)
   очередь: 2 живых тикета
     1. ☐ <id> 'alice' — 14s назад · textscene · 💾предсохранено   ← позиция, возраст, намерение, предсохранение
     2. ☐ <id> 'bob'   — 3s назад · fix validate
   ```
2. **Очередь FIFO с позициями** — лок берёт ТОЛЬКО голова (`turn` отдаёт `ready=True` лишь голове). Справедливо:
   нет thundering-herd и голодания (раньше все retry-сleep'или вслепую).
3. **Темпоральное предсохранение** — `enqueue --save` снимает `git diff --cached` в `queues/commit-queue/<id>.patch`
   с пометкой `status: queued`. Работа **durable**: агент умер / контекст кончился / лок не отпущен — `recover`
   покажет незавершённые тикеты с сохранённой работой, патч применим заново. Ничего не теряется молча.
4. **Жизненный цикл тикета** = флаги: ☐ queued → ⟳ active → ★ done | ✗ failed (`fail` сохраняет patch для recover).

Протокол агента (заменяет голый `git commit`):
```
enqueue <agent> --save           # встал в очередь, staged предсохранён, вижу позицию
loop: turn <agent> --ticket <id> # ready? голова берёт commit-lock; иначе вижу «позиция N из M, впереди …»
  ready → generate && git add <свои файлы> && git commit && done <agent> --ticket <id>
  red   → fail <agent> --ticket <id> --reason …   # лок отпущен, работа сохранена
```

# 3. Ключевое обобщение: коммит-тикет и СЕМАНТИЧЕСКАЯ ячейка — ОДНО
Тикет очереди (technical) и ячейка `text_cell.v1` из [[textscene-unified-spec-2026-06-26]] (semantic) — это два
проявления одной сущности **`contribution.v1`**, проходящей ОДИН конвейер синтеза. Разница ТОЛЬКО в операторе
слияния: для файлов — CRDT/3-way (`crdt_merge`/`seq_merge`), для утверждений — консенсус-по-смыслу (`text_mux`).
Всё остальное общее: durability (предсохранение/draft), справедливость (очередь/ripeness), видимые флаги,
видимый конфликт (никогда не молча).

```
contribution.v1 = { id, author, kind, body|diff, status(флаг), links, lamport }
   technical:  kind=commit  body=staged-diff     merge = selective-add + crdt/seq 3-way
   semantic:   kind=claim   body=утверждение     merge = consensus-by-meaning (≥2 владельца)
```

# 4. Единый словарь ФЛАГОВ (галочки/крестики) — что ставить
Один словарь для технического и семантического слоя (тикеты commit_queue ≡ статусы ячеек text_mux):

| Флаг | Имя | Технически (commit/merge) | Семантически (ячейка/утверждение) |
|---|---|---|---|
| ☐ | queued / draft | в очереди, предсохранён, ждёт | черновик, ещё не вынесен |
| ⟳ | active | синтезируется/коммитится сейчас (голова) | разворачивается/обсуждается |
| ✓ | green / confirmed | гейт зелёный (validate/generate/permissions) | ≥2 РАЗНЫХ владельца → консенсус-кандидат |
| ★ | accepted / done | влито в mainline (commit) | принято в canon (human/integrator) |
| ~ | variant | альтернативный коммит/ветка-вариант | minority-вариант СОХРАНЁН (не отброшен) |
| ! | conflict | строчный/полевой конфликт (маркеры seq_merge) | расхождение тел / `contradicts` — к человеку |
| ✗ | failed / rejected | гейт red / отвергнут (patch сохранён) | опровергнуто красной командой/кворумом |
| 🌫 | fog | непроверено / непрочитано (fog-of-war) | непроверенное утверждение |

Правило: **галочку (✓/★) ставит только ГЕЙТ или КВОРУМ, не автор сам себе** (зеркало tvcp `validator=trust
boundary`); **крестик (✗) и конфликт (!) НИКОГДА не прячутся** красивым мёржем (инвариант «конфликт виден»).

# 5. Процедура СИНТЕЗА (общая, 6 шагов) — для commit и для смысла
```
① ENQUEUE + TEMPORAL-SAVE   durability ПЕРВЫМ: вклад сохранён (queued patch / draft cell) — потеря исключена
② SERIALIZE (FIFO/ripeness) только голова идёт дальше (technical: commit-lock; semantic: ripeness-gate)
③ GATE                      technical: merge_gate (validate→generate --check→permissions) → ✓/✗
                            semantic:  oracle/red-team (кворум ≥2, дивергенция видна)        → ✓/✗
④ MERGE                     technical: selective-add + crdt_merge(поле, OR-Set+tombstone R7) + seq_merge(строка, diff3)
                            semantic:  text_mux.consensus (≥2 одинаково → ✓ ; различны → ~ варианты ; contradict → !)
⑤ RESOLVE FLAGS             ✓+consensus → ★ accept ; ! → эскалация ЧЕЛОВЕКУ (10-сек критерий №10) ;
                            ~ → side-lane (minority СОХРАНЁН) ; ✗ → назад в очередь или drop (patch в recover)
⑥ RELEASE + DEQUEUE         отпустить лок/ход → следующая голова
```
Инварианты конвейера: (1) durability до синтеза; (2) галочку ставит гейт/кворум; (3) конфликт/крестик видимы;
(4) minority не теряется; (5) детерминизм там, где можно (FIFO, CRDT-раскладка), оракул — только на смысл и ВИДИМО.

# 7. Почему это правильно (а не бюрократия)
- Решает РЕАЛЬНУЮ боль (поймана вживую), а не гипотезу.
- Durability-первым = главный анти-риск многоагентности (потеря работы при коллизии/смерти агента).
- Один словарь флагов и один конвейер для файлов И смысла = меньше сущностей, переиспользование (crdt/text_mux уже есть).
- Не прячет конфликт — прямое следствие урока оракула: расхождение делаем ВИДИМЫМ, принятие — гейту/человеку.
