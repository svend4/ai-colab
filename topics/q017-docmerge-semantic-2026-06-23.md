## Q-017: семантический гибрид слияния документации агентов

**Концептуальный разрыв.** `tools/doc_consensus.py` сравнивает пункты только по пересечению токенов: `_norm_tokens` → множество стеммированных слов (46-68), `_jaccard` (138-141), жадная кластеризация при Jaccard>=0.4 против замороженного представителя (144-160). `_stem` (46-60) складывает лишь словоформы одного слова, не синонимы/парафраз. Итог: два агента, утверждающие одну идею разными словами, дают Jaccard~0 и метятся как `divergence`. Эмпирика на двух реальных policy-доках: 307 пунктов, **0 консенсус-кластеров** при thr 0.4 и 0.3, тогда как ручной синтез и D-023 фиксируют >=7 реальных согласий. Тест проходит лишь потому, что фикстуры делят дословные фразы (`test_doc_consensus.py:34-60`) — слепое пятно замаскировано. Это потолок метода, а не вопрос порога.

**Гибридный дизайн — два этапа, повторяющие repo-паттерн «механический extract → agent synthesize».**

- **Механический pre-cluster (stdlib, без изменений ядра).** Reuse `units()` (80-135) и `analyze()` (144-165) с ВЫСОКИМ порогом (~0.65, однострочный конфиг `--thr`, 222). Выход: high-confidence кластеры в >=2 доках = settled consensus (агенту не идут) + **резидуум** = одиночки + по одному представителю (longest-token, как уже выбирает `render()`, 181). Это срез стоимости — агент не пересуживает очевидное.
- **Семантический agent-pass (новый, за флагом `--semantic`; pure-stdlib режим остаётся no-cost default).** `_semantic_pass(residue)` сериализует резидуум в JSON и `subprocess`-зовёт агента тем же паттерном, что `_topic_files`→`variants.py` (203-210) и `synthesis_helper.py:44-52`. Агент судит концептуальное тождество и возвращает СТРУКТУРНЫЙ JSON: consensus-группы по unit-id + rationale «почему одна идея» и divergences в D-017 sub-points (claim/док/причина/что разрешит). Батчи ~40-60 пунктов, union по unit-id — bound стоимости.
- **Слияние (`_merge`).** Транзитивный union механики+семантики по unit-id. Каждый консенсус-пункт несёт оба свидетельства: Jaccard-overlap и rationale агента + `file:line` cross-refs.
- **Выход.** `render()` расширяется по D-017 и конвенциям `synthesis_helper`: `status: proposed`, ничего не auto-accepted — котёл решает (D-018).

**Buildable (effort M):** расширить `tools/doc_consensus.py`, добавить в `tools/test_doc_consensus.py` fixture «одна идея — разные слова», который лексический режим доказуемо проваливает, а `--semantic` ловит — слепое пятно становится регрессионным тестом. Зафиксировать opt-in/scoped natuur семантики в `docs/workflow-orchestration-policy.md`.

**Запись на Q-017:** направление утверждено (семантический гибрид как opt-in расширение, не замена; stdlib + subprocess-agent, без ML/embeddings; default no-cost; обязательная провальная-сейчас fixture). Остаётся реализация — переводить в задачу.

## Дизайн по стадиям (детально)

**Механическая стадия (0-1):** СТАДИЯ 0-1 (stdlib, без изменений ядра). Reuse units() (80-135) для извлечения пунктов {text,tokens,where=file:line,doc} — front-matter/код-фенсы пропущены, мусор отброшен. Затем reuse analyze() (144-165), но запускается с ВЫСОКИМ порогом (thr~0.6-0.7) — это однострочный конфиг существующего --thr (222). Высокий порог сливает только ОЧЕВИДНО-одинаковые пункты (парафраз+стемминг). Выход двух корзин: (a) high-confidence механические кластеры в >=2 доках = settled consensus, агенту НЕ отправляются; (b) РЕЗИДУУМ = одиночки + по одному ПРЕДСТАВИТЕЛЮ на multi-member кластер (longest-token член, как уже выбирает render() через max(members,key=len(tokens)), 181). Только резидуум+представители идут дальше — это срез стоимости: агент не пересуживает дешёвые очевидные матчи.

**Семантическая стадия (2):** СТАДИЯ 2 (новая, opt-in за флагом --semantic; чистый no-cost механический режим остаётся default). Новая _semantic_pass(residue) сериализует резидуум в компактный JSON (на пункт: id,doc,where,text) и shell-out к агенту-синтезатору ТЕМ ЖЕ subprocess+json.loads паттерном, которым doc_consensus._topic_files/synthesis_helper уже зовут variants.py (203-210, synthesis_helper 44-52). Промпт агента: судить КОНЦЕПТУАЛЬНОЕ тождество между доками (не лексику), вернуть СТРУКТУРНЫЙ JSON по фикс-схеме (policy: суб-агенты возвращают JSON, не прозу) — consensus GROUPS (unit-id'ы одной идеи + rationale 'почему одна идея') и DIVERGENCES, детализированные в SUB-POINTS по D-017 (claim / какой док / почему стоит особняком / что разрешит спор). Резидуум бьётся на батчи (~40-60 пунктов/вызов), группы объединяются union по общему unit-id между батчами — bound на стоимость.

**Слияние (3):** СТАДИЯ 3 (новая _merge(mechanical_clusters, semantic_groups)). Механические high-confidence кластеры приняты как есть. Семантические группы сливаются ПО UNIT-ID: если группа ссылается на представителя механического кластера, весь кластер транзитивно вливается в группу. Итог: один консенсус-набор, где членство = union механических+семантических связей, каждый пункт несёт ОБА свидетельства — дешёвый Jaccard-overlap И семантический rationale агента. Что агент не сгруппировал и не пометил — остаётся divergence.

**Выход:** Структурный merge-отчёт, расширяющий render() по D-017 + конвенциям synthesis_helper. Консенсус-секция: на идею — текст представителя, 'встречается в N док.' с file:line cross-refs всех членов, ПЛЮС строка 'почему это одна идея' с rationale агента (пусто/'(механический матч)' для кластеров без агента) — кандидаты в mainline. Divergences: сгруппированы по доку как сейчас, но каждый уникальный пункт развёрнут в D-017 SUB-POINTS (claim · док(и) · причина расхождения · что разрешит). Provenance: front-matter status: proposed, список source-доков и какой агент гнал семантику, явная пометка что ничего не auto-accepted (правило synthesis_helper/D-018: инструмент готовит материал, котёл решает).

## Запись на Q-017

D-023 закрыл единственное divergence-находку (ответственность за сгенерированный индекс). Остаточная открытая часть Q-017 — лексический потолок: token-Jaccard принципиально не ловит концептуальный cross-agent консенсус. Записать на Q-017: РЕЗОЛЮЦИЯ направления — строить СЕМАНТИЧЕСКИЙ ГИБРИД как opt-in расширение doc_consensus.py (`report --semantic`), НЕ замену: механический analyze() на высоком пороге срезает очевидные матчи, агент-pass судит концептуальное тождество только над резидуумом/представителями, _merge сливает по unit-id, отчёт идёт status: proposed в котёл (D-017/D-018), ничего не auto-accepted. Без внешних ML/embeddings — только stdlib + subprocess-agent-вызов (тот же паттерн, что variants.py/synthesis_helper). Обязательное условие приёмки: добавить fixture 'одна идея — разные слова', которую текущий лексический режим доказуемо проваливает (как сейчас на 2 policy-доках: 0 консенсуса при thr 0.4/0.3), а --semantic ловит. Default остаётся pure-stdlib no-cost; семантика опциональна и scoped из-за стоимости LLM-вызовов. Статус Q-017: направление утверждено, остаётся реализация (effort M) — можно переводить в задачу.
