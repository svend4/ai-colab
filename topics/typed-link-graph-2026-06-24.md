# 0. Визитка
> DIV-07 (типизированное/направленное ребро как first-class объект) + DIV-08 (две ортогональные оси
> физически: containment vs typed-edges) — реализованы **на технической реальности**: рёбра уже
> существуют во front-matter, `tools/edges.py` их извлекает, типизирует и делает граф проверяемым.
> Хранилище НЕ меняется (это и был ключ DIV-08 — не «или дерево, или граф», а **обе оси над одними
> атомами**).

## 1. Проблема (из свода §8 «ось вширь»)
Дерево папок/пирамида отвечает «**где** живёт атом» (containment). Но связи «**как** атом относится к
другим» (зависит, заменяет, цитирует, в теме) — рассыпаны по полям front-matter и не запрашиваемы как
граф. Нельзя было спросить «есть ли циклы зависимостей?», «какие атомы — хабы, какие — изоляты?»,
«куда висячие ссылки?». DIV-07/08 требовали сделать рёбра **первоклассными**.

## 2. Решение: две оси над одними атомами (не переписывать хранилище)
```
   ОСЬ-ДЕРЕВО (containment)        ⟂        ОСЬ-ГРАФ (typed edges)
   папки/пирамида L1..L4                    depends · related · superseded · basis · in_topic · cites
   «ГДЕ живёт»                              «КАК связан»
   tasks/T-208.md                           T-208 →depends→ {D-014, T-212, …};  T-212 ←depends← T-208
```
Граф **выводится** из front-matter (+ inline id-ссылки в теле). Ноль миграции данных — DIV-08
буквально: одни атомы, две независимые проекции.

## 3. Таксономия рёбер (поле → тип · направление · семантика)
| Поле front-matter | Тип ребра | Направление | Семантика |
|---|---|---|---|
| `depends_on` | `depends` | A→B | A нуждается в B; **цикл = дефект** |
| `superseded_by` | `superseded` | A→B | B заменяет A; цепочки |
| `related` | `related` | A—B | взаимная связь |
| `l1_basis` | `basis` | portal→tool | портал опирается на инструмент |
| `topic` | `in_topic` | atom→тема | тематическая группировка (ось-тема ⟂ папка) |
| (id в теле) | `cites` | A→B | слабое упоминание |

Внешние id-пространства (валидные, но не файл-атомы): `F-NN` (friction-ledger), `C-NN` (консенсус),
`DIV-NN` (разногласия) — живут секциями внутри docs/topics, не висячие.

## 4. Проверки графа (`edges.py check`) — жёсткое vs мягкое (ЧЕСТНО разделено)
**Жёсткое (✗, ломает инварианты):**
- **Висячие рёбра атом→атом** — depends/related/superseded на несуществующий атом (дефект провенанса).
- **Циклы depends_on** — круговая зависимость (ломает порядок/топосортировку).

**Мягкое (•, информационно):**
- **Темы без файла-атома** — `in_topic` на bare-slug без файла-темы (тег, а не ссылка). НЕ прячем (см. §5.1).
- **Асимметричный related** — A→related→B без обратного (взаимность не навязывается — инфо).
- **Supersede-целостность** — `A superseded_by B`: A должен быть терминальным.
- **Атомы без поля `type`** — гигиена (ломает отображение).
- **Активные задачи-изоляты** (кандидаты на линковку) — отдельно от **изолятов-фундамента** (норма).

## 5. Что нашёл граф на реальном каноне (2026-06-24, после adversarial-критики)
- **0 жёстких висячих атом→атом** (после резолюции docs/ + корневых .md + внешних F/C/DIV id-пространств).
- **1 цикл: `T-208 → T-212 → T-208`** — РЕАЛЬНЫЙ дефект: под-задача T-212 (runner core) объявляет
  `depends_on: [T-208]` (свой зонтик), а T-208 — `depends_on: […T-212…]`. Перевёрнутая зависимость.
  Оба сейчас `done`, так что не блокирует, но это смелл данных → исправить направление (под-задача не
  должна зависеть от зонтика). **Маршрут:** владельцу T-212 (Codex) — не править чужой атом односторонне.
- **D-014 — хаб** (огромная in-степень) против **изолятов-фундамента** D-001/003/005/007/009/011/012
  (ранние accepted-решения). Фундамент-изоляты — норма; 3 активные задачи-изоляты — кандидаты на линковку.

### 5.1. Урок adversarial-критики (4 агента) — честность важнее охвата
Критик поймал, что первоначальный «**0 висячих**» был **вводящим в заблуждение**: `in_topic` молча
исключался из проверки, пряча **29 неразрешённых тем** (bare-slug `architecture-core`, `commit-policy`,
`pipeline-fencing`… не имеют файла-темы). Исправлено: `in_topic` больше не прячется — выделено в мягкую
категорию «темы без файла». Также добавлены: проверка `type`-поля (64 атома без него), разделение
изолятов фундамент/активные, рёбра `detail_ref`/`sources`. Критик отсёк 6 ложных предложений
(author/gate/next/supersede-цепочки) — добавляли бы шум. **Вывод: граф полон по охвату; ценность была
в целостности, не в новых типах.**

## 6. Связь с существующим (не дублируем)
`decision_propagation.py` ловит back-ref-gaps (решение→потребитель не цитирует обратно) — это **частный
случай** графа. `edges.py` обобщает до полного типизированного графа со всеми типами рёбер и
структурными проверками. Дальше propagation можно переписать поверх edges-графа.

## 7. CLI
```
python tools/edges.py check            # дефекты: висячие · циклы · supersede · изоляты
python tools/edges.py stats            # узлы/рёбра по типам/висячие
python tools/edges.py neighbors <id>   # окрестность атома — ОБЕ оси (папка/уровень + рёбра in/out)
python tools/edges.py --json <sub>
```

## 8. Статус подключения и остаток
- ✅ **Граф-проверки в блоке `structure`** — `edges.py check` подключён gate-шагом (FINDER: «броня надета»).
  Жёсткие дефекты (активные циклы / висячие атом→атом) валят блок; терминальные циклы (done↔done —
  историч. артефакт, как T-208↔T-212) выделены в мягкую категорию и НЕ блокируют.
- ✅ **Транзитивные запросы построены:** `edges.py impact <id>` (blast-radius — кто транзитивно зависит,
  обратный BFS по depends/basis, БЕЗ шумных cites) + `edges.py path <a> <b>` (кратчайший путь, как связаны).
  Даёт оркестратору радиус поражения правки (напр. `impact D-014` = 6 атомов цепочки execute-sandbox).
- `contradicts`-рёбра (DIV-07 упоминал): пока нет поля; ввести при появлении противоречий-связей.
