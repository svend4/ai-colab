# T-274 — tripwire D-012: авто-детект одновременности агентов в конвейере

## Зачем

D-012 сделал heartbeat добровольным и оставил tripwire пересмотра: «если в
LIVE.md/logs/heartbeat.json стабильно >=3 одновременных агента — открыть вопрос об
обязательном heartbeat (вариант C)». Перепроверка 2026-07-06 показала: tripwire
никем не измеряется. `LIVE.md` пуст, `logs/heartbeat.json` — `agents: []`, хотя
fix-swarm-workflow'ы реально гоняют по несколько агентов параллельно. Условие
пересмотра не может сработать, потому что одновременность нигде не считается.

## Что сделать

1. В `tools/pipeline.py` (snapshot и/или status) считать «активных агентов сейчас»:
   - свежие claim'ы в `queues/claimed/` в пределах lease TTL (`_claims.DEFAULT_TTL_MIN`);
   - свежие heartbeat'ы в `logs/heartbeat/*.json` (тот же порог свежести);
   - объединение по имени агента, без задвоений.
2. Писать число в `logs/pipeline.json` (поле `concurrency`: current + наблюдённый max)
   и строку в `PIPELINE.md`.
3. При >=3 одновременных агентах печатать advisory-строку:
   «tripwire D-012: >=3 одновременных агентов — открыть вопрос об обязательном
   heartbeat (вариант C), пере-сверить D-012». Только advisory, не ошибка —
   принуждать «добровольность» нельзя (см. D-012).

## Критерий готовности

- `python tools/pipeline.py snapshot` показывает concurrency и max;
- при симуляции 3 свежих claim'ов разных агентов появляется advisory tripwire;
- `python tools/validate.py` ERROR=0; поведение при пустом конвейере не меняется.
