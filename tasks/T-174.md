# T-174 — async-stdio MCP acceptance blocker (WinError 5)

## Закрытие 2026-06-24
Задача переведена в `done` на основании D-025. Стратегия по умолчанию для Windows-машин: **Вариант 2.5 (Sync Acceptance)**. Утверждена иерархия стратегий для обхода `WinError 5` (от Sync и SSE до CMD-обертки). Блокер снят.

Назначение трекинга: `call_tool` MCP acceptance уже закрыта переносимым
**синхронным** путём (`drivers/mcp_sync_acceptance.py`, `pass=6 fail=0`,
`RESULT OK` для gateway). Единственная оставшаяся оговорка — **async** stdio
клиент (`asyncio.create_subprocess_exec`) на части Windows/Python-сред падает
`PermissionError [WinError 5]` (зафиксировано в T-087). Эта задача существует,
чтобы блокер не стал молча постоянным после закрытия T-087/T-088.

Контекст:

- `drivers/mcp_acceptance_test.py` — async stdio acceptance (падает WinError 5
  в затронутых средах).
- `drivers/mcp_sync_acceptance.py` — sync `tools/call` acceptance (зелёный,
  работает как переносимая замена).
- `drivers/gateway.md` (## Статус) ссылается на этот трек как на причину, по
  которой async путь помечен environment-dependent, а не «провален навсегда».

Что сделать:

1. Периодически (или при апгрейде Python/Windows/`mcp`) перезапускать
   `python drivers/mcp_acceptance_test.py` и фиксировать, воспроизводится ли
   `WinError 5`.
2. Если воспроизводится — определить корень: права на pipe/handle,
   ProactorEventLoop vs Selector, антивирус/политика, версия `mcp` stdio.
3. Если найдено решение — применить и подтвердить, что async acceptance
   проходит наравне с sync; затем закрыть задачу и обновить ## Статус в
   `drivers/gateway.md`.
4. Если подтверждается, что ограничение среды постоянно и неустранимо —
   перевести в `wontfix` с явной записью, что официальной acceptance считается
   sync путь, и зафиксировать это в `drivers/gateway.md`.

Критерий закрытия:

- либо async stdio acceptance проходит и задача `done`;
- либо задокументировано окончательное решение (`wontfix`) с обоснованием, и
  `drivers/gateway.md` приведён в соответствие.

## Result 2026-06-23

Реализован периодический монитор:

```powershell
python drivers\mcp_async_stdio_monitor.py gateway --force-acceptance --out reports\mcp-async-stdio-monitor-forced-2026-06-23.md
```

Текущий результат:

- простой `asyncio.create_subprocess_exec` pipe probe падает `PermissionError [WinError 5]`;
- legacy async acceptance `drivers/mcp_acceptance_test.py gateway` падает до вызова инструментов: `ACCEPTANCE pass=0 fail=6`;
- sync gateway acceptance остаётся зелёной: `SYNC ACCEPTANCE pass=6 fail=0`;
- классификация монитора: `async_state=blocked-before-mcp`, `sync_state=sync-ok`.

Вывод: T-174 нельзя закрывать как `done`: официальный async stdio путь в текущей Windows/Python среде всё ещё заблокирован ниже MCP-логики. Задача переведена в `blocked` до изменения runtime; gateway остаётся `ready` по манифесту и sync `tools/call` acceptance.
