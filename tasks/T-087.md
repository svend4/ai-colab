# T-087 — sync MCP stdio probe

Цель: получить локальный MCP acceptance путь, который не использует `asyncio.create_subprocess_exec`, потому что в текущей Windows/Python среде он падает с `PermissionError [WinError 5]`.

Что сделать:

1. Написать минимальный probe на `subprocess.Popen(..., stdin=PIPE, stdout=PIPE, stderr=PIPE)`.
2. Отправить MCP JSON-RPC `initialize`, затем `tools/list`.
3. Проверить минимум один простой server (`data` или `codex-local`).
4. Если стабильно работает — расширить до `files`/`repo-runner`/`gateway`.
5. Если не работает — зафиксировать, что MCP acceptance возможна только во внешнем runtime.

Критерий done:

- либо есть рабочий sync smoke/acceptance скрипт;
- либо есть точный отчёт, почему sync MCP невозможен.

## Result 2026-06-21 - Codex

`T-087` пройдена.

Создан `drivers/mcp_sync_probe.py`: sync MCP stdio probe на `subprocess.Popen`, без `asyncio.create_subprocess_exec`.

Ключевая поправка: установленный `mcp.server.stdio` использует line-delimited JSON-RPC, а не `Content-Length` framing.

Проверки:

```text
python drivers\mcp_sync_probe.py data codex-local --timeout 60
OK data tools=4 ['columns', 'head', 'list_tables', 'summarize']
OK codex-local tools=2 ['codex_available', 'codex_info']
RESULT OK
```

```text
python drivers\mcp_sync_probe.py files repo-runner gateway --timeout 90
OK files tools=4 ['list_files', 'read_file', 'search', 'summarize']
OK repo-runner tools=3 ['inspect_repo', 'repo_risks', 'repo_summary']
OK gateway tools=6 ['files_list', 'files_read', 'files_search', 'files_summarize', 'memory_query', 'repo_inspect']
RESULT OK
```

Вывод: локальный sync smoke путь есть. `T-048` и `T-051` пока не закрываются автоматически, потому что им нужен `tools/call` acceptance, но теперь есть база для отдельного sync call acceptance.
