# T-276 — Cauldron task materializer

## Зачем

Сейчас верхний слой уже умеет запускать субагентные handoff, держать conveyor, делать synthesis и показывать cauldron lanes. Но после синтеза остаётся ручной мост: человек или lead-agent сам превращает `new_task_candidates`, `decisions_needed`, `ratify-build` и `divergence-detail` в новые `tasks/T-*.md`.

Это узкое место замкнутого контура. Без materializer конвейер может запускать субагентов, но не умеет безопасно возвращать результаты обратно в котёл как новые проверяемые единицы работы.

Источник: `docs/closed-loop-agent-cauldron-conveyor.md`, раздел 11.

## Что сделать

1. Спроектировать CLI-инструмент, например:

```powershell
python tools\cauldron_task_materializer.py plan <synthesis-or-cauldron-file> [--json]
python tools\cauldron_task_materializer.py apply <synthesis-or-cauldron-file> --agent <agent> --only approved
```

2. По умолчанию инструмент должен быть read-only/dry-run.

3. Он должен читать структурированные секции:

- `new_task_candidates`;
- `decisions_needed`;
- `route.ratify_build`;
- `route.divergence_detail`.

4. Он должен печатать план будущих задач с evidence и source links.

5. Он не должен:

- принимать decisions;
- ставить `accepted`;
- стирать divergence;
- автоматически коммитить;
- создавать задачи без явного apply.

6. Apply-режим должен использовать `tools/next_id.py`, чтобы не конфликтовать с другими агентами.

7. После apply должны быть обязательны:

```powershell
python tools\generate.py
python tools\validate.py
```

## Критерий готовности

1. Есть dry-run команда, которая на fixture synthesis-файле показывает будущие task candidates без записи.
2. Есть apply-команда, которая создаёт `tasks/T-*.md` только при явном флаге и через `next_id.py`.
3. Divergence превращается в detail-task, а consensus/ratify-build — в build/ratification task.
4. Решения не переводятся в `accepted` автоматически.
5. Есть тесты или smoke fixture.
6. `python tools/validate.py` проходит без ERROR.
