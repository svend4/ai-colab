# T-082 — pipeline concurrency hardening (H/I)

Закрывает находки H и I ревью T-078.

**H — fencing в done/fail.** Раньше `cmd_done` проверял только имя агента и пропускал при
`h is None`; `claim_id` не сверялся, а `cmd_fail` не проверял держателя вовсе.
Теперь:
- добавлен опциональный флаг `--claim ID`; если передан — `claim_id` обязан совпасть с
  текущим держателем (как `require_holder` в `queue.py`), иначе отказ;
- `cmd_fail` теперь тоже проверяет держателя (имя + опц. claim_id);
- проверка вынесена в общий `_check_holder()`;
- `cmd_next` печатает готовую команду `done … --claim <cid>`, докстринг обновлён.
- **Backward-compatible:** без `--claim` поведение прежнее (старые вызовы работают).

**I — атомарный перехват протухшего claim.** Раньше takeover был неатомарным `open('w')`
(два агента могли оба перехватить). Теперь takeover гейтится эксклюзивным lock-файлом,
имя которого выведено из `claim_id` протухшего claim; подмена — через temp + `os.replace`.
Остаточный риск: краш победителя между lock и заменой может оставить lock (редко;
лечится reconcile_state/ручной чисткой) — задокументировано в коде.

**Тесты:** `tools/test_pipeline_fencing.py` — fencing (чужой/верный/без claim_id; чужой
агент) + гонка перехвата (8 потоков → 1 победитель). Регрессия `tools/race_test.py 8 2`
— атомарность свежего claim сохранена. `py_compile` ок, живой `pipeline.py status` ок.
