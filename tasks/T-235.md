# Задача T-235

## Контекст
Наш текущий инструментарий (уровень C) видит код просто как текстовые файлы. Чтобы полноценно понимать чужой код в песочнице без его запуска (Dogfooding experiment), нам нужен семантический парсер.

## Требования
1. Создать `tools/python_analyzer.py`.
2. Использовать модуль `ast` из стандартной библиотеки Python. Инструмент **не должен** использовать `import` или `exec` для чужого кода, чтобы соблюдать политику Read-Only.
3. Инструмент должен:
   - Извлекать граф импортов (зависимости).
   - Выводить список определенных классов и функций.
   - Оценивать уровень рисков (например, использование модулей `os`, `subprocess`, `sys`).
4. Подключить этот инструмент к пайплайну intake для Python-файлов.
