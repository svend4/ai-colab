# T-176 — Семантический гибрид `doc_consensus --semantic`

## Контекст

Q-017 (открыт Stefan) — автоматизация слияния документации агентов: находить общие пункты и подчёркивать cross-reference `file:line`, разногласия выносить как под-структуру. Сейчас `tools/doc_consensus.py` (250 строк) реализует только **механический** лексический конвейер (token-Jaccard). Эмпирически: 307 units / 0 consensus-кластеров при `thr 0.4` и `0` при `thr 0.3` для двух реальных policy-доков (`docs/parallel-work-policy.md` + `docs/commit-stream-policy.md`). Token-Jaccard слеп к концептуальному cross-agent согласию.

## Решение по Q-017

Принято направление: **семантический гибрид как opt-in расширение** (`doc_consensus report --semantic`), НЕ замена. Механика (`analyze()` на высоком пороге) срезает очевидные матчи → agent-pass судит концептуальное тождество только над резидуумом → `_merge` сливает по unit-id → отчёт `status: proposed` в котёл (D-017/D-018), ничего не auto-accepted. Stdlib + subprocess-agent, без ML/embeddings.

Детальный design — `topics/q017-semantic-consolidated-2026-06-23.md` (127 строк).

## Что нужно сделать

1. **`_semantic_pass(residuum)` в `tools/doc_consensus.py`** — для каждого одиночного unit (divergence-кандидат), который механически остался одиноким, запустить subprocess-agent с промптом «этот unit концептуально идентичен какому из ранее кластеризованных consensus-единиц? да/нет + id». Агент возвращает `(consensus_cluster_id | None)`.
2. **`_merge(res, semantic_matches)`** — перетащить unit из divergence в consensus-кластер, указанный агентом. Не auto-accept: отчёт идёт `status: proposed`.
3. **CLI флаг `--semantic`** в `main()` (`:217-245`): парсить, передавать в `analyze(...)` или его обёртку.
4. **Regression test** «одна идея — разные слова» в `tools/test_doc_consensus.py`: фикстуры с разными формулировками одного смысла, которые лексический режим проваливает (0.0 Jaccard), а `--semantic` должен поднять в consensus. Это сделает слепое пятно видимым в тестах.
5. **Документация** в `tools/README.md` — секция «Semantic hybrid (opt-in)»: когда использовать, стоимость (LLM-вызовы per residuum), ограничения.
6. **Cost guard**: opt-in по умолчанию выключен; параметр `--semantic-budget N` ограничивает максимум agent-вызовов на один прогон (чтобы случайно не запустить 307 subprocess-ов).

## Условия приёмки

1. `tools/validate.py` остаётся 7/0/0.
2. Regression test проходит: «одна идея — разные слова» → semantic → consensus поднят.
3. Лексический режим (по умолчанию) остаётся byte-identical (никаких регрессий).
4. Пример прогона на двух policy-доках: 307 units → хотя бы 5+ consensus-кластеров (vs текущие 0) с `--semantic`.
5. Пример прогона на двух обычных policy-доках без `--semantic` — те же результаты, что и до изменений.

## Что я НЕ делаю

- Не трогаю `main()` без явного обоснования (там уже есть парсинг).
- Не добавляю ML/embeddings (только stdlib + subprocess-agent).
- Не auto-accept consensus (всегда `status: proposed` в котёл).

## Результат 2026-06-23 — Codex

T-176 доведена до прикладной стадии: `tools/doc_consensus.py` поддерживает opt-in режим `report --semantic`, который сохраняет обычный лексический режим по умолчанию и добавляет второй semantic-pass только по явному флагу.

Сделано:

- добавлен лимит `--semantic-budget N`; если требуемое число agent-batches выше бюджета, команда завершается до вызова внешнего агента;
- `analyze_semantic(..., budget=N)` прокидывает budget в `_semantic_pass`, поэтому CLI и Python API имеют один и тот же cost/fan-out guard;
- `tools/test_doc_consensus.py` проверяет три критичных свойства: лексический режим не видит парафраз, semantic-pass со stub-agent поднимает парафраз в consensus, CLI пишет `status: proposed` и rationale;
- `tools/README.md` описывает semantic hybrid как безопасное расширение для Q-017/D-017/D-018: результат является материалом для котла, а не auto-accepted решением.

Проверки:

- `python -m py_compile tools\doc_consensus.py tools\test_doc_consensus.py` — OK;
- `python tools\test_doc_consensus.py` — OK;
- `python tools\doc_consensus.py report --semantic --semantic-budget 0 --files docs\parallel-work-policy.md docs\commit-stream-policy.md` — ожидаемый fail-fast: `semantic budget exceeded: need 7 agent calls, budget 0`.

Ограничение: требование «5+ consensus-кластеров на policy-доках» требует реального `DOC_CONSENSUS_AGENT`; без агента это корректно деградирует в proposed-отчёт без semantic-слияния. Текущая приёмка закрывает инфраструктуру opt-in, budget guard и regression-контракт.
