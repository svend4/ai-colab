# Sync MCP acceptance — `drivers/mcp_sync_acceptance.py` (шаг 2/4)

Закрывает «L2 acceptance hardening» (roadmap layers-coverage): официальный async MCP stdio-клиент
на части Windows-сред падает `WinError 5`, поэтому полная `call_tool`-приёмка была непереносимой.

Сделано: расширил `SyncMcpClient` Codex (T-087, `drivers/mcp_sync_probe.py`) с initialize+tools/list
до реального `tools/call` по КАЖДОМУ инструменту с аргументами против `data/fixtures`:

- files (4), repo-runner (3), data (4), codex-local (2), gateway (6) = **19 вызовов**;
- прогон: `SYNC ACCEPTANCE pass=19 fail=0 RESULT OK`;
- переносимо: subprocess.Popen работает там, где async stdio падает (среда Codex тоже).

Файл намеренно в `drivers/` (не `tools/`): при запуске из `tools/` локальный `tools/queue.py`
затеняет stdlib `queue`, на котором держится `mcp_sync_probe` (поймано и исправлено).
Запуск: `python drivers/mcp_sync_acceptance.py [server...]`.
