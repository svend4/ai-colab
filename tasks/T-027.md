# T-027 — `tools/pipeline.py`: конвейер задач («общий котёл»)

Чтобы общение и работа агентов были **динамичнее**, нужен конвейер: агент сам тянет
следующую готовую задачу из общего котла, делает, отчитывается, берёт следующую —
несколько агентов параллельно, через одну форму.

80% уже было: `queue.py` (атомарный захват) и `dispatch.py` (готовность по DAG). Не
хватало одной операции — **атомарного pull-next**: `dispatch.py` только показывал
следующую (read-only), а захват шёл отдельно — между ними окно для перехвата.
`pipeline.py` сливает их в один шаг.

```
python tools/pipeline.py next   <agent>                 # атомарно занять след. готовую
python tools/pipeline.py done   <agent> <T-id> --report "..."
python tools/pipeline.py fail   <agent> <T-id> --reason "..."
python tools/pipeline.py status                          # лента конвейера (одна форма)
python tools/pipeline.py mine   <agent>
```

Готовая задача = `status:todo` + все `depends_on` done + не занята свежим claim'ом.
Захват атомарен (`O_CREAT|O_EXCL`, как в `queue.py`). Отчёт — per-task done-маркер
(`queues/done/<id>.done.md`, без конфликтов) + единый вид через `status`.

**Проверено эмпирически:** 5 параллельных `next` → 5 **разных** задач (ноль задвоений),
задача с невыполненной зависимостью в работу не ушла, статус занятой → `doing`.

Codex продолжил слой B/C из Q-011:

```
python tools/pipeline.py snapshot
```

Команда создаёт:

- `PIPELINE.md` — человекочитаемый снимок конвейера;
- `logs/pipeline.json` — машинный снимок для агентов и скриптов.

Это закрывает этап «диспетчер/конвейер» из `topics/scaling-design.md` динамичной формой: агент крутит цикл `next → (работа) → done → snapshot → next`, не дожидаясь ручной раздачи.
