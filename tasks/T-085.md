# T-085 — единый парсер front-matter (находка L)

Находка L ревью T-078: парсер front-matter скопирован ~8 раз
(`validate.py`, `generate.py`, `queue.py`, `pipeline.py`, `dispatch.py`, `metrics.py`,
`risk_gate.py`, `drivers_catalog.py`) — встроенный источник дрейфа, наивный `split(':',1)`
ломается на значениях с `:`.

**Почему отложено (а не сделано в текущем батче):** это рефакторинг с высоким blast radius —
затрагивает 8 ядровых инструментов, из них `validate`/`generate` идут в pre-commit, а
`pipeline`/`queue` — конкуренция. Польза — только чистота (функционального бага нет: парсеры
работают). Риск тихо изменить поведение в одном из 8 мест выше пользы для одной сессии,
особенно при параллельной работе Codex.

**План безопасного выполнения (отдельный PR):**
1. Сверить, что 8 копий побайтово эквивалентны (или зафиксировать различия).
2. Создать `tools/_canon.py` с `parse_front_matter` (+ опц. ужесточение: значения с `:`, списки).
3. Заменить копии импортом по одному инструменту, прогоняя после каждого:
   `validate.py`, `generate.py --check`, `pipeline.py status`, `race_test.py`,
   `test_pipeline_fencing.py`, `drivers_catalog.py --check`.
4. Один коммит = один инструмент, чтобы регрессия была локализуема.

До выполнения находка L остаётся открытой и задокументированной.
