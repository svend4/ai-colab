# T-159 — Adopt repo_search as top-layer canonical documentation search

Контекст: в рабочем дереве появился `tools/repo_search.py` и тест. Инструмент полезен для вершины пирамиды: он даёт ранжированный FTS/BM25 поиск по `docs/`, `decisions/`, `questions/`, `темы/`, `tasks/`, чтобы агент или человек находил политику/решение/контекст одной командой. Но текущий тест падает на Windows `PermissionError` из-за `tempfile.mkdtemp`, а runtime DB `logs/repo-knowledge.db` не игнорируется.

Критерии done:

- `tools/test_repo_search.py` использует project-safe `drivers/test_tmp.py`;
- `logs/repo-knowledge.db` не попадает в git status как runtime artifact;
- `tools/top.py` получает команду `repo-search` как удобную кнопку верхнего слоя;
- `tools/capabilities.py` и документация отражают новую команду;
- `test_repo_search.py`, `test_top.py`, `capabilities.py --check`/snapshot и `top.py health` зелёные;
- commit включает source/test/docs/generated indexes, но не runtime DB.
