# T-172 — Fix Python tempfile PermissionError on Windows sandbox

Аудит T-171 показал: прямой PowerShell write в `tmp-work` работает, но Python `tempfile.mkdtemp(..., dir='tmp-work')`
создаёт подпапку, в которую Python затем не может записать файл. Из-за этого падают:

- `tools/test_core_export.py`;
- `tools/test_ownership.py`;
- `tools/test_text_extract_docx.py`.

Нужно:

1. Воспроизвести дефект минимальной пробой.
2. Понять причину ACL/sandbox/tempfile.
3. Добавить project-safe temp helper или исправить тесты.
4. Расширить `tools/friction.py` F-004, чтобы он проверял не только прямую запись в `tmp-work`, но и запись в подпапку, созданную Python.
5. Прогнать полный `tools/test_*.py`.
## Result 2026-06-23

Исправлено:

- `drivers/test_tmp.py` теперь делает write-probe созданной temp-директории.
- `tools/test_core_export.py`, `tools/test_ownership.py`, `tools/test_text_extract_docx.py` переведены с `tempfile.mkdtemp()` на `drivers/test_tmp.py`.
- `tools/test_promote_reuse.py`, `drivers/data/test_data.py`, `drivers/repo-runner/test_inventory.py`, `drivers/workbench-db/test_db.py` также переведены на workspace-safe temp helper.
- `tools/friction.py` F-004 теперь отличает project-safe helper от unsafe stdlib `tempfile`: если helper работает, а `tempfile.mkdtemp()` нет, статус `warn`, а не ложный `ok`.
