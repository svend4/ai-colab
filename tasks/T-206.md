# T-206 — safe-auto-apply (RSI, P28 из FINDER-фронтира)

Из C (RSI-автоматизация). P15 (re-measure дельта) и P16 (auto-archive stale streams) **сделаны**
(`adoption.py --delta/--save-baseline`, `stream.py archive --apply`). P28 — самая рискованная часть:
дать детекторам **чинить тривиальное автоматически** (без ручного роутера).

## Почему отдельный design (не в одну руку)

Авто-мутация требует **строгого определения safe**: что можно чинить БЕЗ человека. Слишком широко —
авто-правки шумят/ломают; слишком узко — бесполезно. Это policy → через котёл (D-018) + человеко-гейт
(D-006). Нельзя просто включить.

## Кандидаты на safe-auto (доказанно обратимые, детерминированные)

- `generate.py` index-регенерация при drift (производное, не PRIMARY) — уже по сути авто в хуке.
- `reconcile_state.py fix --apply` для derived-only (index/snapshot) — уже есть, но не авто-триггерится.
- `stream.py archive` stale (P16) — теперь есть, можно по расписанию.
- orphan-doc cross-link — НЕТ (требует смысла).
- dormant-tool retire — НЕТ (governance).

## Что спроектировать

1. Реестр `SAFE_AUTO` правил: {детектор, условие, действие, обратимость=git}. Только derived/идемпотентное.
2. Гейт: `blocks.py improve --auto-safe` применяет ТОЛЬКО SAFE_AUTO, печатает что сделал, оставляет
   PRIMARY/governance человеку (карточкой decision-menu).
3. Тест: safe-auto чинит derived-drift, НЕ трогает PRIMARY/governance.

## Критерий закрытия

`SAFE_AUTO`-реестр ратифицирован котлом; `--auto-safe` применяет только его; PRIMARY/governance всегда
к человеку; тест зелёный. До ратификации — НЕ включать авто-мутацию.
