# T-092 — execute-sandbox gate (находка G)

Закрывает программно-применимую часть находки G ревью T-078: policy требует реальной
песочницы (контейнер/лимиты) до запуска кода, но раньше `validate.py` лишь WARN-ил на
`mode: execute`, то есть execute-драйвер мог пройти канон без реальной изоляции.

Сделано:

1. `tools/validate.py`: `mode: execute` → **ERROR**, если `sandbox` не из набора реальных
   механизмов (`container`/`docker`/`nsjail`/`firejail`/`gvisor`/`sandboxed-vm`). С реальной
   изоляцией — WARN (подтвердить accepted-решение). Декларативные значения (`required-before-...`)
   execute не разрешают.
2. `drivers/SCHEMA.md` пункт 8 обновлён.

Проверка: `validate OK=9/0/0` (ни один текущий драйвер не `execute` → без регрессии); симуляция
гарда подтверждает ERROR на декларативных sandbox и WARN на реальной изоляции.

**Важно (граница):** это лишь ГАРД канона — он не даёт реальной изоляции. Сам запуск
непроверенного кода (svend4) по-прежнему требует настоящей песочницы (контейнер/nsjail + cgroups);
до её реализации `mode: execute` остаётся заблокированным этим гардом. Реализация песочницы —
отдельная инфра-задача (вне текущего ревью).
