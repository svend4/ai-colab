# T-264 — Thread schema MVP

## Зачем

После анализа Zed Parallel Agents и текущей инфраструктуры проекта выявлен главный практический пробел: есть `topics/`, `queues/`, `streams/`, `worktree`, `conveyor` и `top.py`, но нет единого долговечного объекта `thread`, который связывает:

- разговор/историю сообщений;
- task/claim;
- stream/variant;
- worktree/branch;
- outputs;
- проверки;
- следующий шаг.

Задача T-264 запускает первый практический этап headless Zed-like workbench: файловые треды без GUI и без обязательной локальной модели.

## Scope

Реализовать минимальный stdlib-only инструмент:

```powershell
python tools\thread.py init <topic> --agent <agent> --mode read-only
python tools\thread.py status <thread-id> --json
python tools\thread.py add-message <thread-id> user --text "<text>"
python tools\thread.py add-message <thread-id> assistant --file <path>
```

Минимальная структура:

```text
topics/<topic>/threads/<thread-id>/THREAD.json
topics/<topic>/threads/<thread-id>/messages/
topics/<topic>/threads/<thread-id>/artifacts/
```

Минимальная схема `THREAD.json`:

```json
{
  "schema": "thread.v1",
  "id": "thread-YYYYMMDD-HHMMSS-agent",
  "topic": "topic-name",
  "status": "open",
  "agent": "codex",
  "mode": "read-only",
  "task_id": null,
  "stream_id": null,
  "worktree": null,
  "model": null,
  "tools": [],
  "outputs": [],
  "checks": []
}
```

## Acceptance

- `tools/thread.py` создан без внешних зависимостей.
- `tools/test_thread.py` покрывает `init`, `status`, `add-message`.
- Команды не запускают shell и не пишут вне workspace.
- Сообщения append-only: инструмент не переписывает чужую историю.
- `THREAD.json` валиден JSON UTF-8.
- Документация связана с `docs/zed-like-headless-workbench-mvp.md`.
- `python tools\validate.py` проходит либо известные unrelated warnings явно указаны в отчете.

## Out of Scope

- Не реализовывать local LLM adapter в этой задаче.
- Не реализовывать PTY/interactive terminal control.
- Не исполнять чужой код.
- Не переводить governance decisions в `accepted`.
- Не менять существующую модель `pipeline`/`conveyor`, только подготовить объект, который позже может быть подключен к `top.py workspace-cell`.

## Implementation note 2026-06-26

Stage A implemented by Codex:

- `tools/thread.py` added.
- `tools/test_thread.py` added.
- Supported commands: `init`, `status`, `list`, `add-message`, `add-output`.
- Thread state is stored as `topics/<topic>/threads/<thread-id>/THREAD.json`.
- Message bodies are append-only Markdown files under `messages/`.
- JSON is UTF-8 with `ensure_ascii=false`.
- Tool does not call shell, network, model or PTY.
- Focused test passed: `python tools\test_thread.py`.

Known hardening follow-ups:

- CLI subprocess test with timeout, because nested Python processes are unstable in the current Windows/hermes/uv environment.
- Treat message files as source of truth and `THREAD.json` as index when adding future concurrent writers.
- Add a later workspace-cell aggregator instead of extending this tool into an orchestrator.
