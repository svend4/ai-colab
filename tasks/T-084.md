# T-084 — сверка manifest `tools` ↔ реальные `@mcp.tool()` (находка K)

Закрывает находку K ревью T-078: манифестное `interfaces` декларирует одно, а сервер
регистрирует другое (`codex-local`: `interfaces:[workspace-status,run-checks,...]` vs реальные
`codex_available/codex_info`), и `source_last_verified` фиксирует дату, но не сам дрейф.

Решение (надёжное и не ломающее):

1. Введено опциональное поле манифеста `tools:` — фактические имена `@mcp.tool()`.
   `interfaces` остаётся концептуальным и не трогается.
2. `tools/validate.py` → `check_driver_tools()`: для драйверов с объявленным `tools:` статически
   извлекает имена `@mcp.tool()` из `drivers/<id>/mcp_server.py` и сверяет — **ERROR** при
   расхождении. Опционально (без поля — пропуск), поэтому ничего не ломает.
3. Поля проставлены: `data` `[list_tables, columns, head, summarize]`,
   `repo-runner` `[inspect_repo, repo_summary, repo_risks]`, `codex-local` `[codex_available, codex_info]`.
4. `drivers/SCHEMA.md` дополнен (опциональное поле + пункт 9 валидатора).

Проверка: `validate.py` → `OK=9 WARN=0 ERROR=0` (новый OK «drivers tools: 3 …»); негативный
микро-тест подтверждает, что мисматч ловится. Чек уже идёт в pre-commit (через validate).
Осталось: проставить `tools:` для `files`/`gateway` (за их владельцами/после приёмки).
