# T-025 — Импортированный roadmap как источник MVP

Документ `docs/ai_middle_layer_architecture_ru.md` скопирован из внешней папки в проект и должен использоваться как практический roadmap для AI-OS Bridge.

Задача:

1. Сопоставить уровни документа (0-8) с D-010 и текущими задачами T-023/T-024.
2. Выделить минимальный MVP на 2-3 дня.
3. Решить, какие драйверы из backlog создавать первыми.
4. Не строить серверную платформу до локального MVP.

Кандидаты из документа: `file_inventory_driver`, `text_extract_driver`, `classification_driver`, `search_driver`, `repo/github driver`, read-only MCP tool.

## Progress 2026-06-20 - Codex

Содержательная часть начата и вынесена в `docs/mvp-roadmap.md`.

Что извлечено:

- текущая стадия проекта: локальный workbench-прототип, не AI-OS и не сервер;
- плюсы/минусы текущей инфраструктуры;
- MVP-драйверы: `repo-runner`, `files`, `text-extract`, `search-index`, `report`;
- минимальная SQLite-память: `documents`, `chunks`, `entities`, `audit_log`;
- обязательные проверки безопасности для драйверов;
- следующие задачи, которые стоит завести через `next_id.py`.

Front-matter пока не перевожу в `done`, потому что в текущей сессии shell зависает даже на простых командах, а значит нельзя честно прогнать `generate.py` и синхронизировать индексы.
