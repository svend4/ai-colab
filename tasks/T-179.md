# T-179 — Conveyor regulate advisory

## Контекст

После T-177 `conveyor.py next` предлагает `Conveyor regulate` как следующий самостоятельный пункт. Его не надо начинать до T-178, потому target-регулятор должен учитывать классы результатов intake.

## Что нужно сделать позже

1. Спроектировать read-only/advisory команду для `tools/conveyor.py regulate` или `tools/top.py conveyor-regulate`.
2. Входы: current conveyor status, landed/missing-output, idle age, assurance status, result-intake classes.
3. Выход: recommendation `increase`, `hold`, `decrease`, `process-first`, с причинами.
4. Не менять target автоматически без явного флага.

## Условия приёмки

- Есть тесты для increase/hold/decrease/process-first.
- Команда не запускает агентов и не меняет target по умолчанию.
## Результат 2026-06-23 — Codex

Реализован advisory-регулятор workflow-conveyor:

- `python tools\conveyor.py regulate`;
- `python tools\conveyor.py regulate --json`;
- `python tools\conveyor.py regulate --json --no-assurance` для быстрых smoke/tests;
- pure-функция `regulate(...)` возвращает `increase`, `hold`, `decrease` или `process-first`, `target_delta`, `recommended_target`, reasons и `mutates: false`;
- landed outputs best-effort классифицируются через `result_intake.py`;
- тесты добавлены в `tools/test_conveyor.py`.

Текущий реальный smoke: при `target=2`, `inflight=1`, `landed=0` и idle больше 20 минут команда рекомендует `decrease` до `target=1`; это advisory, state не меняется автоматически.
