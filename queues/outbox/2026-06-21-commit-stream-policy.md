# Commit stream policy

По вопросу Stefan о commit-политике добавлена промежуточная модель `streams/`.

Проблема: если несколько агентов работают одновременно, обычный Git commit может случайно включить чужую half-done работу. Но если совсем не фиксировать промежуточные варианты, пропадает сравнение подходов.

Решение:

- mainline commit — только для выбранного и проверенного набора файлов;
- `streams/` — для параллельных "ручейков" вариантов;
- stream packet — это полу-коммит: `STREAM.md`, notes, optional patch/evidence;
- похожая задача может быть закрыта как дубликат очереди, но технический вариант сохраняется в stream;
- integration commit допустим только явно, когда задача именно собрать несколько потоков.

Моё мнение: это правильная середина между "просто текст" и полноценными Git-ветками. Она позволит агентам вести несколько вариантов параллельно, но не загрязнять основную линию незавершёнными изменениями.
