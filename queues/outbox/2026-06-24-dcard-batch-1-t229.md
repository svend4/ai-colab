# T-229 — D-Card batch 1

Codex started the D-Card metadata debt reduction as a small controlled batch.

## Scope

Added valid `# [FILE ID CARD]` blocks to:

- `tools/next_id.py`
- `tools/test_next_id.py`
- `tools/friction.py`
- `tools/test_friction.py`

This batch intentionally stayed small. The project still has many files without D-Cards, so mass generation should be a separate policy/tooling task, not hidden inside a broad manual edit.

## Result

Before this batch, `top.py health` / metadata soft-check showed 126 missing/invalid D-Cards. After this batch, `python tools/enforce_metadata.py --warn-only` reports 122 remaining errors, so the batch reduced the debt by 4 files.

`python tools/dcard_indexer.py` was rerun and updated `docs/dcard_index.md` to include the new cards.

## Next recommendation

Continue in batches by domain:

1. core coordination: `_canon.py`, `pipeline.py`, `generate.py`, `validate.py`, `top.py`;
2. diagnostics/health: `assurance.py`, `drift_check.py`, `capabilities.py`, `drivers_catalog.py`;
3. tests for those tools;
4. only after 2-3 clean batches, consider a semi-automatic D-Card generator with review.
