# T-216 evidence addendum

## Why this exists

`queues/done/T-216.done.md` was closed as plain `done` without applied-evidence. Post-hoc verification found two practical runtime issues in the execute-sandbox gate path:

1. `tools/execute_human_gate.py` could print a Russian usage docstring through a non-UTF-8 Windows console path and fail with `UnicodeEncodeError`.
2. `tools/execute_preflight.py check-all` used `os.path` before importing `os`.

This addendum does not rewrite the original done marker. It records the applied verification and the small safety fixes needed for the gate path to be testable.

## Fixes applied

- `tools/execute_human_gate.py` now calls `_ioutil.configure_output()` before printing CLI help or gate status messages.
- `tools/execute_preflight.py` now imports `os`, so `check-all` can evaluate the audit logger path after backend/isolation/limit checks.
- `tools/test_execute_human_gate.py` now creates its temporary approval directory under project-local `tmp-work/`, matching the established Windows-safe test pattern.
