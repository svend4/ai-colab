# 0. Визитка
> Код нельзя править вслепую-параллельно: 5 агентов в одном файле = конфликт + нарушение «один источник
> истины». Но первый-подход-побеждает = ранняя конвергенция (тот же баг, что в прозе). Решение: дивергенция
> на уровне **КОНЦЕПТА/ПСЕВДОКОДА** (conflict-free), сверка концептов, реализация ОДИН раз. Триада:
> концепт(малый) · гибрид-подход(средний/золотая середина) · реализация(большой, в worktree).

# 1. Условия применимости
Для НЕТРИВИАЛЬНЫХ изменений, где ПОДХОД неочевиден и есть >1 агента/варианта. НЕ для тривиальных правок
(их просто делать). НЕ для механики (один источник истины).

# 2. Проблема
- Слепые ПАРАЛЛЕЛЬНЫЕ ПРАВКИ кода = merge-конфликт + нельзя иметь 2 версии одной функции.
- Но если все ждут первого и правят его подход — ранняя конвергенция: разные АРХИТЕКТУРНЫЕ подходы не
  раскрыты до того, как кто-то утопил усилия в реализации (дорогую часть).
- Нужна дивергенция БЕЗ edit-конфликта.

# 3. Дизайн — триада уровней (золотая середина внутри кода)
- **3.1. КОНЦЕПТ (малый/частный) — псевдокод, не код.** Каждый агент вслепую в своей песочнице:
  ЧТО менять · ЗАЧЕМ · ПОДХОД (псевдокод/ключевые сигнатуры/точки изменения) · альтернативы · риски.
  Реальный код НЕ трогается. Дивергенция свободна (нет конфликта), дёшева.
- **3.2. СВЕРКА КОНЦЕПТОВ → ГИБРИД-ПОДХОД (средний/золотая середина).** Тем же конвейером:
  где подходы СОШЛИСЬ (ядро-подход) / РАЗОШЛИСЬ (trade-offs в детализацию). Синтез лучшего ПО МЕРИТУ —
  это и есть «средний/гибридный вариант» (синтез из концептов, а не голосование).
- **3.3. РЕАЛИЗАЦИЯ (большой/глобал) — ОДИН раз, в worktree.** Один агент пишет реально, в изоляции
  (D-028 Level-1 worktree), ПОСЛЕ консенсуса концепта. Конфликта нет: подход уже выбран.
- **3.4. Сверка С ТЕКУЩИМ КОДОМ — отдельный вход.** Концепт сверяется не только с другими концептами,
  но и с ТЕКУЩЕЙ ситуацией: что есть сейчас, что сломается, что переиспользуемо (вопрос Stefan
  «сверить с текущей ситуацией, проанализировать»). Это вход в сверку, не после.

# 4. Уникальный вклад
- **Дивергенция на уровне КОНЦЕПТА, не edit** → conflict-free И раскрывает РАЗНЫЕ подходы ДО дорогой
  реализации. Это разрешает «как параллелить код» без merge-ада.
- **«Средний вариант» = синтезированный гибрид-подход** (золотая середина концептов) — триада прямо в код.
- **Тот же конвейер (ripeness_gate · independence_measure · consensus_by_meaning) работает для кода
  без переписи** — вариант = псевдокод вместо прозы. Методичка переносится на код целиком.

# 5. Evidence
D-028 уже даёт worktree-изоляцию для кода; `sandbox_runner.py` существует; конвейер сверки построен.
Недостающее звено — концепт-уровень ПЕРЕД worktree: сейчас прыгают сразу в реализацию (ранняя конвергенция).

# 6. Риски
- Концепт разойдётся с реализацией → ИК-5: verify реализации против концепт-консенсуса (сделал то, что согласовано?).
- Псевдокод слишком абстрактен → требовать ключевые сигнатуры + точки изменения, не только прозу.
- Лишний оверхед на мелочи → отсекать условием §1 (только нетривиальное).

# 7. Инварианты кода
- **ИК-1** Дивергенция на КОНЦЕПТЕ/псевдокоде, никогда на edit-уровне (слепые параллельные правки запрещены).
- **ИК-2** Реальный код — только ПОСЛЕ концепт-консенсуса, ОДНИМ реализатором, в worktree.
- **ИК-3** Концепт-вариант зрел, если: что/зачем/подход/альтернативы/риски + сверка с текущим кодом.
- **ИК-4** Гибрид-подход (средний) синтезируется по мериту, не голосованием.
- **ИК-5** Реализация верифицируется против концепт-консенсуса.

# 8. Открытые вопросы
1. Детальность концепта: чистый псевдокод vs проза vs реальные сигнатуры — где золотая середина?
2. Кто выбирает реализатора (автор лучшего концепта? отдельный?) и как избежать Cartographer=Voter?
3. Как машинно verify «реализация == концепт-консенсус»?
