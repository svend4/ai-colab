# Q-017 — слияние документации разных агентов (не только кода)

## Вопрос

Когда разные агенты/люди пишут в документах по одной теме, нужно **слияние документации** (не только
кода): находить **общие пункты** и подчёркивать их (указывать, в каких документах встречаются —
cross-reference `file:где`), консенсус оставлять в mainline-документе как описание, а **разногласия**
выносить, детализировать и обосновывать под-версиями/под-пунктами/под-темами/под-файлами — логически и
грамматически структурированно.

Сейчас синтез ручной (`opinion-synthesis`, `friction-subsystems-synthesis`): таблицы консенсуса/
разногласий без `file:line`, не масштабируется, дрейфует. `synthesis_helper._outline` парсит только
заголовки, не содержание.

## Что решить

Какой механизм принять: (а) **doc-consensus инструмент** поверх `variants.py` (скан тем-доков → общие
пункты с cross-ref + разногласия как под-структура); (б) **формат-вывод** (консенсус = описание в
mainline-доке, разногласия = под-файлы `streams/forks` с обоснованием — модель D-017 для прозы);
(в) расширить `synthesis_helper` до анализа содержания. Детальные варианты — в
`темы/assurance-and-doc-merge-2026-06-22.md` §B.

## Резолюция направления (2026-06-23)

Механический слой принят и работает: `tools/doc_consensus.py` (вариант «а») даёт консенсус (пункты в
≥2 доках) + разногласия с `file:line`. D-023 закрыл единственную найденную им divergence-находку.
**Остаточный открытый пункт** — лексический потолок: token-Jaccard принципиально не ловит
**концептуальный** cross-agent консенсус (на двух реальных policy-доках: 307 пунктов, **0** консенсус-
кластеров при thr 0.4/0.3, хотя ручной синтез фиксирует ≥7 согласий).

Утверждённое направление — **семантический гибрид как opt-in расширение** (`doc_consensus.py report
--semantic`), НЕ замена: механический `analyze()` на высоком пороге срезает очевидные матчи →
агент-pass судит концептуальное тождество только над резидуумом/представителями → `_merge` сливает по
unit-id → отчёт `status: proposed` в котёл (D-017/D-018), ничего не auto-accepted. Без ML/embeddings —
stdlib + subprocess-agent (паттерн `variants.py`/`synthesis_helper`). Обязательная приёмка: fixture
«одна идея — разные слова», которую лексический режим доказуемо проваливает, а `--semantic` ловит.
Детальный дизайн и buildable (effort M): `темы/q017-docmerge-semantic-2026-06-23.md`. Остаётся
реализация — можно переводить в задачу.
