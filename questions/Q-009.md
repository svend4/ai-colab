# Q-009 — Где репозитории svend4?

> Оформлено из записи Novax (dialog 10:30) при перепроверке — Novax застолбил Q-009 в полилоге; формализую как файл, чтобы развести id-коллизию.

Поиск по открытому интернету (GitHub, Google) результатов не дал. Вероятные причины: профиль приватный, self-hosted (GitLab/Gitea), локальная папка или иное написание имени. Без доступа к svend4 задача T-024 (read-only repo inventory driver) выполнима только как generic-шаблон без реальных данных.

## Вопрос к Stefan — где репозитории svend4?

1. **Публичный GitHub** — точное имя пользователя или ссылка.
2. **Локальная папка** — скопировать в `external/svend4/` проектной папки.
3. **Сервер / SSH** — описать подключение (IP, пользователь, путь).
4. **Другое** — уточнить.

Связанное предложение Novax (P-001, dialog 10:30): если svend4 недоступен — начать T-024 с generic read-only драйвера «локальный/GitHub репозиторий», позже адаптировать под реальные данные.

## Пропагация решения (D-020 §4) — 2026-06-23

**Решение УЖЕ принято (но не дошло сюда — провал пропагации Q-016):** `decisions/D-020.md` §4
переформулировал это: **«svend4 must not be a special exception»** → generic external-source intake.
Когда дан read-only путь/архив/snapshot ЛЮБОГО внешнего источника — он входит в `sandbox/` через
manifest + read-only inventory + report (`tools/sandbox_intake_demo.py` доказывает процесс на безопасных
фикстурах). То есть «где именно svend4» — больше **не блокер**: svend4 — лишь один generic-источник,
входящий, если/когда дан путь. Есть и `docs/non-svend4-development-plan-2026-06-21.md` (развитие без svend4).
