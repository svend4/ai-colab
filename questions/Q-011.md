# Q-011 — Динамический конвейер агентов

Контекст: пользователь хочет более динамичный, управляемый, живой процесс разработки. Несколько агентов параллельно берут задачи из общего пула, выполняют, отчитываются — через единый конвейер.

## Варианты

### A. Улучшить queue.py (пул, приоритеты, авто-назначение)

**Описание:** Расширить `queue.py`:
- `next` — взять следующее свободное задание из пула (авто-назначение).
- `status` — показать кто что делает прямо сейчас (heartbeat).
- `priority` — поле приоритета в заданиях (high/normal/low), сортировка по нему.
- `pool` — не один inbox, а несколько пулов (urgent, normal, backlog).

**Плюсы:**
- Используем существующий код (queue.py).
- Минимальные изменения.
- Просто и понятно.

**Минусы:**
- Всё ещё текстовый интерфейс (Markdown).
- Нет визуального конвейера.
- Агенты не видят друг друга без чтения queue list.

**Когда подходит:** Если нужно быстрое улучшение без новой архитектуры.

---

### B. Создать pipeline.md (единый визуальный конвейер)

**Описание:** Новый файл `pipeline.md` — единый конвейер проекта:
- Секция `BACKLOG` — задачи, которые ждут.
- Секция `IN PROGRESS` — кто что делает прямо сейчас (агент + задача + время старта).
- Секция `REVIEW` — на проверке.
- Секция `DONE` — выполнено сегодня.
- Генерируется автоматически из `tasks/`, `queues/claimed/`, `queues/done/`.
- Обновляется при каждом `generate.py`.

**Плюсы:**
- Визуальный, как Kanban-доска.
- Все видят статус одним взглядом.
- Можно смотреть без чтения всего dialog.md.
- Генерируется из существующих данных.

**Минусы:**
- Ещё один генерируемый файл.
- Не решает проблему «живого общения».

**Когда подходит:** Если нужна доска статусов для всех участников.

---

### C. Добавить JSON-логи и heartbeat (машинное взаимодействие)

**Описание:** Новый слой JSON-файлов:
- `logs/heartbeat.json` — каждый агент пишет: `{agent, status, task, started, progress, estimated}`.
- `logs/activity.json` — лента событий (кто что взял, завершил, сдал).
- `logs/pipeline.json` — машинный срез конвейера (для скриптов и агентов).
- Обновляется через Python-скрипт, не руками.

**Плюсы:**
- Машиночитаемо — агенты читают быстро, не парсят Markdown.
- Можно строить автоматизацию (боты, триггеры).
- Heartbeat даёт «живое» ощущение — видно, кто активен прямо сейчас.
- Масштабируется на 10+ агентов.

**Минусы:**
- Новый формат — сложнее для человека (но Markdown-генерация из JSON решает).
- Нужен скрипт для обновления JSON.

**Когда подходит:** Если нужна скорость и масштаб.

---

### D. Агентный чат (heartbeat + live-updates)

**Описание:** Создать `live.md` — файл, который обновляется каждые 5 минут:
- Агенты пишут короткие статусы: «Novax: работаю над T-024, 50%, ETA 15 мин».
- Формат: `HH:MM Agent [🟡/🟢/🔴] задача прогресс%`.
- Старые записи архивируются каждые 24 часа.
- Можно смотреть одним взглядом — кто что делает.

**Плюсы:**
- Максимально «живое» общение.
- Коротко, визуально, быстро.
- Не нужно читать весь dialog.md.

**Минусы:**
- Ещё один файл, который нужно поддерживать.
- Может быстро устаревать, если агенты не обновляют.

**Когда подходит:** Если нужно ощущение «комнаты разработки».

---

## Моя рекомендация (Novax): Комбинация B + C + улучшение A

**Почему:**
1. **`pipeline.md` (B)** — визуальная Kanban-доска для людей. Генерируется из существующих данных. Легко понять.
2. **`logs/pipeline.json` (C)** — машинный срез для агентов и скриптов. Быстро, масштабируемо.
3. **Улучшить `queue.py` (A)** — добавить `next`, `status`, `priority`. Не заменяет, а дополняет.
4. **Heartbeat** — добавить в `logs/heartbeat.json` как часть C. Агенты пишут статус при каждом действии.

**Что это даёт:**
- Человек смотрит `pipeline.md` — видит всё.
- Агент читает `logs/pipeline.json` — быстро, без парсинга Markdown.
- Агент берёт задачу через `queue.py next` — автоматически следующая свободная.
- Система масштабируется на 10+ агентов без переделки.
