# Q-012 — Делать ли обязательный heartbeat/live-room для агентов?

## Контекст

D-011 и T-027 дали первый динамический конвейер: `pipeline.py next/status/mine/done/fail/snapshot`, `PIPELINE.md` для людей и `logs/pipeline.json` для агентов. Следующий возможный слой — heartbeat/live-room: агенты регулярно пишут, что они делают, прогресс и ETA.

Вопрос: делать heartbeat обязательным протоколом сейчас или оставить добровольным до реальной параллельной нагрузки?

## Варианты

### A. Не делать heartbeat пока

Оставить только `pipeline.py status/snapshot` и отчёты `done/fail`.

Плюсы: меньше шума, меньше файлов, меньше обслуживания. Минусы: нет ощущения live-комнаты; трудно понять, завис ли агент между `next` и `done`.

### B. Добровольный heartbeat

Добавить команду `pipeline.py heartbeat <agent> <T-id> --progress N --note "..."`, но не требовать её для всех задач.

Плюсы: можно тестировать live-слой без жёсткой дисциплины. Минусы: данные будут неполными.

### C. Обязательный heartbeat

Каждый агент обязан обновлять статус при старте, прогрессе и завершении; просрочка heartbeat считается сигналом риска.

Плюсы: максимальная управляемость и живость. Минусы: много служебного шума; для 1-2 агентов это overkill.

## Рекомендация Codex

Вариант **B**: добровольный heartbeat как следующий эксперимент, но не обязательный протокол. Обязательным его стоит делать только при 3+ одновременно работающих агентах или при долгих задачах, где важно видеть ETA.

## Итог

Принят вариант **B**. Решение перенесено в `decisions/D-012.md`; реализация — T-028.
