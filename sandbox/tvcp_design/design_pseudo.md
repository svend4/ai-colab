# SEMANTIC-DIFFUSE — псевдо-диффузия для ТЕКСТА (угол A: механизм)

> Перенос `pkg/pseudo` (TVCP) на текст/смысл. Детерминированно, офлайн, в терминале.
> Грунт — прочитанный код: `pkg/pseudo/grid.go` (`Grid.rect`→`upscaleBilinear`→`blur`→`DiffuseFrames`),
> `pkg/scene/scene.go` (`Op` box/text/rect/disc), `pkg/sketch/sketch.go` (named-color seed), `docs/SHARED_WORLD.md`
> (raymeet: Region~100Б, Pose 44Б, «смысл не пиксели»), `ai/BRAIN_PROTOCOL.md` (tvcp-ai/1: `kind:"image"`/`grid`).

## 0. Прямое соответствие примитивов (что на что ложится)

| TVCP / `pkg/pseudo` (пиксели) | SEMANTIC-DIFFUSE (смысл/текст) |
|---|---|
| `Grid.Rows [][]string` (12×8 цветовых токенов) | `TopicGrid.Rows [][]Seed` — 2D-сетка тем: ячейка = заголовок + 2-3 семантических токена |
| цвет-токен `"navy"`/`#rrggbb` (имя в палитре) | seed-токен = `title` + `tags[]` + опц. одна `[[ссылка]]` (имя узла канона) |
| `resolve(pal, tok, def)` — токен→RGB | `resolve(corpus, seed, ⌀)` — seed→FTS-контекст (через `canon_index.py`) |
| `rect()` — выровнять рваную сетку, pad последним цветом | `rect()` — выровнять сетку карточек, pad-ячейка = «(пусто)» |
| `upscaleBilinear(src, sw,sh, ow,oh)` | `elaborate()` — каждая ячейка разворачивается в под-сетку под-карточек, соседи интерполируют контекст |
| `blur(src, radius, passes)` — box-blur, размывает к среднему соседей | «смысловой blur» — обобщение: тело карточки = общий гист, заимствует токены у соседей (см. §3) |
| `DiffuseFrames(pxW,pxH, steps)` — шум→цель, blur затухает | `RevealFrames(steps)` — гист→детали, обобщение затухает (см. §6) |
| `frameNearest` (мозаика) vs `frameSmooth` (мягко) | `viewCoarse` (только заголовки-меню) vs `viewFine` (раскрытые тела) |
| `alpha = i/(steps-1)`, `noise.Blend(target, alpha)` | `alpha` = глубина раскрытия; `blendText(gist, detail, alpha)` (см. §6) |
| `Render→terminal.Frame` / `Image→image.Image` | `render→2D-карто-канва (ANSI/HTML <details>)` |

Ключ: в `grid.go` модель эмитит КРОШЕЧНУЮ сетку (10-12 имён цветов на строку), а ВЕСЬ детальный растр —
детерминированная функция от неё (`upscaleBilinear`+`blur`, без GPU, `rng.NewSource(1)`). Делаем ровно это для
текста: модель/автор эмитит крошечную сетку seed'ов, детальный ТЕКСТ — детерминированная функция от seed'ов + корпуса.

## 1. Объект: `TopicGrid` — семантический «сид» (аналог `Grid`)

```jsonc
{ "kind": "semgrid", "cols": 4, "rows": 3,
  "grid": { "rows": [
    [ {"t":"Транспорт","g":["смысл-не-пиксели","UDP"],"ref":"[[SHARED_WORLD]]"},
      {"t":"Сид","g":["сетка-тем"],"ref":null},
      {"t":"Раскрытие","g":["coarse→fine"]},
      {"t":"Кадры","g":["denoise"]} ],
    [ {"t":"CRDT-канва"}, {"t":"Presence"}, {"t":"Оракул-кворум"}, {"t":"MVP"} ],
    [ {"t":"Риски"}, {"t":"Детерминизм"}, {"t":"Палитра-тон"}, {"t":"Ссылки"} ]
  ] } }
```

- Ячейка = `Seed{ t:title, g:gist-tags[], ref:[[link]]? }`. Это «самая маленькая картинка, какую может выдать
  текст-модель» — прямой аналог комментария в `grid.go` про color-grid. Семантически плотная, ~30-60 байт/ячейка.
- ПОЛОЖЕНИЕ кодирует отношение: строка 0 = общий слой меню, ниже = специализация; столбец = тема. Это даёт 2D —
  «средний путь» между 1D-чатом (одна ось — время) и 3D-видео (три оси — у текста нет глубины).
- Палитра-аналог: `palette` preset (`dawn/dusk/neon` в `pseudo`) → **тон/регистр** (`brief/normal/deep`,
  `ru/en`, `formal/casual`). Один параметр меняет «настроение» всего раскрытия, не трогая seed'ы — как `Request.Palette`.

`rect()` для текста: нормализует рваную сетку в прямоугольник; пустые ячейки = `Seed{t:"·"}` (аналог `defGridColor`),
рваный хвост строки расширяется последним seed'ом (как `extend the last color to pad ragged rows`).

## 2. `elaborate()` — «upscale» сида (аналог `upscaleBilinear`)

`upscaleBilinear` берёт грубую сетку sw×sh и интерполирует в ow×oh: каждая выходная ячейка =
билинейная смесь 4 соседних исходных цветов (`top=src[y0][x0].Blend(src[y0][x1],tx); bot=...; dst=top.Blend(bot,ty)`).

Текстовый аналог — **разворот ячейки в под-сетку с интерполяцией контекста соседей**:
1. Каждая seed-ячейка `(x,y)` разворачивается в блок под-карточек `k×k` (k=апскейл-фактор = желаемая_детализация / размер_сетки, как `pxW/sw`).
2. Под-карточка на дробной позиции `(fx,fy)` детерминированно собирает свой контекст из 4 угловых seed'ов:
   токены берутся в пропорции `(1-tx)(1-ty) : tx(1-ty) : (1-tx)ty : tx·ty` — т.е. под-карточка у границы двух тем
   наследует токены ОБЕИХ (плавный семантический градиент, не резкая граница). Это буквальный `Blend(a,b,t)` на
   мультимножествах токенов вместо RGB-каналов.
3. Тело каждой под-карточки = детерминированный retrieval: `canon_index.FTS(seed.t + seed.g + interp_tokens)` →
   top-N сниппетов, отсортированных стабильно (BM25, затем по id) → склейка. Без модели вообще — чистый retrieval
   (аналог `brain.Reference` painting с `no model at all`). С моделью — то же как промпт-контекст (детерминизм
   через `temperature=0`, фикс. seed).

Итог: грубая 4×3 сетка тем → плотная, например, 16×12 сетка карточек, где границы тем плавно перетекают.

## 3. «Текстовый blur» — обобщение (аналог `blur`/`blurAxis`)

`blurAxis` заменяет каждый пиксель средним по окну `±radius` вдоль оси (сначала гориз., потом верт., `passes` раз);
`blur` затухает к среднему — высокие частоты (детали) гаснут, остаётся низкочастотная форма (общая композиция).

**Текстовый blur = ОБОБЩЕНИЕ карточки до её окрестности:**
- частоты ↔ уровни детализации: «высокая частота» = специфические факты/числа/имена; «низкая частота» = тема/тезис.
- box-blur по карто-сетке: тело карточки `(x,y)` на радиусе `r` = усреднённый/общий тезис её и `±r` соседей.
  Конкретно (детерминированно, без модели): взять заголовки+gist-токены окна `(2r+1)×(2r+1)`, оставить токены с
  частотой ≥ половины окна (это и есть «среднее по каналам» из `blurAxis`: rs/gs/bs/n → здесь tf по токенам/n),
  выдать как одну обобщающую строку. Сепарабельность (как `blurAxis(...,horizontal)` потом вертикально) сохраняем:
  сначала обобщаем по строке (одна тема-полоса), потом по столбцу (один слой-абстракции) — дёшево, O(n·r).
- `radius` большой → сильное обобщение (видно только меню верхнего уровня = `frameNearest`-мозаика тем);
  `radius`→0 → карточки резкие, каждая = свои детали. То есть `radius` — это РУЧКА «общее↔частное».

## 4. «denoise-шаг» — уточнение/раскрытие (обратное blur)

В `DiffuseFrames` denoise идёт неявно: `alpha` растёт 0→1, `noise.Blend(target,alpha)` подмешивает всё больше цели,
а `rad=maxRad*(1-alpha)` — blur ГАСНЕТ. Для текста разворачиваем это в явный шаг:

**denoise-шаг(карточка) = заменить обобщённый гист на следующий уровень детализации = уменьшить radius на 1.**
- Стартовое состояние = «шум» = карточка с ПУСТЫМ/максимально-обобщённым телом (только заголовок; высокий blur).
  Аналог `noise` в `DiffuseFrames` — НЕ случайные байты (текст-шум нечитаем), а максимальное обобщение
  (placeholder-гист «…»). Это честная адаптация: «шум» для смысла = отсутствие специфики, а не белый шум.
- Каждый denoise-шаг: `radius -= Δ`; пере-`elaborate` с меньшим радиусом обобщения → проявляются под-карточки и факты.
- Сходимость гарантирована и детерминирована: за `steps` шагов `radius:maxRad→0`, тело сходится к полному retrieval
  (`viewFine`). Никакой стохастики, кроме фикс. `rng.NewSource(1)` для порядка раскрытия (если нужен «scan»-эффект).
- Прогрессивное раскрытие «меню→детали» = именно последовательность denoise-кадров: кадр 0 = меню заголовков
  (как `view_html.py` свёрнутые `<details>`), последний кадр = всё развёрнуто. Это уже есть в нашем `view_html.py`
  как `<details>` — диффузия делает это ПОТОКОВЫМ и ПОКАДРОВЫМ.

## 5. Wire-format: «смысл, не пиксели» для текста

Как raymeet шлёт `Region`~100Б и `Pose` 44Б, а кадр пере-собирается локально, — мы шлём `TopicGrid` (десятки байт/
ячейка), а ВЕСЬ детальный текст пере-собирается локально из общего корпуса (`canon_index.py` SQLite/FTS5 на каждой машине).

| Идёт по проводу | Что это | Размер |
|---|---|---|
| `TopicGrid` (сид-сетка) | 2D-сетка seed'ов = «meaning of the page» | ~30-60 Б × ячейка, один раз |
| `RevealStep{cellId, radius}` | команда «уточни эту карточку на шаг» | ~12 Б за тик (аналог `Pose` 44Б) |
| `Focus{cellId}` (= текст-`Pose`) | где курсор/вьюпорт участника | ~8 Б, presence |
| правка тела (со-автор) | `crdt_merge` дельта на карточку | строка |

Детальные тела НЕ идут по проводу: они = детерминированная `elaborate(seed, локальный_корпус)`. Это и есть тезис
TVCP, применённый к тексту: «A walker who explores for an hour received a trickle of descriptions and reconstructed
every pixel locally» → читатель получает сид-сетку + reveal-команды и пере-собирает весь текст локально из канона.
Условие корректности (как в raymeet host=single author, idempotent apply): корпус+индекс должны совпадать у всех →
детерминизм `elaborate` обязателен (фикс. сортировка BM25→id, фикс. seed). При расходящихся корпусах — слать diff корпуса.

## 6. Анимация потока — `RevealFrames` (прямой аналог `DiffuseFrames`)

```
func RevealFrames(grid TopicGrid, steps int) []TextFrame {
    target := elaborate(grid, radius=0)        // полный текст (аналог blur(target,maxRad) — но цель резкая)
    maxRad := gridDiag/2                         // как maxRad := pxW/sw/2
    for i := 0; i < steps; i++ {
        alpha := i/(steps-1)                     // 0=меню .. 1=детали   (идентично DiffuseFrames)
        rad   := int(maxRad*(1-alpha))           // обобщение ГАСНЕТ   (идентично rad=maxRad*(1-alpha))
        frame := elaborate(grid, radius=rad)     // blur(card) на текущем радиусе
        frames[i] = blendText(coarseGist, frame, alpha)  // аналог noise.Blend(target,alpha) на УРОВНЕ ТОКЕНОВ
    }
}
```

- `blendText(gist, detail, alpha)` на токенах: показывай долю `alpha` под-карточек раскрытыми (round-robin по
  фикс. порядку `rng.NewSource(1)`), остальное — гистом. При `alpha=0` вся сетка = меню; при `alpha=1` = полный текст.
  Это посимвольный/поблочный аналог RGB-`Blend`: вместо смешения каналов — доля раскрытых под-карточек.
- Каждый `TextFrame` рендерится в терминал как 2D-карто-канва: `scene.Op{op:"box"}` рамка карточки +
  `scene.Op{op:"text"}` заголовок + (раскрытые) строки тела. Кадры печатаются с курсор-home (ANSI), как видео-кадры —
  получается «текст течёт»: меню проявляется в детали покадрово. Для HTML — последовательность `<details open>`.
- ВАЖНО (предел аналогии): для текста ценен не высокий FPS (читаешь один раз), а событийность — пере-рендер кадра
  ТОЛЬКО когда участник жмёт «глубже»/«меню» или приходит `RevealStep` по проводу. `RevealFrames` — это лента
  переходов (wipe/раскрытие), а не тактовый видеопоток.

## 7. Много-агентность (MMORPG / сетка-камер) — поверх механизма

raymeet даёт скелет: `Region`(автор-кусок)+`Pose`(presence)+`ChatSync`(dedup)+host-fanout. Отображение на текст-сетку:
- Канва `TopicGrid` = общий мир/канон. Каждый участник (человек ИЛИ tvcp-ai/1 агент) владеет одной/несколькими
  ячейками = «камера наблюдения» в сетке. Его «аватар» = текущая раскрытая карточка (raymeet «see each other»).
- `Focus{cellId}` = текст-`Pose`: кто на какую карточку смотрит (дешёвый presence, как 44Б Pose).
- Агенты общаются МЕЖДУ собой и с людьми = карточки ссылаются (`ref:[[link]]`); агент «отвечает», авторствуя/
  раскрывая соседнюю ячейку (`elaborate` соседа). Ребро `[[link]]` = канал диалога.
- Конкурентная правка общей канвы СЛОМАЕТ host-last-writer raymeet → подключаем НАШ `crdt_merge`: OR-Set add-wins
  на МНОЖЕСТВО ячеек (конкурентные новые карточки от разных агентов все выживают, remove через tombstone), LWW/diff3
  на тело ячейки. Это технический хребет много-агентности; диффузия — UX поверх.
- Оракул-кворум: «кто диффундирует» = LLM-оракул на `elaborate`. Высоко-ставочные карточки раскрывают ≥2 мозга
  (tvcp-ai/1 за разными `BRAIN_URL`) с ВИДИМОЙ дивергенцией (пометка на карточке через `oracle_quorum.py`), не молча
  мёржить. Граница: РАСКЛАДКА/радиус/порядок — детерминированы (grid.go-стиль); только семантика тела зависит от оракула.

## 8. Маппинг на НАШ репозиторий (что переиспользуем / что строим)

- `tools/canon_index.py` (SQLite/FTS5) = `resolve`/retrieval-движок для `elaborate` — seed→контекст детерминированно.
- `tools/view.py` (`slice_ids` по графу `[[link]]`) = выбор подсетки тем для `TopicGrid`; `view_html.py` (`<details>`
  меню→детали) = УЖЕ прогрессивное раскрытие, диффузия делает его покадровым/2D-пространственным.
- `tools/crdt_merge.py` + `seq_merge.py` = OR-Set ячеек + LWW/diff3 тел для общей много-агентной канвы.
- `tools/thread_runner.py` (тред→FTS-контекст→локальная модель/offline-синтетик→append) = готовый «мозг» для одного
  denoise-шага: вход = seed+radius, выход = раскрытое тело; offline-синтетик = режим «no model» (как `brain.Reference`).
- `tools/oracle_quorum.py` + `consensus_by_meaning.py` = кворум на спорное раскрытие, видимая дивергенция.
- НОВОЕ: `tools/text_diffuse.py` — `TopicGrid` тип + `rect/elaborate/blur/denoise/RevealFrames`; рендер в ANSI-карто-
  канву и в HTML. MVP однопользовательский: срез канона → 2D-сетка карточек → покадровое coarse→fine раскрытие.

## 9. Риски (честно)
- «Шум» для текста не белый шум — пришлось переопределить старт как максимальное ОБОБЩЕНИЕ; аналогия с `noise`
  частична (это эвристика, не математика). Защитимо, но не буквальный изоморфизм с `DiffuseFrames`.
- Детерминизм `elaborate` держится только при идентичном корпусе+индексе у всех узлов; расхождение корпуса ломает
  «пере-сборку локально» → нужен sync/diff корпуса (раздувает wire-format сверх 100Б-идеала raymeet).
- Семантика тела = LLM-оракул = захватываемая единая точка; смягчение (кворум) дорого и само опирается на оракулов.
- FPS-метафора слабая: для текста поток событийный, не тактовый — если продавать как «видео из текста», легко
  переобещать; честно — это 2D-параллель + прогрессивное раскрытие + смысл-провод.
- box-blur по токенам (tf≥окно/2) — грубое обобщение; на коротких/разнородных корпусах даст бедный гист.
