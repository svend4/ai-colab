# TextScene Cards — «полу-диффузия текста как 2D-сетка карточек»

## 0. Одна фраза
1D-чат строит строку за строкой; ТВ генерирует 3D-кадр. Средний путь — **2D-канва
из box-карточек** (`scene.Op{op:"box"}`), где каждая карточка = узел графа «от общего
к частному», а грубый семантический сид **проявляется** в детальные карточки тем же
детерминированным механизмом, что `pkg/pseudo` проявляет цветовой грид в картинку
(`upscaleBilinear`→`blur`), только над СМЫСЛОМ, а не пикселями.

Ключевое наблюдение: `scene.go` УЖЕ умеет рисовать карточку. `op:"box"`
(`f.DrawBox`) = рамка визитки; `op:"rect"`/`op:"vgradient"` = фон/шапка; `op:"text"`
= строки внутри. Сложить N таких box-ов в регулярную решётку = «текстовая сцена».
Ничего нового в рендере не нужно — нужен **слой раскладки** поверх существующего
draw-DSL и **детерминированный движок проявления** поверх существующего pseudo.

---

## 1. Карточка = узел канона (структура `Card`)

Карточка — это `view.py`-узел (`{id, path, body, links}`), упакованный в прямоугольник.

```json
{
  "id": "T-031",
  "summary": "Раскладка 2D-карточек поверх scene draw-DSL",   // = view._gist(body)[:90]
  "body":    "…полный текст узла…",                            // раскрывается при denoise
  "links":   ["D-030","T-029"],                               // рёбра графа = стрелки навигации
  "level":   0,                                               // 0=меню/общее … 3=деталь
  "weight":  0.82,                                            // важность → размер/порядок (как Grid-сид)
  "tag":     "task"                                           // task/decision/topic → цвет рамки
}
```

`summary` берётся ровно как в `view_html.py`: `_view._gist(n["body"])` → первая
содержательная строка, обрезанная до 90 симв. Это «лицо» карточки (свёрнутый
`<summary>`). `body` — это `<pre>` внутри `<details>`, проявляется при раскрытии.
`links` фильтруются по видимому подграфу (`[l for l in links if l in have]`) —
1:1 как уже сделано в `compile_html`.

## 2. Сетка карточек = `Grid`, но ячейка несёт СМЫСЛ, а не цвет

`pseudo.Grid` — это `Rows [][]string`, где токен = имя цвета. Здесь ровно та же
форма, но токен = **id карточки** (или пусто). Это «текстовый сид сцены»:

```json
{
  "format": "textscene",
  "cols": 4, "rows": 3,
  "seed": { "rows": [
    ["T-031", "D-030", "",      ""     ],
    ["T-029", "T-031", "D-030", ""     ],
    ["topic-cards", "",  "",     "T-029"]
  ] },
  "palette": "dusk"
}
```

Это прямой аналог JSON из `PSEUDO_IMAGE.md` (грид цветов), но ячейки — узлы.
Ragged-строки нормализуются точно как в `Grid.rect()` (последний токен растягивает
ряд / пустые → фон). Раскладка детерминирована: одинаковый seed → одинаковая сетка.

### Раскладка ячейки → пиксели терминала
Каждая непустая ячейка `(gx,gy)` отображается в прямоугольник карточки:
```
CARD_W = floor(canvas.W / cols)        // напр. 96/4 = 24 кол. на карточку
CARD_H = floor(canvas.H / rows)        // напр. 30/3 = 10 строк
x = gx*CARD_W, y = gy*CARD_H
```
и компилируется в фиксированный набор `scene.Op` (см. §3). `canvas.W/H` зажаты
`RenderScene` в 400×200 — это и есть наш предел сцены (≈ 16 карточек 24×10 на экран).

## 3. Компиляция карточки в draw-DSL (детерминированно, без новых op-кодов)

Функция `card_to_ops(card, x, y, w, h, open) -> []scene.Op`. Использует ТОЛЬКО
существующие op из `scene.go`:

```
1. рамка:   {op:"box",  x,y,w,h, fg: TAG_COLOR[card.tag]}          // f.DrawBox
2. шапка:   {op:"vgradient", x:x+1,y:y+1,w:w-2,h:1, from:hdr,to:hdr2}// f.SetBlock-полоса
3. id:      {op:"text", x:x+2,y:y+1, s:card.id,      fg:white}      // f.SetBlock по рунам
4. summary: {op:"text", x:x+2,y:y+2, s:wrap(card.summary, w-4)[0],  fg:fg}
   …и далее по строкам перенесённого summary, пока level раскрытия позволяет…
5. рёбра:   {op:"text", x:x+2,y:y+h-2, s:"→ "+",".join(card.links), fg:link}
```

`wrap()` — детерминированный жадный перенос по словам в ширину `w-4` (чистый Python,
без зависимостей). Раскрытие управляется параметром `open`/`level`:
- **свёрнуто (level→0):** рисуем рамку + шапку + `id` + 1 строку `summary` + рёбра.
  Это «меню» — `<summary>` из `view_html.py`.
- **раскрыто (level↑):** добавляем строки `body` (перенесённые), карточка «вырастает»
  вниз или открывается в фокус-панель. Это «деталь» — `<pre>` внутри `<details>`.

Прогрессивное раскрытие «меню→детали» из view_html.py становится **denoise-шагом**:
не «показать/скрыть», а «сколько строк смысла проявить».

## 4. Полу-диффузия текста: сид → проявление (механизм, 1:1 с `pkg/pseudo`)

`pseudo` берёт грубый 12×8 грид и проявляет: `upscaleBilinear` (сгладить) →
`blur` (3 прохода) → `DiffuseFrames` (шум→цель, blur затухает с alpha 0→1). Мы
переносим ТРИ операции на смысл, сохранив детерминизм:

| pseudo (пиксели) | TextScene (смысл) | что делает |
|---|---|---|
| coarse `Grid.Rows` (имена цветов) | seed-сетка id карточек + веса | минимальный «сид» сцены |
| `upscaleBilinear` (12×8 → 80×36) | **layout-upscale**: разложить ячейки в box-карточки, распределить место по `weight` | грубая сетка → точные прямоугольники |
| `blur` (3 прохода box-blur) | **disclosure-blur**: на ранних шагах у карточки виден ТОЛЬКО id+summary; «резкость» = сколько строк body проявлено | размытая карточка = только заголовок |
| `DiffuseFrames` alpha 0..1 (noise→target) | **denoise-шаги**: шаг t раскрывает карточки в порядке `weight` (важные первыми), добавляя по `body`-строке | анимация «проявления» сцены |

### Алгоритм проявления (детерминированный, seedable)
```
elaborate(seed_grid, brain, steps):
  scene = layout_upscale(seed_grid)          # все карточки в режиме summary-only (level 0)
  order = sort(cards, key=-weight, tiebreak=id)   # детерминированный порядок (как rand.NewSource(1))
  for t in 1..steps:
     budget = ceil(len(order) * t/steps)     # alpha = t/steps, как в DiffuseFrames
     for card in order[:budget]:
        if card.body is None:                # лениво «дорисовываем» смысл
           card.body = brain.kind="scene"(prompt=card.summary, ctx=neighbors(card))
        card.level = min(card.level+1, MAX)  # +1 строка проявления = blur затухает
     yield render(scene)                      # кадр t: scene.RenderScene(compile(scene))
```
- **Сид** может прийти от: (а) `view.slice_ids(canon, seed, depth)` — обход графа
  ссылок (офлайн, без модели); (б) `canon_index.py` FTS5-топ-k по запросу →
  k карточек; (в) `brain` tvcp-ai/1 `kind:"scene"` (модель эмитит seed-грид id+вес).
- **Проявление** body карточки: офлайн = взять `n["body"]` из канона (детерм.);
  online = `thread_runner.py` зовёт локальную модель/синтетик с FTS-контекстом соседей.
- Полностью детерминированно при фиксированном seed-гриде и офлайн-источнике —
  как `DiffuseFrames(rng=rand.NewSource(1))`. Без GPU, чистый CPU/терминал.

### Что НОВОГО vs pseudo
`pseudo` сглаживает цвет (непрерывный). Смысл дискретен — нельзя «лерпать» текст.
Поэтому «bilinear» здесь = распределение МЕСТА (layout), а «blur→sharpen» =
**число проявленных строк** (квантованная резкость). Это честная адаптация, не
метафора: те же три стадии, дискретизированные под текст.

## 5. Что идёт по проводу: «смысл, не пиксели» для текста

Как `raymeet` шлёт `Region` (~100–300Б, сцен-граф) и `Pose` (44Б), а не кадры —
TextScene шлёт **сид + дельты раскрытия**, а карточки пере-собираются локально:

| Направление | Payload | Размер |
|---|---|---|
| host → all | `SceneSeed` (cols,rows, сетка id+вес, palette) | ~80–200Б, раз на сцену |
| any → all | `Cursor` (focus card id + level) — аналог `Pose` | ~16Б/тик |
| host → all | `CardDelta` (id, body-патч, новый level) при проявлении | строка, ack-healed |
| any → host | `ack` (have-set проявленных карточек) | ~1/с, крошечный |

`body` карточки НЕ дублируется по проводу, если получатель уже имеет узел в
локальном каноне — шлётся только `id` (как `kind:mesh` в raymeet шлёт имя меша, а
не геометрию). «Сотня копий карточки стоит одно имя». Локальная пере-сборка:
`compile(seed) → scene.RenderScene → terminal.Frame`, либо `view_html.compile_html`
для HTML-варианта. Bandwidth-профиль как у TEXT_CHAT (<1КБ/с), но переносит 2D-сцену,
а не 1D-строку.

### Wire-схема (компактная, версионируемая)
```json
{ "protocol":"tvcp-ai/1", "kind":"scene",
  "scene_seed": { "cols":4,"rows":3,"palette":"dusk",
                  "cells":[{"id":"T-031","w":0.82,"gx":0,"gy":0}, …] },
  "deltas": [ {"id":"T-031","level":2,"body_ref":"canon:T-031"} ] }
```
`kind:"scene"` уже есть в `tvcp-ai/1` (Response.scene). Расширяем `state`-форму, не
ломая протокол — любой мозг (Ollama/OpenAI/reference) эмитит `scene_seed`.

## 6. Навигация (терминал, детерминированная, без мыши)

Курсор по сетке карточек — как WASD-walker в `raymeet`, но по 2D-решётке тем:

| Клавиша | Действие | Аналог в репо |
|---|---|---|
| `h/j/k/l` | курсор по сетке (←↓↑→) к соседней карточке | `raymeet` w/s/a/d |
| `Enter`/`o` | denoise-шаг на фокус-карточке: +1 уровень проявления body | `<details>` open / `g` grow region |
| `Esc`/`u` | свернуть назад (−1 уровень) | `<details>` close |
| `Tab` | прыгнуть по первому `link` карточки (обход графа) | `view.slice_ids` BFS |
| `/` | строка-запрос → `canon_index` FTS5 → новый seed-грид | TEXT_CHAT `/`-команда |
| `g` | «вырастить» сцену: добавить соседей фокуса как новые карточки | `rayexplore` `g` |

Фокус-карточка рендерится в режиме full-body (level=MAX) в выделенной зоне или
растягивается на месте; остальные остаются в summary-режиме. Это «меню всегда
видно, деталь раскрывается по месту» — прямой перенос progressive disclosure.

## 7. Много-агентно / много-участников (MMORPG-сетка камер)

Каждый участник (человек ИЛИ ИИ-агент) владеет своей **зоной карточек** — как
камера наблюдения в сетке мониторинга. Канва делится на «контуры»:

```
┌──────────────┬──────────────┐
│ AGENT-builder│  HUMAN-stefan │   ← каждая зона = под-сетка карточек владельца
│  (proposes   │  (reviews,    │
│   T-* cards) │   opens/edits)│
├──────────────┼──────────────┤
│ AGENT-redteam│  AGENT-oracle │   ← агенты болтают карточками между собой
│ (▲ flags на  │  (кворум:     │     И с людьми, в одной общей сцене
│  чужих карт) │   ✓/✗ метки)  │
└──────────────┴──────────────┘
```

- **Видимость:** все видят сетку (общий `SceneSeed`), но право `denoise`/`edit`
  карточки = `ownership.py`/`permissions` нашего репо. Агент-redteam НЕ редактирует
  чужую карточку, а **прикрепляет** к ней дочернюю карточку-флаг (`link` ребро,
  `tag:"flag"`). Видимый кворум = ряд карточек-вердиктов оракулов рядом с предметом
  (смягчение «оракул-проблемы»: судья не один и виден).
- **Агент↔агент:** агенты общаются, роняя карточки в общую сетку (как `/place`
  объекта в raymeet — карточка едет как обычная `CardDelta`, ack-healed). Это и
  есть «текстовая видеосвязь»: каждый агент = камера, его поток = поток карточек.
- **Конфликты раскрытия/правок** двух участников по одной карточке разрешаются
  `crdt_merge.py`: поля карточки (summary/tag/level) — **LWW** (last-writer-wins по
  ts); `links` — **OR-Set add-wins** (рёбра только добавляются, никто не «теряет»
  связь); тело — `seq_merge.py` diff3 построчно. Никакого центрального лока:
  каждый правит свою копию, мёрж по смыслу (как `git_reconcile.py` merge-driver).
- Сессия пишется/реиграется (`raymeet -record`): timeline сидов+дельт+курсоров =
  крошечный файл, «пере-смотреть как рос разговор-сцена».

## 8. Связка с HTML-веткой (view_html.py)

Два рендера одного `SceneSeed`, обе ветви уже частично есть:
- **Терминал:** `compile(seed) → []scene.Op → scene.RenderScene → terminal.Frame`
  (ANSI). Карточки = box-сетка.
- **HTML:** `compile_html(canon, ids)` УЖЕ даёт `<details>`-каскад. Доработка:
  обернуть карточки в CSS-grid (`display:grid;grid-template-columns:repeat(cols,1fr)`),
  чтобы `<details>` легли 2D-плиткой, а не 1D-столбцом. `<summary>` = свёрнутая
  карточка (level 0), раскрытие `<details>` = denoise-шаг. Самодостаточный файл,
  без сервера/JS (нативная сворачиваемость) — ровно цель P17 из view_html.

Один `SceneSeed` → и терминал, и HTML. «Меню→детали» = и `box`-карточка свёрнута,
и `<details>` свёрнут — одна модель, два бэкенда (как `pseudo.Render`→Frame vs
`spec.Image`→image.Image).

## 9. Минимальный реализуемый срез (MVP, офлайн, детерминированно)

1. `tools/textscene.py`:
   - `seed_from_slice(seed_id, depth)` → `SceneSeed` (через `view.slice_ids`,
     `weight = 1/(1+dist_from_seed)`, раскладка змейкой в `cols`-сетку).
   - `card_to_ops(card,x,y,w,h,level)` → список dict-ов формы `scene.Op`
     (`box`/`vgradient`/`text`), JSON-совместимых с `scene.go`.
   - `compile_scene(seed, levels)` → `{width,height,bg,ops}` (draw-DSL JSON).
   - `elaborate(seed, steps)` → генератор кадров (denoise-проявление).
2. Терминал-превью без Go: `render_ascii(scene)` — мини-интерпретатор box/text/rect
   в плоский ASCII-буфер (для тестов и `--print`); «настоящий» рендер = отдать JSON
   в `scene.RenderScene`.
3. HTML: расширить `view_html.compile_html` флагом `--grid COLS` (CSS-grid обёртка).
4. Тесты (детерминизм): один seed → байт-в-байт один и тот же scene-JSON и ASCII
   (как `pseudo`-тесты сверяют кадры). Red-team: ragged-сетка, переполнение текста
   (clamp 400×200), пустые ячейки, циклы в links.

Всё на чистом Python поверх существующих `view.py`/`canon_index.py`/`crdt_merge.py`;
рендер-контракт — существующий `scene.go` (op-коды не добавляются).

## 10. Риски и честные пределы
- **Дискретность смысла ≠ непрерывность цвета:** «bilinear/blur» переносятся как
  layout+квантованная резкость, не как настоящая интерполяция. Это сознательная
  адаптация, а не буквальный pseudo.
- **Тесный терминал:** 400×200 / 24×10 на карточку = ≤16 карточек/экран. Большие
  графы требуют пагинации/зума (фокус-зона + миниатюра-сетка) — добавляет UI-сложность.
- **Перенос текста** в узкие box-ы рвёт длинные слова/код; нужен аккуратный `wrap`
  и режим «раскрыть в полноэкранную панель» для кода.
- **Оракул-проблема** не исчезает: кворум-карточки делают суждение ВИДИМЫМ, но всё
  ещё опираются на агентов-судей; виден, но не устранён.
- **Конкурентные denoise двух участников** по одной карточке: LWW по level может
  «прыгать»; смягчается тем, что level монотонен (берём max), а тело — diff3.
- **Дрейф сид↔канон:** если `body` правится в каноне после рассылки `body_ref`,
  получатель видит старое; лечится ack-have-set + ре-broadcast дельты (как ChatSync).
