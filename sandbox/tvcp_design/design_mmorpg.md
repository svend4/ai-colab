# GridRoom — «сетка камер наблюдения» для текста (MMORPG-контур TVCP)

> Угол C из триады. Берём `raymeet` (общий растущий мир, presence, «смысл не пиксели»:
> Region ~100Б, Pose 44Б) и заменяем 3D-сцену на **2D-сетку текстовых ячеек-«камер»**.
> Каждый участник (человек ИЛИ ИИ-агент) владеет своей ячейкой = живой полу-диффузионной
> карточкой. Хаб-звезда фанит дельты. Детерминированно, офлайн, в терминале.

## 0. Одна картинка

```
        GridRoom "alchemy-synth"  ·  tick 412  ·  6 occupants  ·  hub: alice
   ┌── col0 ─────────┬── col1 ─────────┬── col2 ─────────┐
row0│ ▣ alice  HUMAN │ ◆ smith  AGENT  │ ◆ critic AGENT  │
    │ Тезис ред-кмд  │ ░ proving…  ▓62%│ Контр-аргумент  │
    │ [3 details ▸]  │ seed→denoise    │ [2 details ▸]   │
   ─┼─────────────────┼─────────────────┼─────────────────┤
row1│ ◆ scout  AGENT  │ ▣ bob   HUMAN   │ · (empty cam)   │
    │ FTS-находки 5   │ смотрит col1    │   join here     │
    └─────────────────┴─────────────────┴─────────────────┘
   focus: bob→col1(smith)   chat: 2 new   ░=noise ▓=elaborating ▣=settled
```

Сетка = «стена камер наблюдения». Ячейка = чья-то текстовая «камера» (его рабочая
карточка). Ты ходишь не ногами (`w/s/a/d`), а **фокусом** по ячейкам; presence = «кто
на какую камеру сейчас смотрит». Это прямой перенос `raymeet`, где `Pose` (позиция+взгляд
в 3D) становится `CellPose` (какую клетку занимаю + на какую смотрю) — те же 44 байта класса.

## 1. Прямое соответствие raymeet → GridRoom

| raymeet (3D мир) | GridRoom (2D текст-сетка) | Что переиспользуем буквально |
|---|---|---|
| `Region` (~100–300Б, scene graph чанка мира) | `CellSeed` — полу-диффузионный сид ячейки (заголовок + 2D-грид тем + слоты) | ack-based reliability, persist, broadcast-once |
| `Pose` (44Б, позиция+взгляд) | `CellPose` (44Б: `cell=(r,c)`, `focus=(r,c)`, `caret`, `mode`) | loss-tolerant, заменяется next-tick |
| `ChatMsg` + `ChatSync` (id-tag, dedup) | межъячеечная реплика (адресная: cell→cell или cell→broadcast) | unique-id, dedup, hub re-broadcast |
| `EncodeEnv` (8Б, время суток на всех) | `RoomClock` (8Б: tick + denoise-фаза комнаты) | синхронный «общий такт» для детерминизма |
| region ack (have-set, ~1/с) | cell-version ack (какие версии сидов уже есть) | self-heal потерь и поздних входов |
| `-record walk.rrec` / `rayplay` | `-record room.grrec` / `gridplay` | таймлайн = аудит совещания агентов |
| `SaveWorld`/`LoadWorldFile` (мир = список Region) | `SaveRoom`/`LoadRoom` (комната = список CellSeed) | комната — это просто файл, копируется/делится |
| hub = единственный автор мира | hub = единственный **сериализатор** дельт и арбитр конфликтов | star-топология, guests фанятся от hub |

Ключ: в raymeet мир растёт регионами впереди идущего; здесь **комната растёт ячейками** —
агент `/join` создаёт новую камеру, hub бродкастит её сид всем, остальные реконструируют.

## 2. Полу-диффузия текста ВНУТРИ ячейки (механика «смысл→проявление»)

Каждая ячейка проходит ту же кривую, что `Grid.DiffuseFrames` (`pkg/pseudo/grid.go`):
`шум → цель`, blur затухает по `alpha = i/(steps-1)`. Только домен — СМЫСЛ, не RGB.

**CellSeed (что идёт по проводу, ~120–400Б)** — текстовый аналог `Grid.Rows` + scene-ops:
```json
{ "cell":[0,1], "owner":"smith", "kind":"agent", "v":7,
  "title":"Доказательство леммы 2",
  "topicgrid":[ ["цель","допущения"], ["шаг-индукции","контрпример?"], ["вывод","связь[[D-12]]"] ],
  "slots":{"цель":"…","шаг-индукции":"…"},          // заполненные слоты (могут быть пусты)
  "phase":0.62, "steps":5 }
```
`topicgrid` — это буквально `Grid.Rows`, но токены — НЕ цвета, а **темы/заголовки** (грубый
семантический сид «от общего к частному»). Локальный рендер делает текстовую версию
`upscaleBilinear`+`blur`:

- **upscale смысла** = `view.py`-обход: каждая тема-токен раскрывается в блок из канона
  (FTS-срез `canon_index.search(topic)` + `[[ссылки]]`), как bilinear «растягивает» 12×8 в 80×36.
- **blur смысла** = прогрессивное раскрытие `<details>` (наш `view_html.py`): на `phase=0.0`
  видны только заголовки (грубо/«размыто»), на `phase=1.0` все слоты развёрнуты (резко).
  «Blur fades out as picture sharpens» = `<details open>` открываются по мере `phase→1`.

**Шаги denoise** (детерминированно, без GPU), ровно как кадры `DiffuseFrames`:
```
phase 0.0  ▢ только title + topicgrid-заголовки (сид)         "░ noise"
phase 0.3  ▢ + 1–2 ключевых слота заполнены (FTS-retrieval)    "▒ rough"
phase 0.6  ▢ + остальные слоты, [[ссылки]] подтянуты            "▓ elaborate"
phase 1.0  ▣ финальный связный текст, details раскрыты          "▣ settled"
```
Кто двигает phase: владелец ячейки (агент через `thread_runner.step()` или человек правкой).
Каждый «шаг denoise» = один append в тред владельца (`thread_runner.run`) + bump `v`/`phase`
+ broadcast дельты. Детерминизм: `rng.NewSource(hash(cell, v))` — как `rand.NewSource(1)` в
`DiffuseFrames` — чтобы синтетик-фолбэк и порядок раскрытия слотов были воспроизводимы.

## 3. Что идёт по проводу — «смысл не пиксели» для текста

Картинку (раскрытый текст ячейки) НИКОГДА не шлём. Шлём сид/дельту; получатель пере-собирает
локально через `view.assemble` + `canon_index`. Бюджеты — как в raymeet-таблице:

| Направление | Payload | Размер | Аналог raymeet |
|---|---|---|---|
| owner→hub→all | `CellSeed` (новая/правленая ячейка) | ~120–400Б, раз на версию | `Region` ~100Б |
| owner→hub→all | `CellDelta` (только изменённые слоты + новый phase) | 20–120Б | region-патч |
| any→all | `CellPose` (где я + куда смотрю + mode) | 44Б/тик | `Pose` 44Б |
| cell→cell\|all | `Utter` (адресная реплика, id+dedup) | строка | `ChatMsg`/`ChatSync` |
| hub→all | `RoomClock` (tick + глоб. denoise-фаза) | 8Б | `EncodeEnv` 8Б |
| guest→hub | cell-version ack (have-set) | ~1/с | region ack |

Локальная пере-сборка: получив `CellSeed`, машина НЕ получает готовый текст — она сама
прогоняет `topicgrid`-токены через свой `canon_index` (FTS) и `view.slice_ids` до нужного
`phase`. Поэтому: один сид → у каждого участника свой локально-вычисленный, но семантически
тот же экран (как Region → каждый рендерит свои пиксели). «Walker за час получил трикл
описаний» → «участник за совещание получил трикл сидов/дельт, а развёрнутый текст пересобрал».

## 4. Много-агентность: люди + ИИ в одной сетке (MMORPG-контур)

**Участники однородны на проводе.** `kind:"human"|"agent"` — единственное отличие в `CellPose`.
Агент = `thread_runner`-цикл, привязанный к ячейке: его тред-файл `threads/<cell>.md`, его
front-matter `agent:`/`model:`/`task:` берётся из `CellSeed.title`. Человек = тот же слот,
двигаемый правкой руками. И тот, и другой публикуют `CellDelta` одинаково.

**Как агенты общаются между собой и с людьми — три канала:**

1. **Наблюдение (пассивно, дёшево).** `CellPose.focus` = на какую камеру смотрю. Агент
   `scout` может «смотреть» на `col1(smith)` и подмешивать его `CellSeed.slots` в свой FTS-контекст
   (`assemble_context` расширяется соседними видимыми ячейками). Это presence-driven контекст:
   агент видит ровно то, на что навёл фокус — не весь репозиторий (бюджет!).

2. **Адресная реплика (`Utter`).** `@smith про шаг-индукции: см [[D-12]]` — id-tagged, dedup
   (`ChatSync`), hub re-broadcast. Может быть human→agent, agent→human, agent→agent. Реплика —
   это НЕ правка чужой ячейки: это запрос/намёк, который владелец волен учесть на следующем
   denoise-шаге.

3. **Contract Net (`pkg/acl`, tvcp-ai §11) — кто берёт под-задачу.** Когда ячейка порождает
   под-вопрос (новый пустой слот `контрпример?`), hub шлёт `cfp` на этот слот. Агенты с
   подходящими `Capabilities` (`/v1/capabilities`: kinds/games) делают `propose` со стоимостью;
   hub `accept-proposal` дешёвейшему. Победитель **открывает новую ячейку** (`/join` рядом) и
   denoise-ит ответ. Это и есть «спавн моба под квест»: задача → новая камера → новый контур.

**Разрешение конфликтов (две правки одной ячейки/слота).** Hub — сериализатор; мердж — наш
`crdt_merge.py`:
- разные слоты → OR-Set add-wins (обе правки живут, как разные поля);
- один слот, оба правили → LWW по `(tick, owner)` ИЛИ diff3 (`seq_merge`), если слот — абзац;
- `phase` → max-wins (монотонно растёт, откат запрещён без явного reseed).
Поскольку владелец у ячейки один, конфликт редок (как в raymeet host — единственный автор
региона); CRDT нужен на со-правку человеком+агентом одной камеры.

## 5. Контуры / области видимости (что кому видно)

«Контур» = область сетки, разделяющая видимость и такт denoise (как раздельные «комнаты камер»).

- **Room** — вся сетка (= один `raymeet`-мир, один hub, один `RoomClock`). Файл `rooms/<id>.grrec`.
- **Cell** — ячейка-камера. Владелец 1. Видна всем в room (как avatar в raymeet виден всем).
- **Focus-cone** — `CellPose.focus`: на что наведён участник. Presence-список «кто смотрит на
  меня» рисуется в шапке ячейки (соц. сигнал: «3 агента смотрят на col1»).
- **Whisper-scope** — `Utter` с адресатом ≠ broadcast: видят только адресат и hub (приватный
  канал агент↔агент), остальным — только факт «idle reply» без тела (как позиционный голос
  в raymeet: дальше/из-за спины — тише; здесь «не адресовано тебе — не доставлено тело»).
- **Layer-видимость по phase.** Зритель с `view-budget` низким получает ячейки только до
  `phase≤0.3` (заголовки-меню); с высоким — полностью (`phase=1`). Это `view.py` frozen/live:
  live = пути+визитки (дёшево, грубый слой), frozen = инлайн тела (полный слой). Один и тот же
  сид рендерится на разную глубину под бюджет смотрящего — буквально progressive disclosure
  «меню→детали» на уровне сетевой видимости.

## 6. Presence

`CellPose` (44Б, тик): `{owner, cell:(r,c), focus:(r,c), caret:int, mode:enum, phase:f8}`.
- `mode ∈ {idle, denoising, typing, listening, bidding}` — статус-глиф в углу камеры
  (`◆ denoising ▓62%`), как `mode` аватара. loss-tolerant: пропал тик — взяли прошлый.
- presence-аватар = глиф+цвет владельца (детерминированный цвет = `hash(owner)`, как glowing
  avatars в raymeet). Человек ▣, агент ◆, пустая камера ·.
- «typing indicator» бесплатно: `mode=typing` + `caret` показывает, где владелец печатает —
  то, чего нет в нынешнем 1D `TEXT_CHAT.md` («Features Not Yet Implemented: typing indicators»).
- prune отключённых: нет `CellPose` N тиков → камера тускнеет «· (away)», сид остаётся (persist),
  как hub в raymeet «prunes the disconnected», но мир (ячейку) держит.

## 7. Рендер сетки в терминале (scene-ops = карточки)

Каждая ячейка рисуется `pkg/scene` ops — это и есть «карточки/визитки»:
- рамка камеры → `op:"box"` (x,y,w,h);
- заголовок+владелец+mode → `op:"text"`;
- denoise-прогресс-бар `▓62%` → `op:"rect"` с заливкой по `phase` (как `vgradient`-полоса);
- фон ячейки по статусу → `op:"rect"`/`"vgradient"` (settled=тёплый, noise=холодный).
Слабая модель эмитит не это, а высокоуровневый `CellSeed` (как `kind:sketch` vs `draw`);
клиент транслирует сид→scene-ops локально (ровно `sketch.ToScene`). Анимация «проявления»
ячейки при bump phase = текстовый `DiffuseFrames`: заголовки → размыто-серые плейсхолдеры
слотов → резкий текст (blur-фаза затухает = плейсхолдеры заменяются реальными строками).

## 8. tvcp-ai/1 интеграция (любой мозг за одним URL)

- Ячейка-агент = `HTTPBrain{URL}` за `BRAIN_URL`. denoise-шаг = `kind` запрос:
  `kind:"image"`+`format:"grid"` буквально возвращает `topicgrid` (сид!), а заполнение слотов —
  `kind:"draw"`/текст. То есть **наш `topicgrid` = `pseudo.Grid`, переиспользуем `kind:image`
  как «сгенерируй семантический сид ячейки».**
- `/v1/capabilities` → кто на что годен → Contract Net роутит `cfp` только подходящим (§11).
- discovery/registry/trust (`pkg/sign` HMAC): в комнату пускаем только агентов с подписанной
  registry-записью — «античит» для MMORPG (нельзя подсунуть мозг-самозванца под чужую камеру).
- `CheckResponse` (§8 conformance) — trust boundary: любой `CellSeed`/`CellDelta` от агента
  валидируется (рендерится в непустой кадр, слоты в границах) до применения. Как в raymeet
  «bad response can't crash the world — falls back to safe region»: плохой сид → safe-камера.

## 9. Маппинг на НАШ репозиторий (взять и применить)

| Компонент GridRoom | Наш существующий код | Что доделать |
|---|---|---|
| ячейка-тред агента, denoise-шаг | `tools/thread_runner.py` (`run`/`step`/`assemble_context`) | phase-поле в front-matter; шаг = bump phase |
| локальная пере-сборка сида в текст | `tools/view.py` (`slice_ids`/`assemble`, frozen/live) | вход = `topicgrid`-токены вместо seed-id |
| progressive disclosure меню→детали | `tools/view_html.py` (`<details>`) | open-уровень = `phase` |
| FTS-контекст под тему-токен | `tools/canon_index.py` (`search`, FTS5) | per-topic кэш, бюджет на ячейку |
| мердж со-правок ячейки/слотов | `tools/crdt_merge.py`+`seq_merge.py` (OR-Set/LWW/diff3) | слот-level гранулярность |
| hub-сериализация дельт | `tools/git_reconcile.py` (merge-driver) | live: in-proc арбитр поверх той же логики |
| комната как файл, record/replay | канон-файлы `rooms/*.grrec` (front-matter+тело) | формат таймлайна (тик→дельты) |

MVP офлайн без сети: hub, ячейки и participants — процессы/потоки на одной машине, «провод» =
очередь файлов `queues/` (уже есть `queues/outbox/`); `CellSeed`/`CellDelta`/`CellPose` — JSON-строки.
Детерминизм от seed → `go test`-зелёный аналог: прогон комнаты воспроизводим по `room.grrec`.

## 10. Что это даёт сверх нынешнего 1D-чата

1D `TEXT_CHAT.md` = одна лента строк, один автор за раз, нет presence/typing/групп. GridRoom =
2D-стена камер: N владельцев параллельно denoise-ят свои карточки, presence/typing/focus
бесплатно из `CellPose`, группы = контуры, «от общего к частному» = phase-раскрытие. Один такт
`RoomClock` синхронизирует всех — текстовый аналог «walk forward and the world unfolds on every
machine in lock-step», только разворачивается не геометрия, а СМЫСЛ.

## 11. Риски

- **Оракул-проблема при мердже семантики слота.** diff3 строк не ловит смысловой конфликт;
  смягчаем видимым кворумом (несколько агентов-судей в соседних камерах голосуют) — но это
  дороже и упирается в тот же один LLM-судья.
- **Бюджет пере-сборки.** Каждый участник локально гоняет FTS+view на каждый сид; при больших
  сетках (>16 камер) дорого. Нужен per-cell кэш и ленивый рендер только видимых/в-фокусе ячеек.
- **Phase-гонки.** Параллельные bump phase на одной ячейке без единого владельца → нужен строгий
  single-writer на phase (max-wins) + CRDT только на слоты.
- **Спам `cfp`/Contract Net.** Лавина под-вопросов → лавина новых камер; нужен лимит spawn/тик и
  TTL пустых камер (как prune disconnected).
- **Детерминизм vs живая модель.** Синтетик-фолбэк воспроизводим, но реальный `BRAIN_URL` —
  нет; record/replay фиксирует ВЫХОД (дельты), не процесс, — реплей честен, но не «пересчитать».
