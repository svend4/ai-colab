# Agent-cell MapReduce - экспериментальная модель большой группы

## Карточка идеи

- Назначение: проверить, как большая группа агентов может работать с большим информационным корпусом без перегрузки верхнего слоя.
- Статус: sandbox idea; не является принятой политикой.
- Риск: если запустить много пишущих агентов без synthesis gate, появится шум и конфликтующие правки.
- Безопасный режим: read-only исследование и отчеты в `queues/outbox/`.

## Модель

```text
3 scouts -> 1 observer -> 1 integrator
```

### Scout

- Читает ограниченный участок корпуса.
- Не меняет код.
- Пишет короткий отчет: факты, вопросы, предложения, ссылки.

### Observer

- Сравнивает 3 scout-отчета.
- Делит выводы на `consensus`, `divergence`, `needs-evidence`, `next-actions`.
- Не утверждает решения.

### Integrator

- Создает задачу, вопрос, proposed decision, tool patch или summary.
- Запускает проверки.
- Передает accepted-решения человеку или назначенному сборщику.

## Почему это полезно

Большое количество агентов полезно только до точки, где синтез дороже сбора. Эта модель ограничивает поток: много чтения снизу, мало утверждения сверху.

## Минимальный тест

1. Дать 3 scout-агентам одну тему, но разные документы.
2. Попросить observer выделить совпадения и расхождения.
3. Попросить integrator сделать один маленький проверяемый артефакт.
4. Измерить: стало ли меньше `unknown`, `open`, `untriaged outbox`.

## Условия перехода из sandbox в policy

- Два успешных read-only прогона.
- Один synthesis report без ручной расшифровки хаоса.
- Один action, который действительно был реализован и проверен.
- Отсутствие конфликтов с AGENTS.md и PROTOCOL.md.
