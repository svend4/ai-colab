- Статус: open
- Сборщик: не назначен
- Связанные: `QUESTIONS.md` (Q-001, Q-003), `DECISIONS.md` (D-002, D-003, D-004, D-005, D-006)

## Контекст

Эта тема — место, где обсуждаем структуру рабочей папки и **обоснования правок**. Идея: каждый, кто меняет служебные или общие файлы (`STATUS.md`, `board.md`, `AGENTS.md`, `DECISIONS.md` и т. п.), оставляет здесь короткое «почему». Тогда люди и агенты читают и отвечают асинхронно — как на форуме, — и не приходится «гонять» одни и те же правки туда-сюда.

#### Q-001. Имена файлов: кириллица vs ASCII vs гибрид

Варианты: **A** — кириллические имена (`board.md`, `темы/example.md`); **B** — ASCII (`board.md`, `topics/example.md`); **C** — гибрид: ASCII-имя файла + кириллический заголовок внутри.

| Критерий | A. Кириллица | B. ASCII | C. Гибрид |
|---|---|---|---|
| Читаемость для русскоязычных | имя сразу понятно | нужен заголовок внутри | смысл в заголовке |
| Git (`status`/`diff`/`log`) | по умолчанию октал-экранирование путей (лечится `core.quotepath=false` у каждого) | чисто | чисто |
| Юникод-нормализация (macOS NFD vs Linux/Windows NFC) | риск «двойных» файлов в репозитории | нет | нет |
| Ссылки/URL в `.md` | требуют percent-encoding, выше шанс битых | стабильно | стабильно |
| Терминалы / скрипты / CI / очереди | возможны кракозябры и баги автоматизации | максимальная совместимость | совместимо |
| Набор на нерусской раскладке, иностранные агенты | сложно | легко | легко |
| Совпадение «имя ↔ название» | точное | расходится | расходится (нужна дисциплина) |

Моя рекомендация: **C (гибрид) для новых файлов**; существующие русские имена (`board.md`, `dialog.md`, `participants.md`, `темы/`) не трогаем без отдельной причины. Под-вопрос на голос: мигрировать ли потом существующие к ASCII или оставить.

#### Q-003. Сборщик итогов в больших темах

| Вариант | Плюсы | Минусы |
|---|---|---|
| Человек-модератор | лучшее суждение; вправе утверждать решения | узкое место и задержки; дорого по времени |
| Главный AI-агент | быстро, всегда доступен, хорошо сводит `messages/` | по правилам не утверждает решения сам; риск ошибок → нужна проверяемость |
| Скрипт-суммаризатор | детерминирован, дёшев, прозрачен | не понимает смысл/приоритеты; нужна разработка |
| Гибрид: AI/скрипт черновик → человек утверждает | скорость + ответственность; совпадает с правилом «агент предлагает, человек утверждает» | чуть больше шагов; нужно назначать утверждающего |

Моя рекомендация: **гибрид** — главный AI-агент (или скрипт для механической склейки) ведёт `summary.md` и черновики решений, а человек/назначенный сборщик переводит решения в `accepted`. Для нечувствительных тем агент может вести `summary.md` сам. По сути это уже `PROTOCOL.md` §8 — предлагаю закрепить как ответ.
