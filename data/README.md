# data/

Рабочая область для корпуса данных и результатов обработки.

Важно: не импортировать реальные чувствительные документы, персональные данные или большие внешние папки без отдельной задачи и явного решения.

## Планируемая структура

```text
data/
  inbox/
  originals/
  copies/
  text/
  chunks/
  indexes/
  reports/
  audit/
  fixtures/
  workbench.db
```

## Правила

- `inbox/` — входящие файлы для обработки; не источник истины.
- `originals/` — неизменяемые копии оригиналов внутри проекта; без перезаписи.
- `copies/` — рабочие копии для нормализации; только через dry-run или явную задачу.
- `text/` — извлечённый текст; можно пересобрать из originals/copies.
- `chunks/` — фрагменты для поиска/RAG; generated.
- `indexes/` — FTS/BM25/vector/JSON индексы; generated.
- `reports/` — человекочитаемые отчёты.
- `audit/` — журналы операций драйверов.
- `fixtures/` — маленький безопасный тестовый корпус без персональных данных.
- `workbench.db` — будущая SQLite-память корпуса.

## Что можно писать автоматически

При наличии назначенной задачи:

- `text/`
- `chunks/`
- `indexes/`
- `reports/`
- `audit/`
- `fixtures/` с synthetic/test данными

## Что требует подтверждения

- импорт реальных документов;
- массовое копирование;
- перезапись `workbench.db`;
- anonymization;
- merge/split больших файлов;
- операции с внешними папками вне workspace.

## Запрещено по умолчанию

- удалять оригиналы;
- менять файлы вне проекта;
- хранить секреты;
- отправлять корпус во внешние API;
- запускать код из корпуса.

Источник правил: `docs/data-folder-plan.md`.
