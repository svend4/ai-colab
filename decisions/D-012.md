# D-012 — Heartbeat агентов: добровольный live-слой

- Контекст: D-011 дал динамический конвейер `pipeline.py next/status/done/fail/snapshot`. Следующий вопрос Q-012: нужен ли обязательный heartbeat/live-room.
- Решение: принять вариант **B** — добровольный heartbeat. Добавить команду `pipeline.py heartbeat`, но не требовать её для каждой задачи.
- Реализация: каждый агент пишет собственный файл `logs/heartbeat/<agent>.json`; агрегированные снимки генерируются в `LIVE.md` и `logs/heartbeat.json`.
- Причина: один общий live-файл с параллельной записью стал бы горячим файлом и источником конфликтов. Per-agent JSON сохраняет живость и снижает конфликтность.
- Когда пересматривать: если одновременно стабильно работают 3+ агента или появляются долгие задачи с ожиданием ETA, можно поднять вопрос об обязательном heartbeat.
- Статус реализации (advisory, 2026-06-23): принятое решение УЖЕ реализовано в `tools/pipeline.py` — команда `heartbeat` (cmd_heartbeat, строки 617-639), per-agent `logs/heartbeat/<agent>.json`, агрегаты `LIVE.md` и `logs/heartbeat.json` (write_heartbeat_views, HEARTBEAT_DIR/LIVE_MD/HEARTBEAT_JSON, строки 50-54). Линтер-правило в validate.py НЕ вводится: вариант B — добровольный, у него нет failure-условия, которое мог бы проверить валидатор; принудить «добровольность» = противоречить самому решению. Структурный контракт front-matter (id/status/title/last_verified) уже покрыт check_sources() для всех decisions/*.md.
- Tripwire пересмотра (advisory): если в LIVE.md/logs/heartbeat.json стабильно ≥3 одновременных агента ИЛИ появляются задачи с ETA-ожиданием — открыть вопрос об обязательном heartbeat (вариант C) и пере-сверить D-012 (last_verified).
