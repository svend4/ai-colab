# D-028 - Independent-first variants

## Контекст

D-017 уже принял принцип `fork-and-synthesize`: содержательные варианты полезны и не должны сниматься как дубли до сравнения.

Новая проблема тоньше: агент может увидеть похожую тему и остановиться слишком рано. Тогда второй вариант не раскрывает свой потенциал, и синтезатору нечего сравнивать. Одинаковое название, похожий вопрос или совпадение 30-50% текста ещё не доказывают, что это шумовой дубль. Это может быть другой случай, другой набор условий, другой риск, другое доказательство или другой путь реализации.

## Proposed decision

Принять уточнение `independent-first` для содержательных вопросов, архитектуры, методологии, ревью и больших предложений:

1. Если тема уже существует, агент не прекращает работу автоматически.
2. Агент создаёт отдельный вариант: `streams/<topic>/<timestamp-agent>/STREAM.md`, `topics/<topic>/forks/<agent>.md` или Level-1 worktree, если есть код/large/hot-file риск.
3. Агент сначала раскрывает свой вариант до состояния `ready-for-synthesis`: условия применимости, полный ответ, отличия, уникальный вклад, evidence, риски, вопросы, candidates для consensus/divergence.
4. Только после этого синтезатор сравнивает варианты.
5. Повторяющиеся пункты становятся candidates для общей ветки (`consensus` / `ratify-build`).
6. Различия, edge cases и несовместимые утверждения идут в `divergence-detail`, а не удаляются.
7. Шумовым дублем считается только вариант, который после synthesis не добавляет новых условий, evidence, risks, вопросов или реализации.

## Boundaries

Правило не применяется к механическим объектам, где должен быть один источник истины:

- id, индексы, generated files, locks, manifests, claim-файлы;
- автоматические snapshots;
- уже утверждённые accepted decisions без нового proposed decision.

Для механики остаётся обычный dedup/canonical-source.

## Consequences

- `tools/stream.py create` должен выдавать не пустую заметку, а структуру для независимого раскрытия варианта.
- `ready-for-synthesis` становится явным статусом готовности к сверке.
- `doc_synthesis.py`, `synthesis_helper.py`, `top.py synthesize-docs` должны читать такие варианты как input, но не принимать accepted-решения.
- Mainline получает только общий результат после synthesis/adoption; индивидуальные варианты остаются в streams как evidence/history.

## To accept

Перед переводом в `accepted` человек или назначенный integrator должен подтвердить:

1. срок, после которого незавершённый вариант считается stale;
2. минимальные поля для `ready-for-synthesis`;
3. кто имеет право ставить `adopted`, `superseded`, `rejected`;
4. нужно ли сделать strict-lint для stream-пакетов;
5. когда worktree обязателен вместо Markdown stream.
