## 0. Дисциплина автономных действий (сквозной принцип)

**ТЕРМИНАЛЬНОЕ действие** = `accept` / `merge` / `commit` / `delete` / `publish` — то, что трудно откатить или объявляет истину.

### Правила

1. **ПОМЕТИТЬ.** Любое терминальное действие без человека несёт машинный флаг `autonomous: true`.
2. **ПРОКОММЕНТИРОВАТЬ.** Рядом — строка-комментарий: что сделано, кем (агент), почему, чего НЕ хватает.
3. **ЧЕРНОВИК.** Артефакт остаётся `proposed`/`draft`, НЕ `accepted`, пока нет подтверждений.
4. **×N ПОДТВЕРЖДЕНИЙ.** Стать `accepted` можно только после **≥2 различных подтверждений ЧЕЛОВЕКА**.

### Что считается за одно подтверждение

| Тип | Засчитывается? | Примечание |
|---|---|---|
| Структурный маркер `confirmed_by: <имя>` | ✅ Да | Машинно-проверяемо |
| Структурный маркер `human_confirmations: ≥1` | ✅ Да | Машинно-проверяемо |
| Участник-человек в front-matter `participants:` | ✅ Да | Если Stefan/Max явно в списке |
| Прозa «Stefan ратифицировал» в теле | ⚠️ Частично | 1-е подтверждение = принять; 2-е = только со структурным маркером |
| 2 раза один человек | ⚠️ Засчитывается | Но требует ≥2 подтверждений; если тот же человек подтверждает 2 раза — этодва подтверждения |
| 2 разных человека | ✅ Да | Идеальный случай |
| 2 разных сессии того же человека | ✅ Да | Если можно отличить (время, контекст) |

**Правило сведения:** для 2-го подтверждения — минимум 1 структурный маркер (`confirmed_by:` или `human_confirmations: ≥1`).

5. **КОРРЕКТИРУЕМО.** Человек правит/отклоняет черновик любое число раз.

### Что сбрасывает счётчик

| Тип правки | Сбрасывает? | Пояснение |
|---|---|---|
| Правка тела в advisory-секции | ❌ Нет | Служебная правка, смысл не меняется |
| Добавление секции «Направление доработки» | ❌ Нет | Это указание, не решение |
| Правка сути решения (критерии, матрица, scope) | ✅ Да | Меняет meaning |
| Изменение `requires_confirmations` | ✅ Да | Критический параметр |
| Добавление/удаление пунктов | ✅ Да | Меняет scope |
| Правка front-matter кроме служебных полей | ✅ Да | Кроме `next:`, `last_verified:` |

**Машинный признак:** `human_confirmations` сбрасывается при изменении любого front-matter поля КРОМЕ: `next:`, `last_verified:`, `topic:`, `related:`.

6. **ДЕТЕКТОР, НЕ АВТО-БЛОК.** Проверка ФЛАГИРУЕТ и КОММЕНТИРУЕТ (read-only/advisory), но сама не блокирует.

## 1. C5 — commit_queue как стандартный протокол коммита

Развивает D-031. **Стандарт для всех агентов:**

```
enqueue <agent> --save → turn <agent> --ticket <id> → git add <свои> && git commit → done
```

### Что в каких случаях

| Сценарий | Режим | Примечание |
|---|---|---|
| Малая правка в общем дереве | Уровень-0: commit_queue | Видимость + предсохранение + справедливость |
| Триггеры D-022 (чужие source/STALE/hot-files/параллель) | Уровень-1: worktree | Приоритетнее |
| Экстренный hotfix (срочное) | Прямой коммит | Только если обосновано; пометить `autonomous: true` |

### Разграничение: C5 vs §0

- **C5 (§1)** — про **процесс коммита** (enqueue → turn → commit)
- **§0** — про **статусы истины** (accept/merge)

**Пересечение:** коммит терминален (§0 п.0), значит commit без тикета помечается `autonomous: true` (§1 мягкий режим).

### Жёсткий vs мягкий режим

| Режим | Требование | Подтверждений |
|---|---|---|
| **Мягкий** (default) | Коммит без тикета — advisory, помечается | 0 |
| **Жёсткий** | Pre-commit требует тикет; без тикета = ERROR | ≥2 (по §0 п.4) |

**Текущий статус:** мягкий режим. Жёсткий — отдельное решение.

## 2. B2 — гейт автономного `accept` для `decisions/D-*.md`

Детектор `autonomy_guard.py` (read-only, флагирует + комментирует).

### Матрица случаев

| # | Состояние `D-*.md` | Сигналов человека | Вердикт | Что делать |
|---|---|---|---|---|
| 1 | `proposed`/`draft` | — | **OK** | Черновик, терминального автономного accept нет |
| 2 | `accepted` + **≥2** сигнала | ≥2 | **OK** | Человек подтвердил (≥1 структурный) |
| 3 | `accepted` + **1** структурный | 1 | **OK** | Первое подтверждение принято; ждём второго |
| 4 | `accepted` + **1** только проза | 1 | **WARN** | Нужно добавить структурный маркер для 2-го |
| 5 | `accepted` + **0** сигналов | 0 | **FLAG** | Автономный accept — понизить до `proposed`, пометить `autonomous:true` |
| 6 | `accepted`, изменён агентом | сброс | **FLAG** | Правка сбросила счётчик — подтвердить заново |

### Зоны ответственности

| Компонент | Зона | Что покрывает |

## 3. Что считать «корректируемым»

### Границы корректировки

**НЕ сбрасывает счётчик** (minor correction):
- Добавление/редактирование advisory-секций (`## Status`, `## Заметки`, `## History`)
- Добавление секции «Направление доработки»
- Правка `next:`, `topic:`, `related:`, `last_verified:`
- Орфография, форматирование
- Добавление примеров и пояснений

**Сбрасывает счётчик** (major correction):
- Изменение сути решения (критерии, scope, матрица)
- Изменение `requires_confirmations`
- Добавление/удаление пунктов
- Изменение определения терминального действия
- Правка связей с другими решениями (добавление/удаление `related:`)

### Машинный критерий

```python
# Сбрасывает если изменилось:
RESET_FIELDS = ['title', 'status', 'requires_confirmations', 'correctable', 'author']
# + любой пункт решения в теле (body diff за пределами advisory-секций)
```

## 4. Порог `requires_confirmations` и процедура повторного захода

### Текущее предложение: `requires_confirmations: 2`

**Обоснование:**
- 1 подтверждение = можно начать работу (direction)
- 2 подтверждения = финальное принятие (acceptance)
- >2 = избыточно для текущего масштаба

### Процедура повторного захода

```
1. Человек даёт правки/корректировки
2. Проверяем: это minor или major?
   - Minor → human_confirmations остаётся;有新评论保留
   - Major → human_confirmations = 0; сброс
3. Агент вносит правки
4. Человек даёт новое подтверждение (2-е)
5. human_confirmations = 2 → статус → accepted
```

### Альтернативы (если Stefan хочет пересмотреть)

| Вариант | requires_confirmations | Когда использовать |
|---|---|---|
| A (current) | 2 | Текущий масштаб; работает |
| B | 1 | Если Stefan хочет быстрые решения; риск: мало проверок |
| C | 3 | Для критических решений (D-системного уровня); риск: медленно |
