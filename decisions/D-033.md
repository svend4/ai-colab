## 0. Дисциплина автономных действий (сквозной принцип)
ТЕРМИНАЛЬНОЕ действие = `accept` / `merge` / `commit` / `delete` / `publish` — то, что трудно откатить или
объявляет истину. Правило:
1. **ПОМЕТИТЬ.** Любое терминальное действие без человека несёт машинный флаг `autonomous: true`.
2. **ПРОКОММЕНТИРОВАТЬ.** Рядом — строка-комментарий: что сделано, кем (агент), почему, чего НЕ хватает (подтверждения).
3. **ЧЕРНОВИК.** Артефакт остаётся `proposed`/`draft`, НЕ `accepted`, пока нет подтверждений.
4. **×N ПОДТВЕРЖДЕНИЙ.** Стать `accepted` можно только после **≥2 различных подтверждений ЧЕЛОВЕКА**
   (структурный маркер `confirmed_by:`/`human_confirmations:` или участник-человек, не проза «как-нибудь»).
5. **КОРРЕКТИРУЕМО.** Человек правит/отклоняет черновик любое число раз; коррекция СБРАСЫВАЕТ счётчик.
6. **ДЕТЕКТОР, НЕ АВТО-БЛОК.** Проверка ФЛАГИРУЕТ и КОММЕНТИРУЕТ (read-only/advisory), но сама не блокирует
   жёстко — потому что жёсткий авто-блок был бы тем же автономным терминальным действием (его включение —
   тоже под п.4, решает человек). Так дисциплина не нарушает сама себя.

## 1. C5 — commit_queue как стандартный протокол коммита (ПРЕДЛОЖЕНИЕ, не авто-включение)
Развивает D-031. Предлагается СТАНДАРТ для всех агентов:
```
enqueue <agent> --save → turn <agent> --ticket <id> → git add <свои> && git commit → done
```
- **Что в каких случаях:** малая правка в общем дереве → Уровень-0 через commit_queue (видимость+предсохранение+
  справедливость). Триггеры D-022 (чужие source/STALE/hot-files/параллель) → Уровень-1 worktree (приоритетнее).
- **Под дисциплиной §0:** жёсткое включение (pre-commit, требующий тикет) **НЕ авто-применяется** этим черновиком —
  это терминальное процессное действие, требует ≥2 подтверждений Stefan. До тех пор — **мягко**: коммит без
  тикета помечается/комментируется (advisory), не блокируется.

## 2. B2 — гейт автономного `accept` на `decisions/D-*.md` (детально, по случаям)
Детектор `autonomy_guard.py` (read-only, флагирует+комментирует). Считает «сигналы подтверждения человеком»:
структурный `confirmed_by:` / `human_confirmations:≥1` / участник-человек (Stefan/Max) / прозаический
«Stefan ратифицировал». Матрица случаев:

| # | Состояние `D-*.md` | Сигналов человека | Вердикт | Что делать |
|---|---|---|---|---|
| 1 | `proposed`/`draft` | — | **OK** | это уже черновик, терминального автономного accept нет |
| 2 | `accepted` + **≥2** сигнала (структурный + участник/проза) | ≥2 | **OK** | человек подтвердил многократно |
| 3 | `accepted` + **1** сигнал (только проза «Stefan…») | 1 | **WARN** | дисциплина хочет ≥2 машинно-проверяемых → добавить `confirmed_by:`/`human_confirmations:` |
| 4 | `accepted` + **0** сигналов (только агент-авторы) | 0 | **FLAG (автономный accept)** | понизить до `proposed`, пометить `autonomous:true`, требовать ≥2 подтверждений |
| 5 | `accepted`, затем изменён агентом без нового подтверждения | сброс | **FLAG** | коррекция/правка сбрасывает счётчик — подтвердить заново |

- **Под дисциплиной §0:** детектор не правит D-файлы сам (это был бы автономный accept/downgrade) — он
  ПИШЕТ флаг-комментарий и оставляет правку человеку/гейту.
