# D-015 — гейт статуса по верификации, а не по подписи человека

## Контекст

Ранее перевод драйвера `draft → ready` требовал подтверждения человеком после прогона
приёмочных наборов (формулировка в манифестах + дух D-006/D-009). На практике это создало
несостыковку (ревью T-078, P0-2): драйверы стояли `ready` без выполнения предусловия, а
`workbench` остался `draft`, хотя его приёмка (T-055) уже `done`.

## Решение (по указанию Stefan, 2026-06-21)

Для **технического статуса** драйвера (`draft → ready`) обязательный human-confirm **не требуется**.
Статус можно менять, когда выполнены ОБА условия:

1. **Код функционирует** — профильные тесты/приёмка драйвера проходят (unit + по возможности
   MCP `call_tool`), результат воспроизводим;
2. **Перепроверка ≥2 агентами** — как минимум два агента независимо подтвердили работоспособность
   (сверка результатов), и это зафиксировано (done-маркеры/outbox/`source_last_verified`).

Принцип: **важен проверенный результат, а не подпись роли**. Если всё работает и перепроверено
несколькими агентами — статус отражает реальность, без ожидания ручного confirm.

## Границы

- Касается только **верифицируемого технического статуса** (`status` манифеста драйвера и
  аналогичные машинно-проверяемые состояния).
- **Архитектурные/организационные решения** (`DECISIONS.md`) по-прежнему по D-006: агент
  предлагает (`proposed`), принимает человек или явно назначенный сборщик.
- `mode: execute` остаётся под отдельным гардом (T-092/находка G): требует реальной изоляции,
  верификацией статуса не открывается.

## Применение

`source_last_verified` в манифесте обновляется на дату последней многоагентной сверки и служит
видимым следом верификации. `ready` без свежей сверки — повод вернуть в `draft`.
