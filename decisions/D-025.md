# D-025: Стратегии обхода WinError 5 (Async MCP stdio)

## Контекст (Проблема)
При запуске локальных серверов MCP (чаще всего Node.js) через асинхронный стандартный ввод-вывод (`stdio`) на некоторых конфигурациях Windows возникает ошибка:
`PermissionError [WinError 5] Отказано в доступе` при вызове `asyncio.create_subprocess_exec`.

Ошибка возникает на самом нижнем уровне: попытка Python создать анонимные пайпы (anonymous pipes) с Overlapped I/O и передать их дочернему процессу. Блокироваться может антивирусом (AV) или локальными политиками прав доступа на дескрипторы.

Чтобы система не оставалась заблокированной (T-174), утверждена матрица решений для агентов. Агентам **разрешается** выбирать стратегию в зависимости от сценария.

---

## Иерархия стратегий (От приоритетных к частным)

### 1. Первичная стратегия (Baseline): Вариант 2.5 — Оставить Wontfix + Sync
Это **рекомендуемый по умолчанию** вариант. Если асинхронный MCP через stdio падает, агент должен просто использовать синхронный клиент (Synchronous MCP SDK).
*   **Когда использовать:** Для большинства локальных вызовов инструментов (Gateway, CLI), где асинхронность не критична.
*   **Почему:** Синхронный `subprocess.Popen` использует другой механизм создания пайпов в CPython, который реже вызывает WinError 5.
*   **Как сделать:** Использовать обертку `mcp_sync_acceptance.py` вместо асинхронного клиента.

### 2. Продвинутая стратегия (Advanced): Вариант 2.3 — TCP/SSE Bridge (вместо stdio)
Если вам критически нужен асинхронный клиент (например, для параллельного стриминга большого объема логов от MCP сервера), и stdio заблокирован.
*   **Когда использовать:** Если синхронный вызов "тормозит" систему или нужен долгий фоновый сервер (например, LSP).
*   **Почему:** HTTP (TCP) локально не использует пайпы процессов. У антивирусов нет претензий к localhost loopback-трафику.
*   **Как сделать:** Обернуть оригинальный MCP-сервер через `npx @modelcontextprotocol/inspector` (который поднимает SSE-сервер) или создать микро-прослойку `express`. Затем подключаться к нему через `SSEClientTransport` вместо `StdioServerTransport`.

## Частные случаи (Fallback Strategies)

Если первые две стратегии не подходят (например, сторонний SDK жестко зашит на `asyncio stdio` и нет возможности поднять SSE-мост), применяйте следующие подварианты:

### 3. Вариант 2.1 — Смена политик Event Loop (ProactorEventLoop)
Иногда ошибка возникает из-за того, что в стороннем потоке поднялся `SelectorEventLoop` (несовместим со stdio pipe в Windows).
*   **Когда использовать:** Если ошибка плавающая (то есть, то нет) или возникает внутри сложного многопоточного приложения (например, внутри ThreadPoolExecutor).
*   **Как сделать:** Перед вызовом MCP явно прописать:
    ```python
    import sys
    if sys.platform == 'win32':
        import asyncio
        asyncio.set_event_loop_policy(asyncio.WindowsProactorEventLoopPolicy())
    ```

### 4. Вариант 2.2 — Прослойка CMD (Handle Inheritance Bypass)
Запуск через `cmd.exe /c`.
*   **Когда использовать:** Если ошибка WinError 5 возникает строго при запуске `node.exe` напрямую (антивирус может не любить, когда скрипты напрямую запускают node с пайпами).
*   **Как сделать:** Изменить команду с `["node", "server.js"]` на `["cmd.exe", "/c", "node", "server.js"]`. Прослойка `cmd.exe` забирает пайпы себе и правильно передает их `node.exe`. Учтите: это ломает корректную остановку (kill убивает cmd, но node остается сиротой).

### 5. Вариант 2.4 — Именованные пайпы (Named Pipes)
Замена Anonymous Pipes на Named Pipes.
*   **Когда использовать:** Как самое последнее средство (Last Resort), если вы пишите кастомный транспорт MCP-SDK на Python.
*   **Как сделать:** Использовать `\\.\pipe\mcp_...` вместо `subprocess.PIPE`. Это требует глубокой переработки SDK и не поддерживается "из коробки", но полностью обходит WinError 5.

## Инструкция для агентов

При столкновении с `WinError 5` в задачах `call_tool` MCP:
1. Выдайте предупреждение: `WinError 5 detected. Applying D-025 Baseline Strategy.`
2. Переключите транспорт на **Sync**.
3. Если задача требует SSE или долговременного стриминга — примените стратегию **TCP/SSE**.
4. В комментариях к коммиту укажите: `Fix MCP connection via D-025 Strategy X`.
