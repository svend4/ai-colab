# D-038 — Верификация драйверов по риску

## Статус
`accepted`. Ратифицировано: Stefan, котёл-день 2026-07-06 (HUMAN-DECISIONS-OPEN) —
ответ по Q3, вариант **(c) по риску**. Дополняет D-015 (гейт статуса драйверов по
многоагентной верификации), не отменяя его.

## Контекст
D-015 требует для `status: ready` драйвера **≥2 агентов** независимой перепроверки, но
**не требует их разнородности**. Батч C3a (`driver-verification-2026-07-06`) вскрыл слабое
место: оба прохода на каждом драйвере (`claude-w3a`, `claude-w3b`) — это **два инстанса одной
модели**, которые разделяют одни и те же слепые зоны и систематические ошибки. Совпадение
вердиктов повышает уверенность, но не эквивалентно мультимодельной проверке. Вопрос Q3: считать
ли «2 инстанса одной модели» достаточными — или требовать разные модели. Ответ — **по риску**.

## Решение (дополнение к D-015)
D-015 дополняется дифференциацией требований к верификации **по риску драйвера**:

1. **Обычные драйверы** (read-only / низкий и средний риск): **2 независимых прохода достаточно**
   — допускаются **2 инстанса одной модели**. Это подтверждает существующую практику D-015
   (≥2 агентов без требования разнородности) для типового случая.
2. **execute / high-risk драйверы**: требуются **РАЗНЫЕ модели / агенты** (не два инстанса одной
   модели). Для драйверов с `mode: execute` и высокорисковых операций совпадение вердиктов у
   инстансов одной модели **не засчитывается** — нужна межмодельная или межлюдская проверка,
   чтобы не унаследовать общие слепые зоны.

## Границы
- Не отменяет D-015: базовый порог «≥2 агентов + воспроизводимый результат» сохраняется.
- Не открывает `mode: execute`: он остаётся под отдельным гардом (D-014, D-015 §Границы) —
  D-038 лишь ужесточает **верификацию** high-risk/execute, а не разрешает их запуск.
- Классификация «обычный vs execute/high-risk» — по существующей семантике риска
  (`risk_gate.py` / манифест `mode`/`risk`), а не по новому реестру.

## Consequences
- Слабое место D-015 (общие слепые зоны инстансов одной модели) закрыто там, где цена ошибки
  высока (execute/high-risk), без лишней нагрузки на типовые read-only драйверы.
- Батч C3a (4 verified двумя инстансами Claude) остаётся валидным для обычных драйверов; для
  любых будущих execute/high-risk потребуется разнородная перепроверка.
- Открытый вопрос разнородности агентов из `driver-verification-2026-07-06` (§Оговорка) —
  закрыт этим решением.
