# D-034 — Отдельные пороги dir_health для архивных каталогов

## Статус
`accepted`. Ратифицировано: Stefan, 2026-07-06 (котёл-ответ по human-actions-plan, блок C1,
вариант (b) — решение принято Stefan напрямую).

## Контекст
Q-W2-4 / аудит: `queues/done` (226 файлов) — единственный оставшийся FAIL самопроверки
`dir_health.py` при общем пороге «файлов в папке >200 FAIL / >100 WARN». Но done-очередь —
**архив**: он растёт по определению, каждый закрытый элемент конвейера добавляет файл.
Общий порог, рассчитанный на рабочие каталоги (навигация человеком и агентом), даёт на архиве
ложный сигнал «структура сломана», хотя рост — норма его семантики.

## Решение
1. Ввести класс **архивных каталогов** с отдельными порогами: **FAIL 500 / WARN 400**.
2. Состав класса: `queues/done` (реестр `ARCHIVE_DIRS` в `tools/dir_health.py`).
3. Обычные каталоги — **без изменений**: FAIL 200 / WARN 100.
4. Оговорка (условие эскалации): **при достижении WARN (400) — шардирование
   (`done/<YYYY-MM>/`) или ротация janitor**, а не очередное поднятие порога.

## Обоснование
- Архив растёт по определению — порог для него измеряет не «сломанную структуру»,
  а лишь момент, когда пора включать шардирование/ротацию. 400/500 — честная семантика
  этого момента.
- Одна строка конфига (вариант C1-b) против правки всех читателей путей (C1-a, шардирование
  сейчас) — минимальное изменение при сохранении сигнала о бесконтрольном росте
  (в отличие от C1-c «исключить из порога вовсе»).

## Реализация
`tools/dir_health.py`: `ARCHIVE_DIRS = {"queues/done"}` + `ARCHIVE_FILES_FAIL = 500` /
`ARCHIVE_FILES_WARN = 400` (комментарий D-034); проверка `files-per-dir` берёт пороги по классу
каталога. Тест: `tools/tests/test_dir_health.py` — кейс архивных порогов.

## Consequences
- `queues/done` (226) уходит из FAIL в OK-зону; сигнал вернётся как WARN на 400 —
  и это будет триггером шардирования/ротации (п.4), не поднятия порога.
- Прочие каталоги продолжают проверяться прежними порогами — защита навигации не ослаблена.
