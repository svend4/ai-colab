# D-036 — Оркестраторный цикл принят как стандарт

## Статус
`accepted`. Ратифицировано: Stefan, котёл-день 2026-07-06 (HUMAN-DECISIONS-OPEN) —
батч-ратификация рекомендаций блоков A/A2/Д. Консолидирует ратифицированные ответы по
Q1, Q9, Q10, Q11, Q13, Q14, Q15, Q17. Пилот T-273 (первый полный цикл по этой модели)
прошёл чисто, чем закрыт путь «(c) пилот → (a) принять» из §9 предложения.

## Контекст
`orchestrator-cycle-proposal-2026-07-06` описал двухслойную модель работы (стратегические
главные агенты + исполнительные рои суб-агентов), 8-тактовый цикл и правила согласования по
риску. Модель кодифицировала цикл, фактически доказанный сессиями 2026-07-02..06
(аудит → котёл → волны 1–3 → конформанс 31/31 → обмен рецензиями Claude↔Codex). Предложение
по собственным правилам (medium/high по §4) уходило на согласование и решение человека, а не
внедрялось автором. Котёл-день 2026-07-06 закрыл связку человеко-гейт-вопросов, включивших эту
модель как стандарт.

## Решение (что принято) — таблица Q → что принято

| Q | Что ратифицировано |
|---|---|
| Q1  | Принят **package/agenda-слой** замкнутого контура (пакет-задание §3, повестка `kotel/agenda.md` §5, статусы цикла). Пилот T-273 прошёл чисто → принятие целиком (вариант (a) после пилота (c)). |
| Q9  | Механизмы **M1–M3** (`package_gate`/`agenda_gen`/`zone_overlap`) включаются **сначала advisory**, перевод в ERROR (жёсткий гейт pre-commit/CI) — **после обкатки**. Путь тот же, что у D-032 (`gap_scan` drift) и bulk_guard: advisory → ERROR после подтверждённой стабильности. |
| Q10 | **Silence-window для medium-пакетов принят: 12 ч** по умолчанию. Истечение окна = **СИГНАЛ**; перевод пакета в `agreed` — **осознанный шаг оркестратора, не авто**. Окно не переводит статус автоматически. |
| Q11 | **ОБЯЗАТЕЛЬНАЯ эстафета** для всех lead-агентов (claude/codex/mavis/novax): объявление пакета в повестке + проверка `zone_overlap` **ПЕРЕД** захватом темы/ID. Это **правило поведения** — агенты не вправе назначить его себе сами; прямой урок коллизии T-275/276 (C2 пакета). |
| Q13 | **Интегратор** цикла: **один назначенный lead-агент** на цикл закрывает петли (интеграция/демонстрация), а не каждый сам по себе. |
| Q14 | **Дефолт масштаба**: 2–4 read-only workflow, **≤1 shared-tree build**. Принято как дефолтное правило масштаба роя. |
| Q15 | **Источники груза** — выбор человека на каждый груз (fixture/локальная/внешний репо). **Запуск внешнего кода (execute) остаётся OFF по D-014.** |
| Q17 | Принят **объединённый runbook closed-loop** (`closed-loop-agent-cauldron-conveyor` + `orchestrator-cycle-proposal`, синтез Р1–Р4) — после пилота, вместе с Q1. |

## Исполнительная рука решения
Инструменты **M1–M3** — `tools/package_gate.py` (валидация пакета-задания), `tools/agenda_gen.py`
(сборка повестки `kotel/agenda.md` из PKG-файлов и вопросов), `tools/zone_overlap.py` (сверка
файловых зон пакетов) — это **исполнительная рука** данного решения. По Q9 они работают advisory
до обкатки; перевод любого из них в жёсткий гейт (ERROR/pre-commit) — отдельное будущее решение
человека, не авто-эскалация.

## Границы
- Пакет — **операционная обёртка**, источник истины остаются канон-объекты T/Q/D (§8 предложения).
- **execute внешнего кода не открывается** этим решением — остаётся под D-014 (Q15).
- Перевод M1–M3 из advisory в ERROR — **не входит** в это решение (Q9: «после обкатки», путь D-032).
- Эстафета (Q11) — правило поведения главных агентов; техническая проверка `zone_overlap` её лишь
  поддерживает, но обязательность объявления/сверки зон — норма, а не авто-гейт.

## Consequences
- Двухслойная модель + пакеты + повестка + эстафета — **стандартный режим** работы главных агентов.
- Узкие места такта 2 (согласование) и такта 8 (котёл) адресованы: silence-window 12 ч + auto-ok для
  low снимают ожидание, D-035 батчирует человеческий гейт.
- Коллизии ID/зон (T-275/276) предотвращаются обязательной эстафетой до захвата.
- Один интегратор на цикл (Q13) убирает размывание ответственности за закрытие петель.
