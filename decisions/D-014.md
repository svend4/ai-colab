# D-014 — Execute OFF по умолчанию + 10-гейтовый preflight

> Зарезервировано 2026-06-20; содержание заполнено 2026-06-23 (P3 из FINDER: D-021 цитировал
> D-014 как binding — «execute = OFF по умолчанию (D-014, 10 preflight-гейтов)» — но запись была
> пустым плейсхолдером). Формализует уже-действующую черновую политику `docs/execute-sandbox-preflight.md`
> в адресуемое решение. **status: accepted** — ратифицировано котлом (D-006/D-018); до accept'а
> остаётся обязательным де-факто (read-only контур уже его соблюдает, validate.py зелёный).

## Решение

Запуск чужого / непроверенного кода **выключен по умолчанию**. `mode: execute` в driver-манифесте
НЕ включается без (а) реальной песочницы, (б) отдельного **accepted**-решения на конкретный
execute-сценарий и (в) закрытых **всех 10** preflight-гейтов ниже. Пока хотя бы один гейт открыт —
режим остаётся `read-only`. Предпочтительный режим текущей стадии — **Вариант C (без execute)**:
`git-log` / `repo-runner` inventory / `files` read-search-summarize / `knowledge.py` / ручной review.

## 10 preflight-гейтов (все обязаны быть закрыты)

| # | Gate | Требование | Проверка |
|---|------|-----------|----------|
| 1 | Решение | accepted decision на конкретный execute-сценарий | запись в `DECISIONS.md` |
| 2 | Источник | репозиторий read-only + прошёл inventory | `repo-runner`/`git-log`/report |
| 3 | Песочница | реальная изоляция (Docker/VM/nsjail/firejail/gVisor/отд. сервер) | preflight-команды |
| 4 | Права | нет секретов и широких host-mount | ручной review команды запуска |
| 5 | Сеть | по умолчанию `--network none`; сеть — отдельное разрешение | manifest + команда |
| 6 | Лимиты | CPU, память, PIDs, диск, timeout | manifest + runner config |
| 7 | Логи | audit команды, exit code, runtime, diff/output | `logs/*` + `reports/*` |
| 8 | Rollback | output в отдельную папку, контейнер удаляется (`--rm`) | отдельный workspace |
| 9 | Валидация | `validate.py` не пропускает fake-sandbox | validate green |
| 10 | Человек | человек явно подтвердил first-run | отдельная запись/команда |

## Жёсткие запреты до отдельного accepted-решения

- Не запускать `run/test/install/pip/npm/make`, shell-скрипты или бинарники из непроверенного репо на хосте.
- Не включать `mode: execute` без реальной песочницы и accepted-решения.
- Не монтировать `C:\Users`, домашнюю папку, `.ssh`, браузерные профили, токены, Docker socket, `.gitconfig`.
- Не давать `--privileged`, host network/PID, доступ к Docker socket, системным дискам, prod-секретам.
- Не считать Docker/WSL сами по себе полной безопасностью (нужны лимиты, сеть, секреты, audit, rollback).

## Обоснование и связи

Полная архитектура (варианты A/WSL2+Docker, B/VM, C/без-execute), форма безопасной `docker run`,
ручные PowerShell-проверки и список обязательного логирования — в `docs/execute-sandbox-preflight.md`.
Схема драйверов — [[D-013]]. Эту запись как binding уже цитирует [[D-021]] (драйвер-безопасность,
execute-гейт OFF). Запуск чужого кода — отдельная подсистема (L3/L4) со своим review/лимитами/audit,
а не «следующая кнопка» в текущем драйвере.

## Ратификация

Черновая политика действует де-факто; эта запись делает её адресуемой как D-014. Перевод
`proposed → accepted` — через котёл (D-006 человеко-гейт / D-018 cauldron-протокол). См. задачу-трекер.
