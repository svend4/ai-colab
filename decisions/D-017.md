# D-017 — fork-and-synthesize

## Контекст

Норма «не плодить дубли» (Q-006/D-009 + практика «снять задачу, если её делает другой») недостаточна
для содержательных работ: если второй агент просто отказывается, **сравнивать и выбирать лучшее не
из чего** — нельзя объединить два варианта, развить проблемные места, прийти к доказательному
консенсусу/технически лучшему решению.

## Решение (Stefan, 2026-06-21)

Для **содержательных** анализов и дизайнов (ревью, онбординг, архитектура, спорные решения) дубли
**полезны как форки**:

1. Если тема/карточка существует, второй агент делает **параллельный вариант (форк)** — отдельный
   файл (`темы/<topic>/forks/<agent>-<short>.md` или `docs/<x>-<agent>.md`), нулевая коллизия.
2. Форки идут **параллельно**, не блокируя друг друга.
3. Затем — обязательный **синтез-шаг**: сравнить варианты → общие пункты (консенсус) в очередь на
   реализацию, спорные → на доказательное обсуждение до консенсуса (как `repo-review` +
   `opinion-synthesis-2026-06-21.md`).
4. **Снимать вопрос «потому что кто-то уже делает» — запрещено**; снять можно только после синтеза.

## Границы

- Чистый **dedup** остаётся для **механических** артефактов, где два варианта не нужны и вредны:
  атомарные id (`next_id.py`), генерируемые индексы (`TASKS.md`/`index.json`/каталог), манифесты,
  статусы — там источник один.
- Форки — для **мнений/дизайна/анализа**, где ценность именно в сравнении.

## Обоснование (доказательства из практики)

В сессии 2026-06-21 параллельные варианты дали лучше, чем один: онбординг (Claude `agent-onboarding`
↔ Codex `top-agent-operating-manual` — взаимодополнили); ревью (Claude план↔факт ↔ Codex
`architecture-docs-recheck` — независимо сошлись); песочница (контракт Codex + `tools/sandbox.py`
Claude — синтез). Во всех случаях сравнение двух вариантов превзошло любой одиночный.
