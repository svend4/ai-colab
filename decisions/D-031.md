# D-031 — commit_queue: стандартный путь коммита внутри Уровня 0

## Статус
`accepted`. Stefan ратифицировал в сессии 2026-06-26 («Да реализуйте это изменение»). Развивает D-021
(Уровень 0 = selective-add + commit_lock) и D-022 (триггеры Level-1); не противоречит им — это слой
КОММИТА поверх Уровня 0.

## Контекст (поймано вживую)
В этой сессии параллельные `git commit` двух агентов столкнулись на `.git/index.lock` → немой
`fatal: Unable to create '.git/index.lock': File exists`. Существующий Уровень 0 (selective-add +
`commit_lock` advisory) + `cohort ship` (авто-регенерация STALE) сериализуют и снимают half-done, НО
оставляют три дыры, прямо названные в выводе [[commit-policy-streams-2026-06-21]] и хвостом D-022/T-148:
1. **немой отказ** — не видно кто держит, насколько, какая моя позиция;
2. **потеря работы** — staged-правки упавшего/умершего коммитера не сохранены;
3. **несправедливость** — слепой retry (thundering-herd, голодание).

## Решение
**`tools/commit_queue.py` (enqueue→turn→commit→done) — стандартный путь коммита внутри Уровня 0**,
поверх `commit_lock` (переиспользует его как мьютекс головы очереди):
1. **`enqueue <agent> --save`** — FIFO-тикет + **темпоральное предсохранение** `git diff --cached`
   (`queues/commit-queue/<id>.patch`, `status=queued`). *Durability-первым*: работа не теряется даже при
   смерти агента / конце контекста / неосвобождённом локе (`recover` восстанавливает).
2. **`turn <agent> --ticket <id>`** — лок берёт **только голова** очереди (справедливость); иначе —
   богатая обратная связь: кто держит · взят N сек назад · осталось по TTL · позиция N из M · возраст
   реального `.git/index.lock`.
3. **`commit`** (правило selective-add остаётся в силе) → **`done`** (отпустить лок, ★) или **`fail`**
   (лок отпущен, тикет ✗ с патчем в `recover`).

**Композиция (не замена):** `commit_queue` — слой коммита; `cohort ship` остаётся для авто-регенерации
STALE-индекса (D-022 п.2); триггеры Level-1 worktree (D-022 п.1) выше по приоритету — при них агент уходит
в worktree, а не встаёт в общую очередь. `cohort ship` может вызывать `commit_queue` для самого шага коммита.

**Единый словарь флагов** ☐queued/⟳active/★done/✗failed зеркалит семантические статусы `text_mux` —
технический коммит и семантическое слияние суть один конвейер синтеза ([[commit-queue-and-synthesis-2026-06-26]]).

## Перепроверка (D-018, технич. + гуман.)
- **Техническая:** `tools/commit_queue.py` + `test_commit_queue.py` (6 проверок: FIFO-позиции ·
  голова-берёт-лок · фидбек-с-позицией · предсохранение+recover · fail · видимость `.git/index.lock` ·
  ticket path-safety) зелёные; `commit_lock`/потребители не сломаны. Параллельный агент усилил
  валидацией ticket-id (path-safety).
- **Гуманитарная:** устраняет немой отказ (главную фрустрацию) и потерю работы (главный анти-риск
  многоагентности); даёт справедливый, читаемый порядок вместо догадок; не повышает поверхность риска
  (read-only доска; коммитит по-прежнему сам агент своими файлами).

## Boundaries (что НЕ решено)
- Остаётся **Уровень 0** (общий рабочий дир). Связку через общий генерируемый индекс снимает не это, а
  `cohort ship` / Level-1 worktree (D-022). При триггерах D-022 — worktree приоритетнее очереди.
- Очередь *кооперативная*: защищает от коллизий между агентами, что её соблюдают; некооперативный
  raw-`git` всё ещё может схватить `.git/index.lock` — но теперь это ВИДНО (board показывает возраст).
- Не отменяет проблему оракула на семантическом плече (см. D-030) — `commit_queue` решает техническое плечо.

## Consequences
- Путь коммита агента: голый `git commit` → `enqueue --save → turn → commit → done`.
- «Хвост потери работы» из D-022/T-148 закрыт предсохранением+recover на Уровне 0 (без обязательного worktree).
- Заложен общий конвейер синтеза (технич.+семантич.) — фундамент для `contribution.v1`.
