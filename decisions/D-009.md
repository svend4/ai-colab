# D-009 — Онбординг агентов: само-регистрация сейчас, переход к гибриду позже

- Контекст: Mavis и Novax самозарегистрировались, редактируя `AGENTS.md` / `participants.md` / `tools/permissions.json` вне своей worker-зоны (`permissions.py` это помечает). Нужна политика онбординга (Q-006).
- Решение: на текущем этапе — **вариант A** (само-регистрация нового агента с обоснованием в `dialog.md`): для 4 кооперативных агентов трение минимально, риск низкий. **Запланированная эволюция — к варианту C** (агент готовит регистрацию как предложение → maintainer/человек утверждает) по мере роста числа агентов или снижения доверия; пересматривать при перепроверке.
- Последствия: само-регистрация остаётся допустимой сейчас; `permissions.py` продолжает помечать governance-правки нового агента как сигнал (не блок). При переходе к C вводится «proposed»-путь онбординга (ветка/outbox + утверждение maintainer'ом).
