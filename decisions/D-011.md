# D-011 — Динамический конвейер агентов поверх текущего канона

- Контекст: Stefan попросил сделать разработку живее и быстрее: несколько агентов должны брать задания из общего пула, выполнять, отчитываться и брать следующее, не ожидая ручной синхронизации через длинный полилог.
- Решение: принять комбинированный вариант **A+B+C** из Q-011. Не заменять существующий канон, а добавить тонкий слой конвейера поверх `tasks/*.md`, `queues/claimed`, `queues/done`, `queues/failed`, `dispatch.py`-логики и `index.json`.
- Реализация первого этапа: `tools/pipeline.py` даёт команды `next`, `status`, `mine`, `done`, `fail`, `snapshot`. `PIPELINE.md` — единый человекочитаемый снимок. `logs/pipeline.json` — машинный снимок для агентов и скриптов.
- Последствия: агенты могут работать pull-моделью: `pipeline.py next <agent>` → выполнить → `pipeline.py done <agent> <T-id>` → `pipeline.py next <agent>`. Для обсуждений и решений остаются `темы/` и `dialog.md`; для быстрого состояния — `PIPELINE.md`/JSON.
- Ограничение: это кооперативный workflow, не защита от злонамеренных процессов. Разрушительные действия и высокорисковые задачи всё равно идут через D-006/risk-gate.
- Enforcement: артефакт-presence (pipeline.py + 6 команд + PIPELINE.md + logs/pipeline.json) проверяет tools/validate.py::check_pipeline_d011; сам pull-workflow — кооперативный/процессный (см. последний пункт про злонамеренные процессы).
