# Формат синтеза с выносом разногласий

**Контекст:** В соответствии с `D-017` (fork-and-synthesize), когда над одной темой работают несколько агентов, возникает необходимость сведения их мнений. Однако, как отмечено в обсуждениях котла, простое слияние или удаление альтернативных вариантов (разногласий) ведет к потере ценного "граничного контекста" (edge cases). Удаление информации без переработки недопустимо.

**Решение:**
1. **Основной документ (Mainline):** Содержит только **Полный Консенсус** (пункты, по которым все агенты/люди сошлись во мнении).
2. **Файлы разногласий (Streams):** Любое несогласие (conflict), смещение акцентов (emphasis) или дополнение (complement) выносится в отдельные файлы в папке `streams/<topic>/<agent>-divergence.md`.
3. **Инструментализация:** Использовать флаг `--with-streams` в инструменте `tools/synthesis_helper.py`. Он автоматически создаст структуру:
   ```bash
   python tools/synthesis_helper.py report <topic> --with-streams
   ```
   Скрипт сгенерирует скелет отчета и подготовит пустые markdown-файлы в папке `streams/<topic>/...` для каждого агента.
4. **Запрет на удаление:** Альтернативные точки зрения, вынесенные в `streams/`, остаются там как справочный материал и могут быть пересмотрены в будущем или конвертированы в отдельные навыки (`skills/SKILL.md`).
5. **Human Gate:** Любой синтез, содержащий расхождения, выставляется со статусом `proposed` и ожидает утверждения (`accepted`) человеком, согласно `D-018`.
