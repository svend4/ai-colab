## Context

T-137 asked to resolve the open points left after the Claude/Codex opinion synthesis:

- D3: how much additional middle-layer automation should be built now;
- T-020/svend4: how to turn the old external-repository blocker into a generic sandbox process;
- fork format: how to support parallel variants without committing half-done work;
- text-extract priority: what can be done without heavy dependencies, and what still needs a decision.

The synthesis uses D-016, D-017, D-018 and D-021/D-022 as constraints: universal core + portals, fork-and-synthesize, collective decision through the kettle, and commit streams.

## Proposed Decision

1. **Use thin automation first.** The current direction should be lightweight wrappers over proven primitives, not a large autonomous router. `tools/top.py`, `tools/cohort.py`, `tools/variants.py`, `tools/synthesis_helper.py`, `tools/merge_gate.py`, `tools/stream.py`, `tools/promote.py`, and `tools/sandbox_intake_demo.py` are acceptable because they reduce repeated manual work, are inspectable, and have focused tests. Heavy router/RAG/topic-summarizer/long-running agent orchestration should wait for measured demand.
2. **Keep fork-and-synthesize operational.** Duplicates of meaningful opinions/designs are allowed as variants. `streams/` is the semi-commit packet format; `tools/variants.py` is the read-only discovery index; `tools/synthesis_helper.py` prepares a proposed synthesis scaffold; `tools/stream.py adopt` records adoption after review. Mechanical artifacts still use dedup and canonical generators.
3. **Do not accept worktree-streams by default yet.** Level 0 is current practice: commit-lock plus explicit selective `git add`. Level 1 worktree-per-agent/task remains proposed until Stefan approves launch and merge ownership.
4. **Reframe T-020 as generic external-source intake.** `svend4` must not be a special exception. When a read-only path/archive/snapshot is provided, it should enter `sandbox/` through manifest + read-only inventory + report. Until then T-020 is blocked, not doing. `tools/sandbox_intake_demo.py` proves the process on safe fixtures without executing code.
5. **Treat promotion as a gate, not a mass migration.** `docs/promotion-rules.md` and `tools/promote.py` formalize L4->L3->L2->L1 checks. Existing L3 history is not physically moved in bulk. Each promotion needs review metadata and a decision reference.
6. **Text extraction stays incremental.** The already implemented `.md/.txt/.html` path is enough for current safe knowledge work. DOCX can be the next low-risk no-dependency step through stdlib `zipfile`; PDF should remain a separate dependency decision (`pypdf` or equivalent) only after a real corpus proves the need.

## Human / Collaboration Rationale

This path is useful for people because it turns many scattered commands into readable buttons and reports. It is useful for agents because it provides stable machine-readable entrypoints and avoids writing over each other.

The main human risk is process overload: too many wrappers can become another maze. The proposed control is simple: a new tool is justified only if it removes repeated friction, has a clear read/write effect, and has a small test.

## Risks and Limits

- More tools mean more documentation and freshness checks.
- `cohort.py ship --run` should be treated as an experimental convenience; normal commits should still use explicit commit-lock and selective `git add` until Level 1 is accepted.
- `promote.py move` is powerful and should be used only after review; `check` is the safe default.
- `sandbox_intake_demo.py` proves read-only intake, not execute safety.
- The real `svend4` blocker remains until a source path/archive/snapshot is provided.
