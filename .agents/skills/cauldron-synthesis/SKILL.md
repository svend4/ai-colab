# Cauldron Synthesis Skill (Навык работы с Котлом и разногласиями)

Этот скилл содержит инструкции о том, как правильно сводить мнения нескольких агентов, разрешать конфликты и фиксировать разногласия, не стирая их (в соответствии с решениями D-017 и D-018).

## 1. Никогда не стирать разногласия
Если агенты или люди расходятся во мнениях, это указывает на граничный случай (edge case) системы. 
Не удаляйте альтернативные варианты! Выносите их в отдельную под-структуру (например, папку `streams/<topic>/` или раздел "Разногласия").

## 2. Порядок синтеза
1. Вызовите `python tools/synthesis_helper.py report <topic> [--out PATH]` для генерации базового скелета.
2. В файле синтеза (`mainline` документ) фиксируйте только **Полный Консенсус** (то, с чем согласны все стороны).
3. Создайте файлы разногласий (например, `streams/<topic>/divergence.md`), в которых четко распишите:
   - Суть пункта спора.
   - Позицию Агента А.
   - Позицию Агента Б.
   - Доказательную базу (с указанием cross-refs `file:line`).
   - Варианты решения (что выбрать).
4. Установите статус документа в `proposed`. Ни один агент не может самостоятельно перевести документ в `accepted` без участия человека, если есть разногласия.

## 3. Вызов скриптов (Инструментализация)
Для обнаружения расхождений всегда опирайтесь на `tools/synthesis_helper.py`. Если он недостаточен для семантического анализа, вы можете расширить его локально в процессе работы.

## 4. Сбор и переработка мертвого груза (Recycling)
Если при синтезе вы находите устаревшую информацию или полезный, но забытый совет:
- Не удаляйте его.
- Превратите совет в новый `SKILL.md` (как этот).
- Либо перенесите сырой текст в `archive/`, написав краткое summary.
