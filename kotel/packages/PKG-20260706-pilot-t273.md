# PKG-20260706-pilot-t273 — Pilot T-273

## 1. Purpose

1.1. Проверить объединённую модель `closed-loop` + `orchestrator-cycle` на реальной задаче `T-273`.

1.2. Не запускать внешний код и не делать accepted-решения.

1.3. Подготовить первый безопасный L2-сценарий AI-OS Bridge через read-only путь.

## 2. Boundary

2.1. Этот package не claims `T-273` и не меняет owner задачи.

2.2. `T-273` сейчас остаётся канонической задачей; package является операционной оболочкой пилота.

2.3. Выполнение package должно идти через отдельный claim/worktree только после явного старта lead-agent.

2.4. Перед стартом `lead` должен быть заменён с `pending` на конкретное значение: `claude`, `codex` или `claude+codex`.

2.5. Параллельный отчёт `reports/t273-pilot-divergence-reconcile-2026-07-06.md` предлагает синтезировать два варианта как последовательность:

```text
W_safety / route boundary
  -> GATE
  -> W_build / L2 inventory payload
  -> W_run
  -> W_verify x2
  -> W_report + scribe
```

2.6. Этот package принимает последовательность как candidate route, но не меняет status на `in-swarm` до фиксации lead, source path и конкретных команд запуска.

2.7. Safety/route preflight зафиксирован в `reports/T-273-l2-pilot-safety-gate-2026-07-06.md`: GO только для read-only fixture/local-folder inventory, NO-GO для external execution.

## 3. Recommended First Scenario

3.1. Не начинать с внешнего svend4/infon execution.

3.2. Начать с read-only L2 payload:

1. выбрать маленький локальный каталог или fixture;
2. собрать inventory через `files` или `file-inventory`;
3. записать report в `reports/`;
4. показать ограничения, риски, качество результата;
5. сформулировать следующий payload или задачу.

3.3. Driver priority:

| Priority | Driver/tool | Use | Constraint |
|---|---|---|---|
| 1 | `files` | list/read/search/summarize | read-only only |
| 2 | `file-inventory` | scan/render file map | low-risk inventory |
| 3 | `git-log` | read-only repo history if source is a repo | no hooks/build |
| 4 | `sqlite` | selected local DB only | read-only SELECT/WITH only |
| 5 | `data` | CSV/TSV only | avoid JSON/SQLite claims until drift fixed |
| later | `repo-runner` | local repo inventory only | no clone, no install, no tests |
| avoid first | `gateway`, `workbench`, `codex-local` | broader composition/manual bridge | not first pilot path |

3.4. Forbidden in the first pilot:

1. `git clone`, network fetch or external repo execution;
2. `pip install`, `npm install`, build scripts, test scripts from external code;
3. write to real user data;
4. accepted decisions without human gate;
5. broad filesystem scan without selected source.

## 4. DAG

| Node | Type | Description | Output |

## 5. Worker Briefs

### 5.1. Worker A — Route map

Read-only. Проверить, какие существующие drivers/tools подходят для первого L2 payload. Вернуть список команд, ограничений и рекомендуемый route. Первый выбор: `files` / `file-inventory`.

### 5.2. Worker B — Safety verifier

Read-only. Проверить, где есть риск внешнего execution, секретов, больших логов, грязного дерева, hot files. Вернуть safety checklist.

### 5.3. Worker C — Report composer

Read-only. Свести W1/W2 в `reports/T-273-l2-pilot-plan-2026-07-06.md` или аналогичный report.

## 6. Agreement Rule

6.1. Risk is `medium`.

6.2. До реального запуска pilot-package нужен один из вариантов:

1. явное ok Stefan;
2. ok одного другого агента ростера и отсутствие veto до `review_deadline`;
3. решение котёл-дня по D-035.

6.3. Если используется реальный пользовательский каталог, Stefan должен явно выбрать или подтвердить источник.

6.4. Если используется внешний источник, сначала нужен sandbox intake. Execute запрещён до отдельного accepted decision и human first-run gate.

## 7. Done Criteria

7.1. Есть report с выбранным route.

7.2. Есть safety checklist.

7.3. Нет execution внешнего кода.

7.4. Нет accepted decisions без человека.

7.5. Все next actions превращены в `T-*`, `Q-*`, package follow-up или archived note.

7.6. После пилота есть решение: принять package/agenda layer, упростить, или отложить.
